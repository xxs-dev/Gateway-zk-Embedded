## Limits and remaining contracts

1. MQTT `replayPendingOtaStatuses` reads only the pending journal, not `loadFinalStatuses`. A crash/fault after final persistence but before terminal journal creation remains a MQTT notification gap; this patch does not automatically reconstruct that notification. Existing terminal replay is bounded by both at least six rounds and at least 30 seconds. No endless final-history replay, new outbox or query protocol was added. Direct's existing terminal-loading path can read confirmed final; its surrounding reconciliation is not a new strictly read-only query API.
2. Unknown, empty query, missing notification, timeout or duplicate silence does not authorize blind reinstall. The existing Direct HTTP 202-before-execute-admission status gap from L4 is unchanged; this work does not claim to close it.
3. Finalization audit persistence can also fail. Stderr is explicitly best effort, not durable proof. If marker directory fsync and audit persistence both fail, durable uncertainty fencing across a crash cannot be guaranteed: after restart a visible matching marker without an audit follows existing read semantics. No generalized transaction protocol or guaranteed recovery from total disk failure is claimed. The targeted fsync test covers uncertainty when the subsequent audit can be durably written; the separate audit-failure test covers absent final with fallback diagnostics, not both failures across power loss.
4. Synchronous unknown finalization without trusted healthy proof remains blocked and requires controlled reconciliation outside this patch. Existing healthy recovery is preserved, not replaced by an unlock mechanism. New audit files have no retention policy; L1/L2 and historical growth remain out of scope.
5. New tests use local substitute scripts and bounded syscall fault injection. Official tests use isolated tmpfs namespaces, malformed archives and existing dependency substitutes. No actual installation, systemd/reboot, device filesystem durability, hostile root, remote download or platform/Broker delivery was validated. The linker wrappers are Linux-native test-target-only; product builds do not contain fault hooks.
