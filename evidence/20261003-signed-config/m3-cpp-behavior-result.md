# M3 C++ local behavior checkpoint

Scope: private x86_64 WSL `/tmp/ota-m3-local-*` fixture, no Broker connection, owner launch, systemd, device, `/opt` operation, or deployment. The test directly compiles product `ota_service.cpp` in its translation unit and separately compiles both real MQTT publisher product translation units. It calls the product health decoder, durable journal replacement and new `OtaService` readers, and the same two encoder entry points used by production publication.

Final build: WSL Ubuntu g++ 15.2.0, C++17, `-O0 -g -ffunction-sections -fdata-sections -Iinclude -pthread`, three named source inputs, `-Wl,--gc-sections -ldl`; exact argument array and exit 0 are in `m3-cpp-behavior-final-local/build.json`. Final run: WSL root for root-owned private handoff fixture, exit 0 in `run.json`. Raw build/run streams remain local; exact SHA-256 values are in the two JSON records. Compiler `-MM` identified 19 repository inputs; their full bytes are in local `input-snapshot/`, with before/after/snapshot SHA equality in `inputs-{before,after}.json`.

The test covers original job/occurrence, candidate/artifact SHA and healthy result through pending/final restart readers and both JSON encoders; syntactically valid numeric pending field rejection; missing/invalid production health evidence; wrong job/token; and old nonproduction pending/final/encoder compatibility. First valid-shaped cross-proof transaction mismatch was red (run exit 1, stderr SHA-256 `846f86872d4207026c5d68d948bc29d981709d92625a8c77d61c0ad1941c2289`); the product now requires health transaction to equal the root-owned handoff proof and record. The compiler's initial include-`.cpp` approach also failed with a GCC 15 internal compiler error; that draft is preserved separately and is not product evidence.

The fixture uses a precomputed job/token transaction ID matching the owner formula, but C++ does not independently derive that ID. This checkpoint proves consistency with the trusted handoff proof, not execution of the owner, signature verification, real MQTT delivery, ARM behavior, or a complete original-job recovery protocol. Those gates remain open.
