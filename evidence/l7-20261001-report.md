## Change

- MQTT OTA replay is a nonthrowing boundary for reconciliation, journal read, OTA publication and journal clear. It reuses the scan timestamp/last-attempt field, adds one capped retry-delay field, and isolates diagnostic publication. Failure delays are 10s, 20s, then at most 30s; a successful attempt restores the existing 5s interval. Failure resets successful replay accounting, not task state.
- Existing retention still requires at least six complete successful publication rounds AND 30s before journal clearing. A reconcile failure aborts that OTA replay attempt; normal full/realtime scanning continues. This does not add a final-history outbox or reconstruct missing MQTT notifications.
- Direct GET keeps existing items and independently attempts existing final reads after reconcile failure. Top-level `reconciliationFailed` covers recovery/config/final-read exceptions, without task failed/completed fabrication or exception text. This is Direct API diagnostics only: the current Windows DTO ignores this field; no Windows warning/display is claimed.
