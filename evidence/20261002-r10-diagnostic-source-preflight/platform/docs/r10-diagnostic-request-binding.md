# R10 diagnostic request binding

New deployments require H2 migration V16 or PostgreSQL migration V17 before starting the platform. `edge_diagnostic_request` owns the immutable cmdId, device, command, argument, normalized operator and request timestamp. Reservation commits in `REQUIRES_NEW` before MQTT publish; ingress checks it before the first-write terminal inbox. A failed or uncertain publish does not delete the reservation or imply remote cleanup. Rejections are not terminal records. The request and terminal tables are durable history owned by the diagnostic task lifecycle; include both in R07 inventory/retention planning and do not purge them as a deployment shortcut.

Upgrade precondition: stop admitting new remote diagnostic tasks and let all existing QUEUED/DISPATCHING/DISPATCHED tasks reach a reviewed terminal state before enabling the new ingress. Requests published by the old version have no binding and their later replies will be rejected, not guessed or backfilled. A platform timeout means no reply before its deadline, not proof that a remote process stopped; unresolved delivery/execution requires operator review before the quiet window is declared complete. Do not relax binding or use last-write-wins to bridge this migration.

The diagnostic reply topic alone accepts up to `6 * 1 MiB + 4096` bytes, matching the edge's conservative JSON envelope budget for a 1 MiB diagnostic output. Other topics and outbound publishes keep the configured maximum (capped at 4 MiB). Output is redacted before truncation and durable insertion. Local H2/MockMvc, Paho callback and Vue typecheck evidence is not PostgreSQL migration, live Broker, ARM or device acceptance.
