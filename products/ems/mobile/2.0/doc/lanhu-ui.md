# EMS 2.0 蓝湖还原记录

## 范围

版本 `2.0.11-lanhu` 使用蓝湖原稿坐标，画布为 1440×810。界面由可交互的 Qt 控件、实时点位绑定和少量原稿局部位图组成，不用整张设计图覆盖页面。

已还原的完整设计：仪表、并机拓扑、自检、部署、自定义曲线、电芯曲线、告警、PCS、BMS、TMS、MCCB、柴油机、策略控制。输出保留 39 个路由 ID，兼容旧导航入口。监测、设置、单机拓扑等未取得完整设计的正文留空，不继续套用旧版页面。

`LayoutProfile=XMindV2` 仍生成原有 1920×1080、34 页布局。没有修改 EMS 策略算法、SHM ABI、协议或设备驱动。

Lanhu 包必须配合本次新增控件支持的 Qt renderer 使用，不能假定旧 renderer 能正确显示。旧 XMind 布局的生成、包校验及部分原生布局回归已通过，不等于所有旧画面已完成真机回归。

## 控制边界

- 已确认点位：PCS 复位、启动、停止及 1318–1323 六个分相功率设定；458 防逆流使能。
- 模式枚举、BMS 上下电具名命令、TMS 启停和四个温度阈值、MCCB、柴油机、其他策略使能均保留禁用位置，等待明确点表及命令值。
- 24、8、20、18 等策略运行状态不是使能点，不能写入。
- PCS 运行状态读 1209/1210/1211；并离网状态读 1216/1217，不把 1214 远程/就地当作运行状态，也不把未并网解释为离网。
- 未配置的从车不复用本机遥测。拓扑连接线是设计示意，不构成实物接线或运行许可判据。
- 引导中的设备检查目前只使用已配置通信反馈，不能代替完整安全检查。供电状态、自检汇总和未映射检查结果保持未知；完成部署不可执行。
- 控制仍经过原有登录、确认、范围校验和边端写后回执。切换状态只反映真实反馈，点击不乐观改成成功。

## 曲线与告警

仪表图保留近两小时窗口，其余曲线沿用最近一小时。功率与电压使用独立坐标轴；图例按原稿顺序显示，并支持原有点击隐藏、缩放和平移。

电芯曲线按原稿的上下等高区域显示，最高值使用蓝色。点表中的电芯电压单位为 mV，保留真实单位，不直接复制原稿的 V 示例标签。柴油机页保留原稿的“遥控快速停机、遥控市电合分闸、遥控发电合分闸、遥控手/自动”名称，所有动作仍为禁用预留。

告警表使用原稿七列和每页八条的实际分页。当前告警数由已配置告警条件计算，任何缺失、坏质量、过期或非有限数据均不能显示为零告警。今日数、累计数、发生时间、恢复时间尚无历史接口，不用采样时间或启动时间代替。表中“数据不可用”行是诊断占位，不等同于已发生告警。

## 视觉证据

运行 `tools/build-lanhu-review.py --references <蓝湖导出目录> --screens <截图目录> --output <对照目录>`，产生原稿/渲染并排图、50% 叠图、HTML 和文件 SHA256 清单。个别原稿是 1440×811，工具记录原始尺寸并统一为 1440×810。

95% 是待验收目标，不是当前已证明的结论。真实遥测、时钟、登录态、禁用占位和未知状态与原稿示例必然不同；不能以大面积白色背景的相同像素数量替代逐页视觉验收。

Windows renderer 的 `--preview-values <pointBatch.json>` 仅在 `--screenshot` 模式允许使用本地测试数据。该路径不会连接设备或替换现场配置；测试数据截图应明确标记为 fixture。

视觉截图使用 Windows 原生 Qt 平台插件；offscreen 插件在本机缺少中文字体回退，不能用于视觉验收。原稿的示例数值、告警历史、检查结果和控制使能颜色不是验收数据，未接入部分不会伪造成功状态。
