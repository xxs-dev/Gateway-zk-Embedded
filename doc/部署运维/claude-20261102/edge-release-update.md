## 3. 控制确认与仲裁

核心规则只有三条：只有“反馈确认”才算动作确认；结果未知既不是成功也不是失败；任何情况都不自动重发。回执协议、共享内存布局和 MQTT 字段都没有改，平台收到的内容不变。

### 3.1 回执分类（本地画面）

| 回执 | 画面显示 | 算不算确认 | 该点的锁 |
| --- | --- | --- | --- |
| 还没有回执 | 命令已受理，等待驱动回执 | 否 | 保持 |
| `writeback-submitted` | 已下发，未确认（只交给了输出或通信） | 否 | 解除 |
| `writeback-succeeded`，未回读确认 | 协议写入成功，动作未确认 | 否 | 解除 |
| `verifyPassed=true` | 反馈确认成功（显示反馈来源和回执原文） | **是** | 解除 |
| 本地参数或信箱已提交 | 本地参数已提交（未下发设备） | — | 解除 |
| 结果未知（超时或反馈不一致） | 结果未知：设备可能已执行；未自动重发 | 否，也不是失败 | **保持到跟踪期结束** |
| 确定失败 | 执行失败 + 阶段 + 原因 | — | 解除 |
| 10 秒仍无回执 | 等待回执超时，结果未知；继续跟踪到 70 秒，期间晚到的最终回执标为“晚到回执” | 否 | 保持 |

只认本条命令（cmdId + 点号）的回执；最终结果出现后不再被更旧或矛盾的记录替换。

### 3.2 本地锁

- 命令被边端受理时登记到进程级的控制事务表，与页面和控件无关。退出登录、登录过期、工程重载都不会解锁，重新登录后锁仍有效。
- 只有本命令、本点的确定最终回执才解锁；否则到跟踪期截止（按钮和参数输入 70 秒，PCS 三相 70 秒）一律解锁，不留永久锁。
- 事务按 cmdId 区分，旧命令的晚到回执不会解除新命令的锁。
- 事务表只在内存里：KY-SCADA 进程重启后不保留。

### 3.3 图形 EMS 的 confirmedControlWrite

| 目标 | 必要配置 | 确认依据 |
| --- | --- | --- |
| Modbus / DL645 / IEC 等 | `write.verifyAfterWrite` 且 `verifyByRead`（原规则） | 目标点自身回读 |
| 本机 DO | `write.verifyIndex` 指向辅助触点 DI（不能是输出本身），`verifyValue` 只能 0/1 | 触点反馈 |
| CAN | `write.verifyIndex` 指向设备状态信号（不能是命令信号或脉冲信号） | 状态信号 |

- 不满足时节点在下发前拒绝、不发送，状态 -2。
- 状态输出：确认 3；确定失败 -1；结果未知、不一致、写入但未确认 **-2**（原来记 -1）。读这个输出的逻辑要知道 -2 也表示需要人工复位。仓库发货配置里没有用到这个节点。

### 3.4 AGC/AVC 的结果未知

- 结果未知的设定值登记为未知事务，**永不再发**，与写入死区（包括 0）和 PCS 遥测超时无关。
- 未知事务在三种情况下结束：同一 cmdId 的晚到确定回执；PCS 遥测在容差内到达本事务目标（好质量、未过期、采样晚于下发）；控制器给出不同的设定值并被受理。
- 晚到的成功与按时成功同样记账；晚到的确定失败不重复计数。
- 唯一例外（原有规则）：已使能但不可用的 PCS 按尽力下发安全态 0。
- 未知事务只在内存里，AGC/AVC 服务重启后不保留。
- 本轮**没有**开放“遥测不到位即自动重试”。

### 3.5 没有改变的部分

- 控制仍由边端仲裁：命令信箱按入口和服务端策略授权（本轮之前已实现），本轮没有增加任何绕过仲裁的下发方式。
- MQTT 回执、直连维护、第三方转发和 pointctl 原样转发 stage/outcome/verifyPassed，未改。
- 本轮没有改 AGC/AVC 是否接受平台调度的配置；不开启 AGC/AVC 默认平台调度的要求不变。

- 新增源文件 `local_display_qt_control_receipt.cpp`，已加入 CMake 和 Qt 构建脚本；控制事务表是头文件，不增加源文件。
- 22.11 的 Qt 测试由 3 个变为 5 个（新增回执跟踪和 PCS 回执测试）。

- **22.11 的全量正式构建和现场部署另行安排**。内网已做过的是定向构建（见第 6 节），不是全部 19 个生产目标的发布构建。

### 4.2 升级后的行为变化

| 方面 | 变化 | 现场要做什么 |
| --- | --- | --- |
| AGC/AVC | 结果未知时不再自动重发同一设定值，零死区和遥测超时也不例外 | 如果现场以前靠重发补偿丢包，升级后连续失败计数会上升、按 `maxConsecutiveWriteFailures` 进入失效，需要人工核实 |
| 本地画面控制 | 结果未知的点在 70 秒内不能再次下发，退出登录、重新登录、工程重载都不能绕过 | 紧急操作用设备侧或独立急停回路，不依赖本画面 |
| confirmedControlWrite | 未确认但可能已执行时状态由 -1 改为 -2；CAN/DO 可用辅助反馈确认 | 自建的图形 EMS 逻辑若读这个输出，要把 -2 也当作需要人工复位；用 CAN/DO 时配 `write.verifyIndex` |
| 画面状态文字 | 单一来源的未定义枚举显示“未知(原值)”；组合状态无效仍显示 `--`；陈旧、坏质量仍是 `--` | 无需操作，告知值班人员 |
| 画面标签 | PCS 模式标签改为“模式设定”；PCS 监测页“控制模式”改为“PCS远程/就地”；电芯页共用探头只显示一次 | 同上 |
| 灰色按钮 | 可以点击，只弹出不可用的原因，不下发 | 同上 |
| SOE 列表 | 选中行改为浅蓝底深色文字 | 无 |
| 画面生成器 | 断路器槽位固定按 zh-CN 排序（并网、储能、负荷）；已发布的工程包不受影响 | 只在重新生成时体现；非 zh-CN 主机上生成的槽位顺序会变 |

### 4.3 104 现场工程

通用 56 页生成器不能替代 104 现场工程。需要重新生成时：

1. 用现场运行配置生成（`-RuntimeConfigDirectory`），显式传入 BAU（`-BauMeterCode`）。
2. 标准生成后再运行 `prepare_comm104_hgm6110nc_controls.py`。
3. 不能因为重新生成丢掉现场工程已有的绑定；未确认的电表口径不猜测补齐。

### 4.4 现场保持

此前各轮的内网验证都在隔离环境进行，前后 130 个安装/配置/服务文件哈希一致，没有重启现场服务，没有改现场配置、账号、证书、EasyTier、4G 或网络；104 未操作。正式部署时同样不应顺带修改这些内容。

## 5. 现场操作与排障

### 5.1 本地画面下发控制之后

1. 看回执框。只有“反馈确认成功”或“画面反馈点……一致”才是动作确认；“已下发，未确认”和“协议写入成功，动作未确认”要到现场核实。
2. 出现“结果未知”时**不要重复点击**。该点保持锁定，直到出现确定回执或 70 秒跟踪期结束，期间点击会提示上一条命令编号。先在现场或监测页核实实际状态，再决定是否重新操作。
3. PCS 三相功率的汇总逐类列出各相结果。“3 相已下发、未确认”不等于协议写入成功，更不等于功率已到位。
4. 灰色按钮可以点，只会弹出不可用的原因（PCS 就地、反馈过期、未开放等），不会下发。

需要紧急操作时，用设备侧或独立急停回路。重启 KY-SCADA 会清掉画面锁，但不会改变设备上可能已经发生的动作，不要把重启当成解锁手段。

### 5.2 常见现象

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 点击后提示上一条命令编号，不下发 | 上一条命令结果未知，该点在跟踪期内锁定 | 等确定回执或 70 秒；先核实现场状态 |
| 回执框改显示“晚到回执” | 10 秒内没收到，70 秒内又收到了最终回执 | 按晚到的结果处理 |
| 状态显示“未知(7)”一类 | 设备报了配置里没有定义的枚举值 | 核对设备手册和点表配置；不要当作画面故障 |
| 状态显示 `--` | 数据陈旧、坏质量，或组合状态的无效组合 | 查采集和通信 |
| AGC/AVC 连续失败计数上升或进入失效 | 结果未知不再重发；可能是通信丢包或 PCS 未执行 | 人工核实 PCS 实际功率和通信，不要改配置去恢复自动重发 |
| 图形 EMS 里 confirmedControlWrite 输出 -2 | 结果未知、反馈不一致或只写入未确认；或目标没配确认条件被拒 | 核实设备状态后人工复位；检查 `verifyIndex` 或回读配置 |
| SOE 页面报 `SOE storage unavailable: min-free-bytes` | SOE 存储所在的文件系统空闲低于生产保护要求的 256 MiB | 清理磁盘或扩大空间；不要调低保护阈值 |

本轮没有修改服务模型、常用命令和 MQTT 主题，其他排障仍按仓库 `doc/部署运维/边端操作手册.md` 第 13 节。
