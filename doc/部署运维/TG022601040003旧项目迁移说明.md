# TG022601040003 旧项目迁移说明

## 设备与旧运行时

- 设备：`TG022601040003`
- 地址：`10.126.126.7`
- 架构：全志 `aarch64`，Ubuntu 20.04.6
- 旧程序目录：`/root`
- 旧 MQTT 客户端：`/root/mqtt_client`
- 旧数据服务：`/root/dataStore`
- 旧 Modbus 服务：`/root/modbusRTU_1`、`3`、`4`、`7`、`8`
- 旧 systemd 单元：`app-mqtt_client.service`、`app-dataStore.service`、`app-modbusRTU_*.service`

旧项目中 `modbusRTU_2/5/6` 没有可执行文件或有效配置，不应继续生成新版采集任务。

## 配置迁移规则

1. 串口参数从 `modbusRTU_N.xml` 读取。
2. 从站和寄存器从 `modbusRTU_N_Reg.xml` 读取。
3. `VarList.xml` 使用 `index` 关联寄存器文件；不能使用 `appDataIndex`。
4. `VarList.xml` 的 `note` 迁移为 `meterCode`，`unit` 迁移为 `pointCode`。
5. 同一从站、同一地址明确存在一条读和一条写时合并为一个新版点，保留读写能力。
6. 多条同地址记录无法唯一判断时不强行合并，并写入迁移报告。

本次生成结果：5 个新版 Modbus 设备文件、64 个从站、1739 个点位。旧 `meterCode` 和 `pointCode` 已回填；旧项目没有可用设备名称字段的点仍需由平台点库补充显示名称。

## MQTT 双路上送

新版路由保持：

```text
edge/telemetry/full/TG022601040003
edge/telemetry/realtime/TG022601040003
```

兼容旧平台的路由保持：

```text
ky/peidian/COMM202600092
```

兼容路不复用新版分片 JSON，而是按旧结构发布：

```json
{"data":[{"meterid":"MTR...","metrics":[{"KY02100024":"1.0000"}]}]}
```

新版路由按新版周期上传，兼容旧路按旧项目的 10 秒周期额外上传。两路使用同一 MQTT broker 连接，不启动旧 `mqtt_client`，避免旧 Modbus/共享内存链路与新版重复运行。

## 切换顺序

1. 备份 `/root`、`/etc/systemd/system/app-*.service`、`/var/log/apps` 和当前网络信息。
2. 停止并禁用旧 Modbus、`mqtt_client`、`dataStore` 服务。
3. 安装新版二进制、systemd 单元和本次生成的 runtime 配置。
4. 先启动新版 Modbus，检查 5 个串口的从站在线和点值数量。
5. 再启动新版 MQTT，分别订阅新版和旧 topic，核对 payload 结构及设备身份。
6. 验证通过后才允许删除旧服务文件；旧配置备份至少保留一版，不能在验证前删除。

## 当前限制

本迁移实现了旧格式遥测兼容上送。旧 MQTT 的遥控、遥调和即时取数入站 topic 使用旧 payload 协议，未在没有样例报文的情况下强行映射到新版命令接口；切换前如仍需旧平台下发控制，应先提供一组脱敏的旧控制报文进行协议适配。
