# 4G 与有线网络故障切换

## 目标

`gateway-network-failover` 持续检查 4G 网卡是否能够访问公网。当 4G 连续不可用时，设备自动使用有线默认路由；4G 恢复并连续检查通过后，再自动恢复为 4G 主路由。

`gateway-cellular` 是前置拨号服务：等待 Quectel ECM 网卡出现，拉起 `usb0`，并以前台常驻方式运行 `udhcpc`，持续完成 DHCP 获取和租约续期。不要使用 `udhcpc -q` 代替该服务；`-q` 获取首个租约后会退出，设备可能在租约变化或链路重建后再次失联。

该服务同时调整默认路由和 systemd-resolved 的 DNS 主出口，不关闭 4G、有线网卡或 EasyTier，因此不会影响设备固定网口和隧道地址的维护访问。只切默认路由、不切 DNS 会出现“公网 IP 可达，但 MQTT 域名无法解析”的假在线状态。

## 判定与切换

- 4G 网卡默认为 `usb0`。有线候选配置默认为 `ens1, auto`：先检查首选口 `ens1`，再自动发现并轮询其余实体以太网口。
- 健康检查通过 `usb0` 单独访问 `223.5.5.5:53`，不会被有线网络的结果误判。
- 连续 3 次检查失败后，依次探测所有有线候选口，将可访问公网的端口设为主路由，并把 4G 默认路由 metric 调整为 `600`。
- 连续 2 次检查成功后，将 4G 默认路由 metric 恢复为 `10`。
- 主出口切换时，把 `~.` DNS 路由和公共 DNS 设置到当前主出口，并清除其他候选接口的 DNS 默认路由。默认 DNS 为 `223.5.5.5`、`119.29.29.29`，可通过 `routeFailover.dnsServers` 覆盖。
- 当前有线端口失效时会优先检查上次选中的端口，再轮询其余实体端口并自动切换。
- 没有 IPv4 地址、没有默认网关或公网探测失败的有线口会被跳过。所有有线口均不可用时不会降低 4G 路由优先级，避免设备完全失联。

默认检查间隔为 15 秒，因此正常情况下约 45 秒切换到有线、约 30 秒恢复到 4G。

正式配置位于 `monitor-service.json -> systemMonitor.cellular.routeFailover`，在 `gateway`、`ems`、`agc_avc` 三种运行模式下共用。`/etc/default/gateway-network-failover` 仅用于兼容没有该配置段的旧项目；运行 JSON 中存在配置时以运行 JSON 为准。

## 安装与启用

初始化包会安装脚本和 systemd 单元。`gateway-services` 根据运行配置中的 `enabled` 字段统一启停该服务，不需要按运行模式分别维护。

当 `routeFailover.enabled=true` 时，`gateway-services` 会同时启用并按顺序启动：

1. `gateway-cellular.service`：维持 `usb0` DHCP 地址和网关。
2. `gateway-network-failover.service`：探测公网并管理默认路由和 DNS。

旧项目尚未重新执行初始化流程时，可手工启用：

```sh
systemctl enable --now gateway-network-failover.service
```

旧项目还应同时启用常驻 DHCP：

```sh
systemctl enable --now gateway-cellular.service
```

查看状态：

```sh
/opt/modbus-gateway/bin/gateway-network-failover.sh status
/opt/modbus-gateway/bin/gateway-cellular.sh status
systemctl status gateway-cellular.service
systemctl status gateway-network-failover.service
tail -n 50 /opt/modbus-gateway/data/network-failover.log
```

状态中的 `wiredCandidates` 表示已发现的候选实体网口，`selectedWiredInterface` 表示当前选中的有线出口。

服务同时把受控状态写入 `/run/gateway-network-failover/state`。除原有的 `mode`、
`last_result` 和 `selected_wired_interface` 外，状态文件还包含：

- `failover_enabled`：自动故障切换是否启用。
- `prefer_cellular`：配置策略是否为 4G 优先。
- `cellular_interface`：配置的 4G 出口网口，默认 `usb0`。

`SystemMonitor` 只读取该状态文件，不执行路由命令，并把结果放入系统遥测的
`cellular.route`：

```json
{
  "available": true,
  "failoverEnabled": true,
  "preferCellular": true,
  "usingCellular": true,
  "mode": "cellular",
  "activeInterface": "usb0",
  "selectedWiredInterface": "",
  "lastResult": "healthy",
  "lastChecked": "2026-07-30T07:46:41Z"
}
```

平台必须分别显示“4G 是否连接”“是否启用 4G 优先”和“当前实际出口”。配置为
4G 优先但因故障回退到有线时，应显示“当前有线出口，4G 备用”，不能仍标记为当前
4G 出口。旧状态文件缺少新增字段时，边端兼容推断运行模式，但平台保持“出口状态未知”，
不伪造 4G 优先状态。

同时检查 DNS 与 MQTT 实际连接，不能只看 systemd 的 `active`：

```sh
resolvectl status usb0
getent hosts kygate.kyxn.net
ss -tnp dst 113.57.218.220:8883
```

## MQTT 连接恢复

边端内置 MQTT 发布器区分接收连接和发送连接。网络或 Broker 主动关闭发送连接后，内核会先显示 `CLOSE-WAIT`；新版发布器在接收轮询和每次发送前都会非阻塞检查该连接，立即释放旧 socket，再建立新连接后发送，避免恢复后的第一条状态、配置分片或事件写入失效连接。

`SystemMonitor` 和 `MqttDriver` 通过接收轮询清除失效发送连接；只发布事件的 `EventEngine` 每 500ms 调用轻量连接维护入口，只检查发送 socket，不订阅控制 Topic。所有服务在实际发送前还会再次检查，因此旧连接不会持续累积，恢复后的第一条消息也不会写入失效连接。排障时应同时检查 PID、`NRestarts`、DNS 解析、MQTT socket 和一次真实配置拉取，不能只看 systemd 的历史失败状态。

Windows 客户端配置拉取验收应看到分片数连续增长并最终达到 `receivedChunks/totalChunks`；只验证连接按钮或 MQTT 端口连通不能覆盖完整链路。

## 现场验证

测试前确认 `ens1` 已获得地址和默认网关。可通过临时不可达探测地址验证回退，再恢复默认探测地址验证自动恢复。测试期间不要关闭 EasyTier，测试完成后必须确认主路由、MQTT 和监控服务均恢复正常。
