# 4G 与有线网络故障切换

## 目标

`gateway-network-failover` 持续检查 4G 网卡是否能够访问公网。当 4G 连续不可用时，设备自动使用有线默认路由；4G 恢复并连续检查通过后，再自动恢复为 4G 主路由。

该服务只调整默认路由优先级，不关闭 4G、有线网卡或 EasyTier，因此不会影响设备固定网口和隧道地址的维护访问。

## 判定与切换

- 4G 网卡默认为 `usb0`。有线候选配置默认为 `ens1, auto`：先检查首选口 `ens1`，再自动发现并轮询其余实体以太网口。
- 健康检查通过 `usb0` 单独访问 `223.5.5.5:53`，不会被有线网络的结果误判。
- 连续 3 次检查失败后，依次探测所有有线候选口，将可访问公网的端口设为主路由，并把 4G 默认路由 metric 调整为 `600`。
- 连续 2 次检查成功后，将 4G 默认路由 metric 恢复为 `10`。
- 当前有线端口失效时会优先检查上次选中的端口，再轮询其余实体端口并自动切换。
- 没有 IPv4 地址、没有默认网关或公网探测失败的有线口会被跳过。所有有线口均不可用时不会降低 4G 路由优先级，避免设备完全失联。

默认检查间隔为 15 秒，因此正常情况下约 45 秒切换到有线、约 30 秒恢复到 4G。

正式配置位于 `monitor-service.json -> systemMonitor.cellular.routeFailover`，在 `gateway`、`ems`、`agc_avc` 三种运行模式下共用。`/etc/default/gateway-network-failover` 仅用于兼容没有该配置段的旧项目；运行 JSON 中存在配置时以运行 JSON 为准。

## 安装与启用

初始化包会安装脚本和 systemd 单元。`gateway-services` 根据运行配置中的 `enabled` 字段统一启停该服务，不需要按运行模式分别维护。

旧项目尚未重新执行初始化流程时，可手工启用：

```sh
systemctl enable --now gateway-network-failover.service
```

查看状态：

```sh
/opt/modbus-gateway/bin/gateway-network-failover.sh status
systemctl status gateway-network-failover.service
tail -n 50 /opt/modbus-gateway/data/network-failover.log
```

状态中的 `wiredCandidates` 表示已发现的候选实体网口，`selectedWiredInterface` 表示当前选中的有线出口。

## 现场验证

测试前确认 `ens1` 已获得地址和默认网关。可通过临时不可达探测地址验证回退，再恢复默认探测地址验证自动恢复。测试期间不要关闭 EasyTier，测试完成后必须确认主路由、MQTT 和监控服务均恢复正常。
