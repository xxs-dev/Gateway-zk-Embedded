# AM5SE-F 原生 SOE

## 实现范围

在既有 AM5SE IEC103 独占连接内，接收装置突发事件，解码后持久化到独立 SQLite 历史库，再由 EMS 本机画面显示。不是对采样值做差分，也不把总召结果伪装成 SOE。

支持 `am5se_active_tcp` 和 `am5se_passive_tcp`。沿用现有 ACD / 一级数据召唤流程，目录召唤、COMTRADE 下载期间收到的事件走相同入口，不建立额外设备连接，不增加电气控制命令。

本次没有部署到现场，也没有发送跳闸、合闸或试验命令。当前验证为本机 Linux x86 编译、模拟协议集成测试和 Qt 离屏测试，不是 Allwinner 现场验收。

## 事件识别

- 仅收录 ASDU1、ASDU2 且 COT=1 的突发事件。总召响应、ASDU44 遥信快照和测量更新不生成事件。
- 按标准 IEC103 单信息体结构解析；ASDU1 保留 DPI 和 CP32，ASDU2 额外保留相对时间 RET、故障序号 FAN。
- 校验 FT1.2 外层及链路地址；存储 ASDU 标识、CA、FUN、INF、原始 DPI、原始 CP32 和完整链路用户数据十六进制。用户数据不含外层起止符、长度和校验字节；完整线路帧仍以通道取证为准。
- 原始 DPI=1/2 才标记值有效，0/3 或带非预期高位者保留为无效值。未确认语义时显示 `DPI=n`，不得自动解释成分/合、动作/返回。
- 不支持的 ASDU 不生成 SOE；符合事件类型但长度不合法的帧报告解析错误，不生成虚假有效事件。此类帧须结合通道取证分析。

设备实际固件的突发帧结构和事件地址表仍需用厂商资料或真实报文确认。模拟测试不能替代固件一致性验证。

## 时标

CP32 只有时、分、毫秒等字段，不含日期。程序按 `utcOffsetMinutes` 将接收日与相邻日期比较，选择距离接收时刻最近的日期，存为 UTC 毫秒。默认偏移 +480 分钟，页面明确显示 UTC。

页面分别显示装置时标和 EMS 接收时刻，并标记“日期推定”。时标无效时装置时间显示 `--`，原始时标仍保留。装置时间可用于核对事件顺序，但本实现按入库序号分页，不因装置时钟回拨而覆盖或重排已有记录。

日期推定不等于装置已对时；装置时钟错误、积压超过半天或设备使用夏令时均可能造成推定日期/绝对时间不可靠。UTC 偏移是固定配置，不自动处理夏令时。

## 启用配置

两个 AM5SE 示例配置已加入默认关闭的 `protocol.iec.soe`。经现场审批后，在实际 AM5SE 驱动配置的 `protocol.iec` 内设置：

```json
"soe": {
  "enabled": true,
  "sqlitePath": "/opt/modbus-gateway/data/iec103-soe.db",
  "utcOffsetMinutes": 480,
  "mappings": []
}
```

启用前检查：

1. 仅现有独占 AM5SE 实例连接装置；配置中的机器身份和设备编号正确。
2. 数据目录已经存在，驱动可写，显示服务可读 SQLite 数据库及 WAL/SHM，运行环境具有 `libsqlite3.so.0`。
3. 可用空间至少 256 MiB；确认时间同步状态和装置使用的时区。
4. 配置在驱动启动时加载。变更需要维护窗口；不要为了验证事件发送实际电气命令。

无映射时也可保存事件，界面保留原值与“含义待确认”。如 FUN/INF/CA 匹配现有点表，可借用点名，但不会据此推断 DPI 极性。

### 可读含义映射

每条映射必须明确 `commonAddress`、`typeId`（1 或 2）、`functionType`、`informationNumber`、`name`、`state1`、`state2` 和 `confirmed:true`；`state1/state2` 分别对应原始 DPI=1/2。相同标识重复定义会被拒绝。

填写顺序：先核对厂商固件地址表与现场报文，再填写中文事件名称及两种状态，最后设置 `confirmed:true`。本实现不预填未经确认的 AM5SE-F 动作/返回表，不能为通过校验而直接填 `confirmed:true`。下属固件或设备型号不同，必须重新确认。

## 本机画面

入口：告警页面 → SOE。当前告警列表保留，新增独立历史页，不以历史事件代替当前告警。

- 每页 50 条，可翻页、回到最新；最新页可见时每 2 秒刷新。
- 事件和状态居中显示，提供装置时间、接收时间、设备编号、事件名、状态、质量。
- 悬停单元格可查看原始编码、RET/FAN、原始 CP32 和链路用户数据。
- 数据库不可读时显示“SOE 数据不可用”，不冒充“无事件”。显示进程只读，不创建事件库，也不提供写入设备的操作。
- `qtSoeTable` 默认使用上述路径；自定义路径时需同步设置画面组件的 `soeDatabase` 属性。
- 当前为边端本地数据库视图。远程工程预览不会自动读取现场库；本次不包含平台上报、远程历史接口、导出或日期筛选。

## 存储与故障边界

SQLite 使用 WAL 和 FULL 同步。每批最多 256 条，使用每次接收分配的事件 ID，对同一待提交批次的重试做幂等处理。相同设备时标、相同内容但不同接收次数的记录不会按内容合并，所以快速“动作→返回”能够分别保存。

写库失败向驱动上层报错，待提交事件及 ID 保留在当前进程内，后续发送请求前先重试提交。失败持续时采集/录波会受阻，应处理磁盘、权限或数据库忙问题；不能把这段时间称为正常持续采集。

按 EMS 接收时间保留约 30 天，每次成功追加后至多每分钟清理 512 条过期记录。清理是渐进的，不是严格容量上限；数据库空闲页可能复用但文件不自动缩小。无新事件时不主动清理，生产需监控容量。

以下不能承诺端到端 exactly-once 或零丢失：

- 设备取出事件后、数据库提交前进程崩溃或断电，内存待提交记录可能丢失。
- 长时间背压可能导致装置事件队列溢出，容量取决于固件。
- 当前同 FCB 超时重试被覆盖，但跨请求的迟到/重复响应并无可靠全局事件号用于判重。
- malformed 或未知类型事件须依赖原始报文进一步分析，不能视为已有完整语义覆盖。

- ASDU1/2、总召排除、截断帧拒绝、无效 DPI/时间、跨午夜日期推定、显式状态映射。
