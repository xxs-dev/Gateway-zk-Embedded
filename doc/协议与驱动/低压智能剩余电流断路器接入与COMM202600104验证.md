# 低压智能剩余电流断路器接入与 COMM202600104 验证

## 1. 适用范围

本文记录《低压智能剩余电流断路器通讯协议-20231101》的边端接入方式，以及 `COMM202600104` 在 `10.126.126.9` 上的现场读写验证结果。

该设备使用 DL/T 645 风格扩展协议，不是 Modbus。单一 `Dlt645Driver` 进程同时承载读取和 `C=14H` 写入，读写共享同一个串口客户端和事务锁。写控采用设备级、点位级双重开关。`COMM202600104` 已验证 0 级出厂密码并按现场要求打开设备级写开关；模式试跳仍保持禁用。

## 2. 现场接线和地址

| 项目 | 配置 |
| --- | --- |
| 设备身份 | `COMM202600104` |
| 串口 | `COM2` / `/dev/ttySP2` |
| 串口参数 | `9600, 8E1` |
| 并网断路器 | 地址 `20`，645 地址 `000000000020` |
| 储能断路器 | 地址 `21`，645 地址 `000000000021` |
| 负荷断路器 | 地址 `22`，645 地址 `000000000022` |

`CN002260608004` 是移动储能 EMS 整机型号/编号，不是断路器通信地址，也不能替代 `machineCode`。

## 3. 协议差异

请求帧为：

```text
FE FE FE FE + 68 + 6字节BCD地址 + 68 + C + L + DATA(+33H) + CS + 16
```

本型号每次请求前必须发送 4 个 `FE` 唤醒字节。未发送前导时，三台设备均无 RX；配置 `transport.wakeupBytes=4` 后，地址 20、21、22 均稳定返回校验正确的响应帧。

边端配置示例：

```json
{
  "protocol": {
    "type": "dlt645_2007",
    "transport": {
      "serialPort": "/dev/ttySP2",
      "baudRate": 9600,
      "dataBits": 8,
      "stopBits": 1,
      "parity": "E",
      "timeoutMs": 800,
      "frameIntervalMs": 150,
      "wakeupBytes": 4
    }
  }
}
```

## 4. 模板分层

项目保留两份点表：

| 文件 | 用途 |
| --- | --- |
| `config/templates/dlt645_residual_current_breaker_20231101_points.json` | 协议完整模板，65 点（59 个监测点、6 个控制点）；供新项目生成和其它固件继续验证 |
| `config/templates/dlt645_residual_current_breaker_20231101_comm104_verified_points.json` | `COMM202600104` 现场模板，51 项：11 个基础读取点、1 个在线点、33 个主动上报 bit、6 个控制点 |

设备配置为 `config/runtime/devices/device_dlt645_breakers_20_22.json`。三个设备共用 COM2 和同一驱动进程，避免同一串口被多个进程并发打开。

## 5. 现场支持结果

2026-07-21 在 `10.126.126.9` 连续读取三台设备，以下 11 个 DI 均返回正常数据：

| DI | 点位 | 字节数 |
| --- | --- | --- |
| `02010100` | A 相电压 | 2 |
| `02010200` | B 相电压 | 2 |
| `02010300` | C 相电压 | 2 |
| `02020100` | A 相电流 | 3 |
| `02020200` | B 相电流 | 3 |
| `02020300` | C 相电流 | 3 |
| `02900000` | 当前剩余电流最大相 | 1 |
| `04000501` | 运行状态字 1 | 现场返回 1 |
| `04000502` | 运行状态字 2 | 现场返回 1 |
| `03810000` | 总跳闸次数 | 2 |
| `03810101` | 断路器运行时间总累计 | 现场返回 2 |

完整模板中的功率、功率因数、频率、剩余电流值、8 路温度、开关状态和 96 位事件状态在当前固件上返回 `D1/ERR=0x01`，表示“无请求数据”。其中温度 DI 已按协议表修正为 `020F0400~020F0407`，复测后仍不支持，因此不是地址拼写问题。

协议完整模板仍保留这些点，不能据此判断其它固件也不支持。`COMM202600104` 生产模板另外保留协议中已明确含义的 33 个主动上报 bit；当前设备不响应对 `04001504` 的主动轮询，所以这些点保持 `quality=0`，不能解释为正常。驱动对同一 DI 的成功或失败结果均按单轮缓存，每个表地址每轮最多请求一次 `04001504`。6 个写控制点没有读取任务，也不会进入全量上传。

## 6. 共享内存 index

现场模板每台设备包含 11 个基础读取点、6 个控制点、1 个在线点和 33 个主动上报 bit。基础读取点原 index 不变：

| 设备 | index 范围 |
| --- | --- |
| 并网断路器 20 | `200000~200010` |
| 储能断路器 21 | `210000~210010` |
| 负荷断路器 22 | `220000~220010` |

控制点 index 如下：

| 设备 | index 范围 |
| --- | --- |
| 并网断路器 20 | `200011~200016` |
| 储能断路器 21 | `210011~210016` |
| 负荷断路器 22 | `220011~220016` |

在线点和主动上报 bit index 如下：

| 设备 | 在线点 | 主动上报 bit |
| --- | ---: | --- |
| 并网断路器 20 | `200017` | `200018~200050` |
| 储能断路器 21 | `210017` | `210018~210050` |
| 负荷断路器 22 | `220017` | `220018~220050` |

上线前已扫描全局显式 index，上述区间没有冲突。2026-07-26 重新部署后，共享内存有 135 个读取点：36 个基础/在线点为 `quality=1`，99 个主动上报 bit 因设备不支持主动轮询而为 `quality=0`。服务 `NRestarts=0`，驱动约占 1% CPU、15 MB RSS。

## 7. 服务与验证

```sh
systemctl status dlt645-driver@device_dlt645_breakers_20_22.service
/opt/modbus-gateway/bin/pointctl dump --shm gateway_point_store_ttySP2 --limit 80
journalctl -u dlt645-driver@device_dlt645_breakers_20_22.service -n 100 --no-pager
```

`mqtt-service.json` 和 `monitor-service.json` 的 `deviceConfigFiles[]` 必须包含断路器设备配置，`sharedMemoryNames[]` 必须包含 `gateway_point_store_ttySP2`，否则驱动虽然能采集，MQTT 全量上传和 Windows 实时监测仍看不到这些点。

## 8. 安全边界

- 驱动实现通用 DL/T 645 `C=14H` 写入，支持 `dlt645_scheduled_control`、`dlt645_none`、`dlt645_bcd`、`dlt645_uint_le` 和 `dlt645_fixed_hex` 编码。
- 协议模板包含预约/立即跳闸、取消跳闸、预约/立即合闸、取消合闸、模式试跳、取消试跳 6 个控制点。模式试跳点默认禁用。
- 设备配置必须显式设置 `dlt645.write.enabled=true`，并填写 4 字节设备写密码后才允许写入。密码按协议数据域 `PA P0 P1 P2` 顺序填写 8 位十六进制字符；操作者代码按 `C0 C1 C2 C3` 顺序填写。
- 维护认证密码 `Kydl2026` 不是断路器设备写密码，不得写入 `dlt645.write.password`。
- `C=94H` 只表示设备接受写请求，不代表物理闸位已变化。必须结合运行状态字、辅助触点或现场确认做结果校验。
- 厂家提供的 0/1/2 级出厂密码分别为 `0000`、`1111`、`2222`，三种权限均可写，操作者代码不限制。协议字段顺序为 `PA P0 P1 P2`；当前生产配置采用并已验证 0 级编码 `00000000`，操作者代码使用 `00000000`。1、2 级密码未做真实控制验证，不作为当前生产配置。
- 2026-07-23 使用负荷断路器地址 22 完成真实分闸、合闸测试：`220011=0` 后独立辅助触点 `index 999` 从 `1` 变为 `0`；`220013=0` 后从 `0` 恢复为 `1`。两次命令均未收到 `D4/ERR`，最终物理状态为合闸。
- 上述合闸完成后，`ttySP2` 地址 20、21、22 同时出现响应超时。共享内存和 UART4 已重建/复位，服务均恢复运行，但设备仍无协议应答。现场必须检查 RS485 A/B、总线端子、通讯模块供电和设备通讯状态；该问题未闭环前禁止继续执行真实控制测试。
- `运行状态字2` 按协议可能在读取后清除设备侧事件新增标识，业务告警不能只依赖该原始字，需要结合事件记录或 DI 辅助触点。
- 同一物理串口只能启动一个采集驱动实例。

设备级写控配置示例：

```json
{
  "dlt645": {
    "write": {
      "enabled": true,
      "password": "00000000",
      "operatorCode": "00000000"
    }
  }
}
```
