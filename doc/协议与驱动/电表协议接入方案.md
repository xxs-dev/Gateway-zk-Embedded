# DL/T 645 电表协议接入说明（2007 / 1997）

本文说明边端 DL/T 645 驱动的当前实现、配置写法和边界，内容与 `src/dlt645_*.cpp`、`src/validation/dlt645_validation.cpp` 一致。标准点表见 [电表协议标准点表说明.md](电表协议标准点表说明.md)，验证流程见 [电表协议运行测试.md](电表协议运行测试.md)，断路器扩展协议见 [低压智能剩余电流断路器接入与COMM202600104验证.md](低压智能剩余电流断路器接入与COMM202600104验证.md)。

## 当前能力

- 独立可执行程序 `Dlt645Driver`，systemd 模板 `dlt645-driver@.service`。`protocol.type` 选择规约版本：`dlt645_2007` 或 `dlt645_1997`（只有这两种写法；`ModbusRtu` 不再承载 DL/T 645 配置）。
- 一个配置文件对应一条串口总线、一个规约版本，`meters[]` 下可挂多块表；同一进程内所有表共用一个串口客户端和事务锁。
- 空 `meters[].points` 按 `protocol.standardPointsFile` 模板自动展开（模板的 `"protocol"` 必须与 `protocol.type` 一致）。
- 结果写入共享内存，由 `MqttDriver` 上传；驱动补充 `device_online` 在线点。

两版帧结构相同（`68 A0..A5 68 C L DATA(+33H) CS 16`，应答 `C|80H`，`C|A0H` 表示有后续帧，`C|C0H` 为异常应答带 1 字节错误字），差别如下：

| 功能 | 2007 | 1997 |
| --- | --- | --- |
| 数据标识 DI | 4 字节，配置写 8 位十六进制 `DI3DI2DI1DI0` | 2 字节，配置写 4 位十六进制 `DI1DI0` |
| 读数据 | `11H` → `91H`/`B1H`/`D1H` | `01H` → `81H`/`A1H`/`C1H` |
| 读后续数据 | `12H`（DI + 帧序号）→ `92H`/`B2H`/`D2H` | `02H`（DI）→ `82H`/`A2H`/`C2H` |
| 写数据 | `14H`：DI、`PA P0 P1 P2`、`C0..C3`、数据 → `94H`/`D4H` | `04H`：DI、`PA P0 P1 P2`、数据（无操作者代码）→ `84H`/`C4H` |
| 远程控制 | `1CH`（见“远程控制”）→ `9CH`/`DCH` | 无 |
| 广播校时 | `08H` | `08H` |
| 读通信地址 | `13H`（全 `AA` 地址）→ `93H` | 读 `C032`（表号）发往通配地址 |
| 错误字 | bit0 其他错误、bit1 无请求数据、bit2 密码错/未授权、bit3 速率不能更改、bit4 年时区数超、bit5 日时段数超、bit6 费率数超 | bit0 非法数据、bit1 数据标识错、bit2 密码错、bit4..6 同左 |

异常应答的错误字按版本解析后上报（如 `ERR=0x04 (password error/unauthorized)`）。

## 运行链路

```text
DLT645 电表 -> Dlt645Driver -> MemoryPointStore -> MqttDriver -> 平台 / Windows 工具 / 本地画面
```

对上统一输出 `index`、`machineCode`、`meterCode`、`pointCode`、`name`、`value`、`quality`、`ts`、`expireAt`，上层不区分 Modbus 或 DLT645。

## 设备配置

```json
{
  "schemaVersion": "1.0.0",
  "protocol": {
    "type": "dlt645_2007",
    "transport": {
      "serialPort": "/dev/ttySP1",
      "baudRate": 2400,
      "dataBits": 8,
      "stopBits": 1,
      "parity": "E",
      "timeoutMs": 1000,
      "frameIntervalMs": 200,
      "readRetryCount": 1,
      "wakeupBytes": 4,
      "localEcho": false
    },
    "standardPointsFile": "config/templates/dlt645_2007_standard_points.json",
    "standardPointsVersion": "1.3.0"
  },
  "dlt645": {
    "autoIndexBase": 200000,
    "timeSync": { "enabled": false, "intervalMs": 86400000 },
    "write": { "enabled": false }
  },
  "collect": {
    "defaultIntervalMs": 1000,
    "maxTasksPerMeterPerCycle": 2,
    "offlineFailureThreshold": 3
  },
  "meters": [
    { "meterCode": "METER0001", "deviceName": "1号电表", "address": "000000000001", "points": [] }
  ]
}
```

传输字段：

| 字段 | 说明 |
| --- | --- |
| `timeoutMs` | 发送完成（有回显时为回显读完）到应答收齐的等待时间 |
| `frameIntervalMs` | 总线静默时间：上一帧应答收完（或超时）后，至少静默这么久才向**任何**表发下一帧 |
| `readRetryCount` | 读超时的 DI 在后续几个采集周期优先重试；写入永不重试 |
| `wakeupBytes` | 每帧前发送的 `FE` 唤醒字节数，0..16 |
| `localEcho` | RS-485 适配器会把发送字节回显到接收端时设为 `true`：驱动发送后先读掉回显并逐字节核对，不一致按总线冲突报错 |

接收侧按帧同步：前导 `FE`、垃圾字节、截断帧、校验错帧会被跳过，从下一个 `68H` 重新找完整帧；其他地址的迟到应答、本表上一个请求的迟到应答（DI 不符）只跳过不采用，等到超时仍无本请求的应答则报错。

`meters[].address` 为 1..12 位十进制数字，不足 12 位左补 0（加载时告警）；含字母、分隔符或超长直接报错；同一总线上地址重复报错。

## 点位写法

```json
{
  "index": 200001,
  "pointCode": "voltage_a",
  "name": "A相电压",
  "enabled": true,
  "collectPriority": 0,
  "read": {
    "enable": true,
    "dataType": "dlt645_bcd",
    "scale": 0.1,
    "unit": "V",
    "intervalMs": 1000,
    "dlt645": { "di": "0201FF00", "byteCount": 2, "offset": 0 }
  }
}
```

- 倍率写在 `read.scale`（`read.offset` 为数值偏移量）。`read.dlt645` 只有 `di`、`byteCount`、`offset` 三个字段；在 `read.dlt645` 里写 `scale` 或 `decoder` 加载时报错，不再被静默忽略。
- `read.dlt645.di`：2007 为 8 位十六进制 `DI3DI2DI1DI0`（如 `02010100`），1997 为 4 位十六进制 `DI1DI0`（如 `B611`）；位数与 `protocol.type` 不符加载报错。
- `read.dlt645.byteCount`：该点占用的字节数；`0` 表示取 DI 数据的剩余全部字节（仅适合单值 DI）。
- `read.dlt645.offset`：该点在 DI 数据内的字节偏移，用于块读。共用同一 DI 的点只发一次请求，各自按 `offset/byteCount` 取值。例如 `0201FF00` 依次返回 Ua、Ub、Uc（各 2 字节）：Ua `offset=0`、Ub `offset=2`、Uc `offset=4`。块 DI（2007 任一字节为 `FF`，如 `0201FF00`；1997 末位为 `F`，如 `901F`、`B61F`）的点必须写 `byteCount`；同一块 DI 上两个点解码完全相同的字节（漏写 `offset`）加载报错。
- `collectPriority`：`0` 实时量（默认），`>0` 后台量，见“调度”。

`read.dataType` 白名单（其余类型加载报错）：

| 类型 | 说明 |
| --- | --- |
| `dlt645_bcd` | 无符号 BCD，低字节在前；任何半字节为 A..F（含 `FF` 填充）判为非法值，点置坏质量 |
| `dlt645_bcd_signed` | 最高字节 bit7 为符号位，其余 BCD：电流、功率、需量、功率因数、组合无功电能 |
| `dlt645_uint_le` | 小端无符号整数（≤8 字节）；配 `read.bit` 取单个位 |
| `dlt645_bitfield_le` | 小端状态字，配 `read.bit` 取位 |
| `dlt645_hex` / `dlt645_datetime` | 原始字节十六进制文本 |
| `dlt645_ascii` | 原始字节文本 |
| `device_online` | 驱动生成的在线点，不发请求 |

## 调度

每个 DI 是一个读任务，服务所有共用该 DI 的点。每个采集周期：

1. 选出已到期的 DI（任一点距上次读取已满 `read.intervalMs`），按到期先后排序，越久没读越先读。
2. 先排实时 DI（`collectPriority=0`），最多 `collect.maxTasksPerMeterPerCycle` 个（实时租约下用 `realtimeMaxTasksPerMeterPerCycle`）。
3. 剩余名额给到期的后台 DI；实时量占满名额时，每隔 `backgroundTaskIntervalMs` 仍给后台 1 个名额（与 Modbus 采集器同一规则），保证后台量不饿死。
4. 一个周期内遇到第一个读超时即结束该表本周期，死表每周期只耗一次超时，不拖住同总线其他表。

刷新周期由总线带宽决定：以标准模板为例，23 个实时 DI、每周期 2 个，约 12 个周期轮完一次；12 个电能 DI 为后台量，约 60 s 一轮。需要更快时可提高 `maxTasksPerMeterPerCycle`，或在电表支持时改用块读（如 `0201FF00`、`0203FF00`）。

## 失败与离线

- 单个 DI 读超时：连续失败未达 `collect.failureBadQualityThreshold`（且在 `failureGoodValueGraceMs` 内）时保留上次好值；达到后该 DI 的点置坏质量（保留旧数值，`quality=0`）。
- 表回异常应答（2007 `D1H` / 1997 `C1H`）：说明表在线但没有该数据，该 DI 的点立即置坏质量，不计入离线。
- 整表：连续 `offlineFailureThreshold` 个周期没有任何应答判离线，`device_online=0`，该表**全部**采集点置坏质量；此后每周期只探测一次，并按 `slaveFailureBackoff*` 退避。连续 `recoverySuccessThreshold` 个周期有应答恢复在线。
- 未达离线阈值前的失败只记日志，不上报 `collect-failed`，在线点保持原值。

## 写入与控制

写入默认关闭，必须同时满足：

1. 设备配置 `dlt645.write.enabled=true`，并配置 `password`（8 位十六进制，顺序 `PA P0 P1 P2`）；2007 还需 `operatorCode`（`C0..C3`），1997 写帧没有操作者代码（配置了只告警、不使用）；
2. 点位 `enabled=true` 且 `write.enable=true`。

口令规则：

- `password` 填完整的 8 位十六进制字符串，字段顺序 `PA P0 P1 P2`（`PA` 为权限等级，`P0..P2` 为密码）；`operatorCode` 同样 8 位十六进制（`C0..C3`）。格式不对加载报错。
- 厂家 0 级出厂密码 `0000` 的协议编码是 `00000000`，是有效口令，不拒绝。COMM202600104 的断路器使用 `password=00000000`、`operatorCode=00000000`，已在地址 22 的负荷断路器上完成实际分、合闸验证。
- 口令随运行配置下发，配置拉取时按 `password` 字段脱敏；调试帧日志（`GATEWAY_DLT645_DEBUG=1`）中写帧和远程控制帧整帧脱敏为 `<redacted>`。

支持的写编码：`dlt645_scheduled_control`（断路器扩展跳/合闸：延时 0..99 + 单位，0 为立即；仅 2007）、`dlt645_remote_control`（`1CH` 远程控制，仅 2007）、`dlt645_none`、`dlt645_fixed_hex`、`dlt645_bcd`、`dlt645_uint_le`。

跳/合闸等开关命令（`dlt645_scheduled_control`，以及 `dlt645_remote_control` 的 `trip`、`close`）必须配置闸位读回，否则加载报错。读回目标二选一：

- `write.dlt645.verifyPointCode`：本表的 DL/T 645 读点（如闸位 DI `07020100`），执行器直接向表读取；
- `write.dlt645.verifyIndex`：本网关上其他设备的点（网关 index），例如固件没有闸位 DI 时用 DIO 辅助触点。执行器从共享点库读取：值必须是好质量、未过期；`94H` 之后只认命令发出之后采集到的值。用模板展开的表在 `meters[].positionReadBackIndex` 里填这个 index，驱动把它填进该表所有缺读回目标的开关点。

本表读回示例：

```json
"write": {
  "enable": true, "min": 0, "max": 99, "step": 1,
  "verifyAfterWrite": true, "verifyByRead": true, "verifyDelayMs": 200,
  "dlt645": {
    "di": "06010101", "dataType": "dlt645_scheduled_control", "byteCount": 2, "unit": 2,
    "verifyPointCode": "breaker_switch_state", "verifyValue": 0, "verifyTimeoutMs": 3000
  }
}
```

跨设备读回示例（COMM202600104：断路器 20/21/22 的闸位来自 DIO 辅助触点 998/997/999）：

```json
"meters": [
  { "meterCode": "COMM202600104_LOAD_BREAKER", "address": "000000000022", "positionReadBackIndex": 999 }
]
```

模板里的开关点只写 `verifyAfterWrite`、`verifyByRead`、`dlt645.verifyValue`（跳闸 `0`、合闸 `1`），不写目标；启用了开关点但没有读回目标的表，驱动启动时报错。

执行流程：

1. 执行前读一次读回目标：读不到（点库：没有值、过期或坏质量）则拒绝、不发命令；已是目标值（`verifyValue`）则直接返回成功、不发命令。
2. 发送命令（`14H`/`04H`/`1CH`）。异常应答（`D4H`/`C4H`/`DCH`）为明确拒绝，错误字解析后上报；超时、校验错、回显不符等“已发出但无确定应答”的情况返回 `outcomeUnknown=true`（`success=false`），上层不得换新 cmdId 重试。
3. 立即命令收到正常应答（`94H`/`84H`/`9CH`）后，等待 `verifyDelayMs`，在 `verifyTimeoutMs` 内轮询读回点：到达目标值为成功（`verifyAttempted=verifyPassed=true`）；读到其他值为失败；一次都读不到为 `outcomeUnknown`。
4. 延时命令（1..99 分钟）只确认 `94H`，结果注明未校验闸位。
5. 写入不自动重试。

开关点满足 `verifyAfterWrite + verifyByRead`，可直接作为图形 EMS `confirmedControlWrite` 的目标（其确认依赖驱动回执的 `verifyPassed`）。

## 远程控制（2007 `C=1CH`）

DL/T 645-2007 标准远程控制，帧数据为 `PA P0 P1 P2`、`C0..C3`、`N1`（控制类型）、`N2`（保留 `00`）、`N3..N8`（命令有效截止时间 `ssmmhhDDMMYY`，网关本地时间 + `validitySeconds`）；正常应答 `9CH`，异常应答 `DCH`（错误字解析上报）。点位写法：

```json
{
  "index": 200280, "pointCode": "dlt645_remote_trip", "enabled": true,
  "write": {
    "enable": true, "allowedValues": [1],
    "verifyAfterWrite": true, "verifyByRead": true, "verifyDelayMs": 500,
    "dlt645": {
      "dataType": "dlt645_remote_control", "controlType": "trip", "validitySeconds": 300,
      "verifyPointCode": "dlt645_relay_open", "verifyValue": 1, "verifyTimeoutMs": 5000
    }
  }
}
```

| `controlType` | N1 | 说明 | 闸位读回 |
| --- | --- | --- | --- |
| `trip` | `1AH` | 跳闸（拉闸） | 必须 |
| `close_permit` | `1BH` | 合闸允许（由用户在表上合闸） | 不要求 |
| `close` | `1CH` | 直接合闸 | 必须 |
| `alarm` / `alarm_release` | `2AH` / `2BH` | 报警 / 报警解除 | 不要求 |
| `keep_power` / `keep_power_release` | `3AH` / `3BH` | 保电 / 保电解除 | 不要求 |

- 远程控制点没有 DI，写 `1` 触发；`validitySeconds` 10..86400，默认 300。
- 与写入同一套安全约束：设备级与点级写开关默认关闭、跳/合闸强制闸位读回、执行前读、应答后读回确认、无确定应答为 `outcomeUnknown`、不自动重试、日志脱敏。
- 标准表的继电器状态在运行状态字 3（`04000503`）bit4（0 通、1 断），国标模板提供默认禁用的 `dlt645_relay_open` 读点与 `dlt645_remote_trip`/`dlt645_remote_close` 控制点。
- 本实现发送明文口令帧。要求密文（ESAM 安全认证、身份认证后加密下发）的费控表不适用，此类表会以 `DCH`（密码错/未授权）拒绝。
- 1997 配置使用 `dlt645_remote_control` 加载报错。

## 广播校时（`C=08H`）

`dlt645.timeSync.enabled=true` 时，驱动向广播地址 `999999999999` 发送 `ssmmhhDDMMYY`（网关本地时间），表不应答。默认关闭。

```json
"dlt645": { "timeSync": { "enabled": true, "intervalMs": 86400000 } }
```

- 周期 `intervalMs` 为 1 h..7 d（默认 1 d，按单调时钟计，不受墙钟跳变影响）。
- 只在网关时钟可信时发送：内核报告时钟已同步（`adjtimex` 的 `STA_UNSYNC` 已清除，即 `timedatectl` 的 “System clock synchronized: yes”，由 chrony/ntpd/systemd-timesyncd 置位），且日期不早于 2024 年。不可信时跳过并每分钟重试，日志说明原因。
- 23:55～00:05 不发送（标准不允许在午夜 0 时前后 5 min 内校时，避开日冻结与结算），推迟到窗口之后。
- 广播与采集、写入共用同一客户端：等当前事务结束并经过总线静默时间后才发送，发送瞬间取时间；发送后同样保持静默时间。
- 标准限制：DL/T 645-2007 规定广播校时不应答，表只在自身时钟与广播时间相差 ±5 min 以内时执行，且每日只校一次（当天多发的被表忽略），因此每次最多纠正 5 min，默认周期 1 d 即可。1997 表同样不应答，幅度与次数限制以表计说明书为准。偏差超过 5 min 的表需用带口令的写日期/时间（2007 `04000101`/`04000102`，1997 `C010`/`C011`）现场处理，本驱动不自动下发。

## 读通信地址诊断

用于调试：总线上只接一块表时读出它的通信地址。不进入周期采集，需先停止该串口上的驱动服务（串口独占）。

```bash
/opt/modbus-gateway/bin/Dlt645Driver --config <设备配置> --app-config <应用配置> --read-address
/opt/modbus-gateway/bin/Dlt645Driver --config <设备配置> --app-config <应用配置> --read-address --address-pattern AAAAAAAA0012
```

- 2007：全 `AA` 地址发 `13H`（应答 `93H` 带表地址）；缩位地址（低位为已知的表号末几位、高位字节为 `AA`，如 `AAAAAAAA0012`）发读 `04000401`。
- 1997：向通配/缩位地址读 `C032`（表号）。
- 监听整个 `timeoutMs`：多块表同时应答（多个地址或报文冲突）时报错并提示断开其他表或改用缩位地址；无应答时报“无表应答”。

## 加载校验

`parseDeviceConfig` 末尾调用 `validateDlt645DeviceConfig`，模板在加载时调用 `validateDlt645PointList`。报错（加载失败，信息带点名和字段名）：

- 未知 `read.dataType` / 写编码；`di` 位数与 `protocol.type` 不符（2007 8 位、1997 4 位十六进制）；1997 配置使用 `dlt645_scheduled_control` / `dlt645_remote_control`；远程控制点写了 DI、`controlType` 未知、`validitySeconds` 不在 10..86400；
- `byteCount`/`offset` 越界、块 DI 缺 `byteCount`、块 DI 上重复解码同一字节、`bit` 用在不支持的类型或越界、`scale` 为 0；
- 表地址非 1..12 位数字、同总线地址重复；`wakeupBytes` 不在 0..16；
- `password`/`operatorCode` 不是 8 位十六进制；2007 开启写入缺 `operatorCode`；
- `dlt645.autoIndexBase` 不在 1..4294967295、自动编号块超出 uint32、显式 index 落在自动展开表的编号块内；
- `dlt645.timeSync.enabled=true` 时 `intervalMs` 不在 1 h..7 d；
- 模板缺 `"protocol"`，或模板版本与 `protocol.type` 不符（驱动展开时）；
- 开关命令缺闸位读回（模板除外，目标由 `meters[].positionReadBackIndex` 提供，驱动启动时按展开后的表检查）；`verifyPointCode` 与 `verifyIndex` 同时配置或都没配；`verifyPointCode` 不是本表启用的读点；`verifyIndex` 指向命令点自身；跨设备读回缺 `verifyValue`；写编码与 `byteCount`/`unit`/`min`/`max` 不匹配。

仅告警：地址不足 12 位、非块 DI 上重复解码、点写开但协议写关、禁用点上的上述问题。

## 自动展开与 index

`meters[].points` 为空时按模板顺序展开：第 n 块表（从 0 计，含禁用的表）`index = dlt645.autoIndexBase + n×10000 + 模板位置`，`autoIndexBase` 默认 200000，每表占 10000 个编号（模板不得超过 10000 点）。驱动、点库路由、MQTT 服务和本地画面用同一展开函数（`expandDlt645MeterPoints`）。模板新增点只能追加在末尾，避免已有点 index 漂移。

同一网关加载多份使用自动展开的 DL/T 645 配置时，每份配置设不同的 `autoIndexBase`（如 200000、300000），编号块不能重叠（重叠时点库路由报重复 index）。单份配置内的显式 index 与自动编号块重叠在加载时报错。

## Mock

`Dlt645Driver --mock` 使用模拟电表（`Dlt645MockSerialPort`），只有配置中启用的表地址应答：

- 2007：按国标格式应答模板中所有 DI（`0205` 视在功率、`0206` 功率因数、`0207` 相角、带符号电流/功率/组合无功电能、`FF` 块读）和断路器扩展 DI；`14H` 回 `94H`，`1CH` 回 `9CH`，二者都模拟分合闸（`07020100` 与状态字 3 bit4 反映闸位）；`13H` 回本表地址。
- 1997：`01H` 读 `901x/902x/911x/912x` 电能、`B61x` 电压、`B62x` 电流、`B63x/B64x` 功率、`B65x` 功率因数、`C032` 表号及 `F` 结尾块；`04H` 回 `84H`。
- 未知 DI 回异常应答 `ERR=02`；`08H` 广播只记录不应答；通配地址匹配多块表时模拟应答冲突；支持 `FE` 前导与 `localEcho`。
