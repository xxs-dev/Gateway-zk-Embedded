# COMM202600104 厂家枚举与 PMC-350-A5 点表验收

## 1. 目的

本文记录 `COMM202600104 / 10.126.126.9` 厂家点表整理结果。目标不是把原始状态字简单改名，而是同时保留诊断依据和可直接阅读的业务状态：

- 厂家状态、告警、故障点使用 `valueMap` 描述原始值含义。
- 位域保留原始字，并按协议 bit 定义生成独立点。
- 质量为 `0` 的点保持“未知”，不能用 `value=0` 推断为正常。
- 协议不支持、地址为 `0` 且默认关闭的旧占位点，在确认无策略和画面依赖后删除。

Windows 实时监测从工程配置读取 `valueMap` 并显示中文含义；边端继续保存数值、质量和原始字，EMS 逻辑只依赖稳定 index 和明确的质量状态。

## 3. PMC-350-A5 点表变更

依据 `PMC-350-A5_Modbus规约_V2.4_20250429`，每台电表删除以下 10 个旧占位点：

- 当前组合有功尖、峰、平、谷电能。
- 当前组合无功尖、峰、平、谷电能。
- 电压变比 PT。
- 旧运行状态占位点。

删除前已扫描当前 EMS 策略、模块化策略图、KY-EMS 绑定和工程配置，没有发现运行逻辑引用。`KY-EMS-PointMap.example.json` 中残留的同名映射也已删除，避免画面继续显示永远无值的点。

每台电表按说明书新增 36 个协议寄存器点和 41 个拆位点，包含：

- DI、DO 状态字及各通道状态。
- 剩余电流断线、装置供电状态。
- 4 路温度探头断线。
- 16 路越限报警。
- 接线自检、暂态报警、电压缺相等状态位。
- 寄存器 `95~104` 的协议状态和运行数据。
- 基本参数寄存器 `6000/6002/6004/6006`：电压一、二次侧额定值和电流一、二次侧额定值。

运行配置每台共 130 点，其中额外包含设备在线点。原始状态字继续保留，拆位点使用 `0=正常/断开`、`1=具体告警/闭合` 等协议含义，便于定位具体原因。

4 个基本参数按 `uint32/ABCD` 读取，读取功能码为 `0x03`。写入使用协议规定的 `0x10`，边端 JSON 以十进制保存为 `16`；写入启用高优先级、范围校验和写后回读。`6006` 仅允许 `1/2/3/4/5/100A`，不能把 `6~99` 当作连续有效值。现场验收只执行读取，没有修改设备参数。

## 4. 现场验收

2026-07-26 在 `10.126.126.9` 验收：

- 三台 PMC-350-A5 均为 `130/130` 点 `quality=1`。
- `gateway_point_store_ttySP1` 共 390 点，无缺失、无坏质量。
- 三台电表均包含寄存器 `95~104`。
- 三台电表的 `6000/6002/6004/6006` 实测均为 `380/380/5/5`，质量均为 `1`。
- 三台电表各有 41 个拆位状态点，均带非空 `valueMap`。
- 30 个旧占位 pointCode 在运行配置中剩余 0 个。
- `modbus-rtu@device_modbusRTU_1.service` 为 `active/running`，`NRestarts=0`。

DL/T 645 断路器的 `04001504` 是主动上报状态字，当前设备不响应主动轮询，因此 33 个事件 bit 保持 `quality=0`。这表示“未知”，不是“全部正常”。采集器已保证同一表地址、同一 DI、同一轮最多发一帧；超时结果也会在该轮复用，不再因 33 个 bit 重复请求 33 次。
