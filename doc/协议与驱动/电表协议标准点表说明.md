# DLT645-2007 标准点表说明

本文说明当前 `DLT645-2007` 标准点表模板的用途、字段和维护规则。标准模板文件位于：

- [dlt645_2007_standard_points.json](../../config/templates/dlt645_2007_standard_points.json)

## 当前定位

标准点表是 DLT645 电表配置的固定基线：

- 模板由项目维护，不要求现场人员逐点手填 DI。
- 平台和 Windows 工具生成 DLT645 设备配置时使用同一份模板。
- 边端 `Dlt645Driver` 在 `meters[].points` 为空时可按模板自动展开。
- 模板用于统一中文名称、`pointCode`、`DI`、倍率、单位和数据类型。

模板不是运行时采集结果，也不保存具体电表地址和最终 `index`。具体电表实例仍在设备配置的 `meters[]` 中维护。

## 文件结构

模板文件结构：

```json
{
  "protocol": "dlt645_2007",
  "version": "1.2.0",
  "source": "national_standard",
  "points": [
    {
      "templateKey": "forward_active_energy_total",
      "pointCode": "forward_active_energy_total",
      "name": "正向有功总电能",
      "category": "telemetry",
      "di": "00010000",
      "dataType": "dlt645_bcd",
      "byteCount": 4,
      "scale": 0.01,
      "unit": "kWh",
      "defaultIntervalMs": 1000,
      "storeLatest": true,
      "storeHistory": true,
      "reportOnChange": false,
      "enabledByDefault": true
    }
  ]
}
```

## 字段说明

| 字段 | 说明 |
| --- | --- |
| `templateKey` | 模板内唯一键，用于生成和差异比对 |
| `pointCode` | 业务点编码，导出到设备配置后保持稳定 |
| `name` | 中文点名，实时监控和表格编辑默认显示 |
| `category` | 点位分类，常见 `telemetry`、`status`、`event` |
| `di` | DLT645 数据标识，4 字节十六进制字符串 |
| `dataType` | 解析类型 |
| `byteCount` | 响应数据字节数 |
| `scale` | 倍率 |
| `unit` | 单位 |
| `defaultIntervalMs` | 默认采集周期 |
| `collectPriority` | `0` 实时量（默认），`>0` 后台量；见[电表协议接入方案.md](电表协议接入方案.md)“调度” |
| `offset` | 块读时该点在 DI 数据内的字节偏移（对应设备配置的 `read.dlt645.offset`），默认 0 |
| `bit` | `dlt645_uint_le` / `dlt645_bitfield_le` 取位 |
| `storeLatest` | 是否写最新值缓存 |
| `storeHistory` | 是否进入历史采样 |
| `reportOnChange` | 是否按变位事件上传 |
| `enabledByDefault` | 生成设备配置时是否默认启用 |
| `access` / `write` | 写点：`access=write` 且带 `write` 块；模板里的写点一律默认关闭 |

模板条目里的 `scale` 即设备点位的 `read.scale`。可选的说明字段（`desc`、`phase`、`notes`、`standardSource` 等）不参与运行。

## 数据类型

模板只允许以下类型，其余类型加载模板时报错：

- `dlt645_bcd`：无符号 BCD（A..F 半字节判非法）
- `dlt645_bcd_signed`：最高位为符号位的 BCD（电流、功率、功率因数、组合无功电能）
- `dlt645_uint_le`、`dlt645_bitfield_le`：小端整数 / 状态字（配 `bit`）
- `dlt645_hex`、`dlt645_datetime`、`dlt645_ascii`：原始字节文本
- `device_online`：驱动生成的在线状态点

## 关键 DI 与格式（DL/T 645-2007）

| 数据 | DI | 格式 | 模板类型 |
| --- | --- | --- | --- |
| 电压 A/B/C | `02010100..02010300` | XXX.X V，2 字节 | `dlt645_bcd` |
| 电流 A/B/C | `02020100..02020300` | XXX.XXX A，3 字节，最高位方向 | `dlt645_bcd_signed` |
| 有功功率 总/A/B/C | `02030000..02030300` | XX.XXXX kW，3 字节，有符号 | `dlt645_bcd_signed` |
| 无功功率 总/A/B/C | `02040000..02040300` | XX.XXXX kvar，3 字节，有符号 | `dlt645_bcd_signed` |
| 视在功率 总/A/B/C | `02050000..02050300` | XX.XXXX kVA，3 字节，有符号 | `dlt645_bcd_signed` |
| 功率因数 总/A/B/C | `02060000..02060300` | X.XXX，2 字节，有符号 | `dlt645_bcd_signed` |
| 相角 A/B/C | `02070100..02070300` | XXX.X °，2 字节 | `dlt645_bcd`（默认禁用） |
| 电网频率 | `02800002` | XX.XX Hz | `dlt645_bcd` |
| 正/反向有功电能 | `0001xx00` / `0002xx00` | XXXXXX.XX kWh | `dlt645_bcd` |
| 组合无功1/2 电能（模板名“正向/反向无功”） | `0003xx00` / `0004xx00` | XXXXXX.XX kvarh，最高位符号 | `dlt645_bcd_signed` |

1.2.0 修正：1.1.0 把 `0206xx00` 标成视在功率、`0207xx00` 标成功率因数，电流和组合无功电能按无符号解码（-25.5 A 被解成 825.5 A）。修正时保持各点在模板中的位置不变（自动 index 不漂移），相角点追加在末尾。

## 默认启用与周期

| 类别 | 默认 | 周期 | 优先级 |
| --- | --- | --- | --- |
| 电压/电流/功率/功率因数/频率 | 启用 | 1000 ms | 实时（0） |
| 当前电能（总及费率） | 启用 | 60000 ms | 后台（1） |
| 上 1..12 结算日电能（240 点） | 禁用 | 3600000 ms | 后台（1） |
| 相角 | 禁用 | 1000 ms | 实时（0） |

结算日数据每月只变一次，默认不采；需要时在设备配置中显式启用，周期不应低于 1 h。

## 点位范围

模板 1.2.0 共 279 点：

- 当前正/反向有功电能、组合无功1/2 电能（总及费率 1..4）
- 上 1 到上 12 个结算日电能（默认禁用）
- 三相电压、三相电流
- 总及分相有功、无功、视在功率，总及分相功率因数
- 三相相角（默认禁用）
- 电网频率
- 驱动补充在线点 `device_online`

需量、状态字等其它 DI 不在国标模板中，需要时在设备配置 `points[]` 中按上文写法添加。

## 结算日电能规则

结算日数据按规则展开，不手工维护 240 条重复逻辑。

组合规则：

```text
dataId = typeCode | (itemNo << 8) | dayNo
```

参数：

| 参数 | 取值 |
| --- | --- |
| `dayNo` | `1..12`，表示上 1 到上 12 个结算日 |
| `itemNo` | `0` 总电量，`1..4` 费率 1 到费率 4 |
| 正向有功 `typeCode` | `0x00010000` |
| 反向有功 `typeCode` | `0x00020000` |
| 组合无功1（正向无功）`typeCode` | `0x00030000` |
| 组合无功2（反向无功）`typeCode` | `0x00040000` |

示例：

- 上 1 个结算日正向有功总电量：`00010001`
- 上 1 个结算日正向有功费率 1 电量：`00010101`
- 上 12 个结算日反向无功费率 4 电量：`0004040C`

## 命名规则

`templateKey` 是英文稳定键（如 `forward_active_energy_total`、`settlement_day_1_forward_active_energy_tariff_1`、`apparent_power_total`），用于生成和差异比对；`pointCode` 使用平台统一编码（如 `KY02100891`），导出到设备配置后保持稳定；中文名用于界面显示。1.2.0 新增的相角点没有平台编码，`pointCode` 为 `dlt645_phase_angle_a/b/c`。

## 默认行为

| 点位类别 | `storeLatest` | `storeHistory` | `reportOnChange` |
| --- | --- | --- | --- |
| 电能类 | true | true | false |
| 结算日电能类 | true | true | false |
| 电压/电流/功率/频率类 | true | true | false |
| 在线点 | true | false | true |

## index 分配

标准模板本身不固定 `index`。设备配置生成时再按电表实例分配：

- 第 1 块表：`200000 + 点位偏移`
- 第 2 块表：`210000 + 点位偏移`
- 第 3 块表：`220000 + 点位偏移`
- 每块表预留 `10000` 个 index；点位偏移即模板中的位置，模板只能在末尾追加点

该编号只在一个设备配置文件内唯一：同一网关有多份自动展开的 DLT645 配置时会从 200000 重复编号，必须在 `points[]` 中写显式 index。正式工程生成时，应再经过全局点位路由表检查，确保不会和 Modbus、DIDO、CAN、IEC、EMS 虚拟点等重复。

更新标准模板时必须同步检查：

- [电表协议接入方案.md](电表协议接入方案.md)
- [电表协议运行测试.md](电表协议运行测试.md)

- Windows 工具内置模板和初始化包
- 平台配置生成逻辑

新增或修改模板点位时，不要随意改变已投产项目正在使用的 `pointCode`。如确实需要改名，应在平台和 Windows 工具里做兼容迁移。
