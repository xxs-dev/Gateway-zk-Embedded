# IEC101/103/104 接入设计

边端独立 `IecDriver` 负责 IEC 60870-5-101/103/104 采集，不挂载到 Modbus、DLT645 或 CAN 驱动。采集结果写入 `MemoryPointStore`，由 `MqttDriver` 统一负责全量、实时和补发，驱动内不直接推 MQTT。

## 支持范围

| 协议 | 链路 | 实现 |
| --- | --- | --- |
| IEC104 (`iec104`) | TCP 长连接 | `Iec104Client`：STARTDT/TESTFR/S 帧、k/w 窗口、t1/t2/t3、N(S)/N(R) 监视；总召唤与电度召唤（跟踪 ACT_CON/ACT_TERM）；自发变位后台接收；遥控/设点；对时（等待确认）；参数与文件传输 API |
| IEC101 (`iec101`) | 串口 FT1.2，**非平衡方式** | `IecFt12Client` + 通用 FT1.2 非平衡主站：请求链路状态、复位远方链路、FCB 翻转、同 FCB 重发、二级数据轮询、按 ACD 请求一级数据；总召唤、电度召唤 |
| IEC103 (`iec103`/`iec103_serial`/`iec103_tcp`) | 串口或 TCP 上的 FT1.2，非平衡方式 | 同一 FT1.2 主站：复位通信单元、ASDU 7 总召唤（COT 9）、ASDU 8 结束总召唤、一级/二级数据轮询 |
| 安科瑞 AM5/AM5SE IEC103 网口 | 边端主动连接装置 TCP Server（`am5se_active_tcp`），或装置经 UDP 广播后反连边端（`am5se_passive_tcp`） | `Am5seIec103Client`：使用同一个 FT1.2 主站与轮询会话，另加两种连接方式和 COMTRADE 录波 |

- 平衡方式未实现：IEC101/103 配置 `balanced=true` 在加载时被拒绝。
- IEC101 只实现串口；遥控/设点、参数、文件只实现 IEC104。
- 不再有两套 FT1.2 链路实现：IEC101、通用 IEC103 与 AM5SE 共用 `src/iec_ft12_link.cpp`（链路层）和 `src/iec_ft12_client.cpp`（轮询会话）。

## FT1.2 非平衡主站（IEC101/IEC103/AM5SE）

每个采集周期 `poll()`：

1. 链路未就绪时初始化：IEC101 先“请求链路状态（FC9）→链路状态（FC11）”，再“复位远方链路（FC0）→确认”；IEC103 直接“复位通信单元（FC0）→确认”。复位后第一帧 FCV=1 报文 FCB=1。
2. 链路（重新）建立后发总召唤：IEC101 为 `C_IC_NA_1`（COT 6，QOI=`interrogationQualifier`），IEC103 为 ASDU 7（COT 9，SCN=`returnInformationIdentifier`）。之后按 `interrogationIntervalMs` 周期重复；未收到结束（IEC101 ACT_TERM、IEC103 ASDU 8）的总召唤至少 `max(周期, 5 min)` 内不重发。IEC101 在总召唤结束后发电度召唤 `C_CI_NA_1`。
3. 每周期请求一次二级数据；任何应答 ACD=1 时请求一级数据，直到 ACD=0 或达到 `maxPollFrames`。总召唤已发出但链路复位后尚未收到任何应用数据时，继续请求二级数据直到帧数上限。
4. 应答 DFC=1 时本周期不发总召唤/电度召唤等用户数据，只请求数据。

链路规则：

- 每个请求的应答超时为 `pollTimeoutMs`；无应答时以同一 FCB 原样重发 2 次，仍无应答则链路置为未就绪并报错，下个周期重新初始化链路并**重新总召唤**。
- 发送新请求前清空接收缓冲；应答必须来自配置的链路地址、PRM=0、功能码与请求匹配（发送/确认：ACK/NACK 或 E5；请求/响应：用户数据 FC8、无数据 FC9 或 E5；链路状态：FC11），否则丢弃。
- **兼容分支（临时）**：请求/响应的“无数据”应答目前还接受固定帧 ACK（FC0）。来由：现场已验证的 AM5 装置对空的一级/二级数据请求回的是哪个功能码当时没有记录，而旧 AM5SE 驱动接受任何帧；若直接拒绝 FC0，该装置可能每个周期都触发链路复位。删除条件：现场用通道报文监测确认该装置无数据应答为 FC9 或 E5 后，删除 `src/iec_ft12_link.cpp` 中 `Ft12UnbalancedMaster::acceptable()` 的 `|| function == 0`。
- 重发后，同一请求的迟到重复应答（与已接受应答字节相同）被识别并丢弃，不会被当作下一次请求的应答（修复“迟到一次后每次都拿到上一次数据”）。
- 总召唤开启（`pollOnCollect=true`）时，链路复位后子站只回 E5/ACK、从未给出任何应用数据，`poll()` 报错（设备离线），不再显示“在线但无数据”。

## IEC104

- 连接并收到 STARTDT 确认后发一次总召唤，之后每 `interrogationIntervalMs` 一次（默认 15 min，0 表示仅连接后一次）。跟踪 `C_IC_NA_1` 的 ACT_CON（COT 7）/ACT_TERM（COT 10）；否定确认或 COT 44–47 结束该次总召唤。
- 未收到 ACT_TERM 的总召唤/电度召唤不重发：至少等待 `max(周期, 5 min)`，届时记录告警后再发下一次。
- 总召唤结束后发电度召唤 `C_CI_NA_1`（`counterInterrogation=true`，默认开启；QCC=`counterInterrogationQualifier`，默认 5＝总请求、不冻结不复位），之后每 `counterInterrogationIntervalMs` 一次（默认 15 min，0 表示仅连接后一次）。
- 收到 I 帧时校验 N(S)=V(R)：丢帧（跳号）或重复帧都按协议错误断链重连；N(R) 越界同样断链。
- STARTDT 在 t1 内未确认即断链；APCI 长度必须为 4..253，起始字节或长度错误即断链。
- 对时 `C_CS_NA_1` 发出后在 t1 内等待 ACT_CON，否定或超时都报错（`clockSyncIntervalSec>0` 时由驱动主循环按单调时钟周期调用）。

### 遥控/设点

- 命令类型：45 单命令、46 双命令、47 步调节、48/49/50 设点（归一化/标度化/短浮点）、51 32 位位串；58–64 为对应带 CP56Time2a 时标的类型。未配 `write.iec.typeId` 时由 `write.dataType` 推导（`single_command`→45、`double_command`→46、`regulating_step_command`→47、`setpoint_normalized`→48、`setpoint_float`/`float32`→50、`bitstring_command`→51，其余→49）。
- 确认按**命令类型**、命令 IOA 和公共地址过滤，从不使用读点的 typeId。
- 双命令 DCS、步调节 RCS 只允许 1/2，0/3 在发送前拒绝。
- COT 44–47（未知类型/传送原因/公共地址/信息对象地址）或 P/N=1 的确认判为确定失败。
- 选择-执行：选择被否定→失败；选择超时、执行被否定或执行超时时补发撤销（S/E=1，COT 8）。
- 执行帧已交给套接字但没有确认（或激活终止超时/否定）时，`CommandResult.outcomeUnknown=true`：装置可能已动作，上层不得换新 cmdId 重试。执行帧未发出（窗口/连接失败）时为确定失败。

## 解码、质量与时标

- 点位 `typeId` 按类型族匹配，配置不带时标的类型也接收自发上送的带时标类型：1/2/30、3/4/31、5/6/32、7/8/33、9/10/34/21、11/12/35、13/14/36、15/16/37、17/38、18/39、19/40。IEC103 点 `typeId=44` 接收 ASDU 1/2/44，`typeId=1/2` 互相匹配。
- 类型 20（`M_PS_NA_1`）每个信息体 5 字节（SCD+QDS），展开为 16 个状态位，用 `read.iec.elementIndex`（0..15）选位。
- 类型 7/8/33 位串按无符号 32 位解。
- 保护事件：17/38 解 SEP（ES）与 CP16 动作时间；18/39 解 SPE、QDP 与继电器持续时间；19/40 解 OCI、QDP 与继电器动作时间；时标按 CP24/CP56 解。
- 质量模型为二值（`quality` 1 好 / 0 坏，`qualityMsg` 写明原因）：IV、NT、BL、SB、OV（QDS 溢出）、双点 DPI 0/3、计数量 IV/CY、IEC103 MEA OV/ER 都置坏；BL/SB 也置坏，因为封锁值/人工替代值不是当前实测值。
- 带时标的帧（CP56Time2a、CP24Time2a、IEC103 CP32Time2a）以设备时标作为点时间；时标 IV=1 时用接收时间。点值过期仍按接收时间计算。
- 时标所在时区由 `timestampZone` 决定（104、101、103/AM5SE 共用）：`local`（默认）按网关本地时区，`utc` 按 UTC。解码和发出的时标（104 对时 `C_CS_NA_1`、带时标命令、AM5SE 在线/校时广播）都用同一设置。
- SU（夏令时）位：`local` 下 CP56Time2a 按 IEC 60870-5-4 处理，SU=1 取夏令时、SU=0 取标准时，用来区分夏令时结束时重复的那一小时；网关时区没有夏令时或 SU 与日期矛盾时，按时区自身规则换算。发出的时标在本地夏令时期间置 SU。`utc` 下没有夏令时，SU 忽略、发出时不置。CP24Time2a/CP32Time2a 没有日期，按当前时间推算，其 SU 位不参与换算。
- 测试帧（COT T=1，IEC103 COT 7 测试模式）不更新生产点。
- 双点（104 类型 3/4/31、IEC103 ASDU 1/2 的 DPI）映射到 `bool`/`single_point` 点时：1→0（分），2→1（合），0/3→保留旧值、质量置坏；`double_point` 点保留原始 DPI 0..3。IEC101/104 的 DIQ 由标准定义此含义；IEC103/AM5SE 变位帧见下文说明，该映射未经固件验证。

### IEC103 ASDU

| ASDU | 解析 |
| --- | --- |
| 1 / 2 | 带时标报文：FUN、INF、DPI、CP32Time2a、SIN（ASDU 2 另含 RET/FAN） |
| 3 / 9 | 被测值 I / II：MEA 为 13 位补码（÷4096，标幺到额定值的 1.2 或 2.4 倍），OV/ER 置坏；ASDU 9 个数取 VSQ，ASDU 3 取帧长；`elementIndex` 选第几个被测值 |
| 4 | 故障测距（R32.23）+ CP32Time2a |
| 10 | AM5SE 通用分类数据：组 0 条目 n 映射为 INF 139+n |
| 44 | AM5SE 遥信块：每块 16 位 |
| 8 | 总召唤结束（不产生点值） |

## 配置

协议级字段 `protocol.iec`：

| 字段 | 说明 |
| --- | --- |
| `transportMode` | `iec104`：`tcp`；`iec101`：`serial`；IEC103：`serial`/`tcp`；安科瑞装置：`am5se_active_tcp`（装置为 TCP Server）或 `am5se_passive_tcp`（装置反连） |

| `linkAddress` / `linkAddressSize` | FT1.2 链路地址；非平衡方式 IEC101 地址 1–2 字节，IEC103 1 字节；广播地址不可用 |

| `maxPollFrames` | IEC104 一次最多处理帧数；FT1.2 一个周期最多请求/应答次数 |
| `backgroundReceive` / `sendSFrameAck` | IEC104 后台接收、S 帧确认，默认 true |
| `t0Ms`/`t1Ms`/`t2Ms`/`t3Ms`/`kWindow`/`wAck` | IEC104 定时器与窗口；STARTDT 确认、对时确认按 t1 监视；AM5SE 反连等待按 t0 |

### 加载时校验

`src/validation/iec_validation.cpp` 在加载时拒绝必然不能工作或会静默出错的定义（报错中带点位与字段名）：协议类型与 `transportMode` 不匹配、IEC101 走 TCP、`balanced=true`、IEC104 字段长度不是 2/2/3、IEC101 字段长度越界、IEC103 链路地址不是 1 字节、链路地址为广播地址、公共地址/IOA 超出字段长度、QOI 不在 20..36、QCC 的 RQT 不在 1..5、不支持的监视类型、IEC101/104 点没有 IOA、IEC103 点缺 FUN/INF、`elementIndex` 用在不支持的类型上、非 IEC104 配置写点、不支持的命令类型、位串命令配置选择-执行、限定词越出 QU/QL 位、单命令 `allowedValues` 不是 0/1、双命令/步调节 `allowedValues` 不是 1/2、`am5se_active_tcp` 缺 `tcp.host/port`、`timestampZone` 不是 `local`/`utc`。总召唤周期小于 1 分钟、命令 IOA 为 0 只告警。

## AM5SE IEC103 网口与录波

AM5/AM5SE 网口有两种互斥连接模式，必须按装置网络菜单选择：

- 装置显示 TCP `Server`：`am5se_active_tcp`，`IecDriver` 主动连接 `protocol.tcp.host:port`。
- 装置主动连接边端：`am5se_passive_tcp`，`IecDriver` 监听 `listenPort`（默认 1048），未连接时向装置 UDP `1032` 发送 41 字节在线/校时报文，装置据此反连。

连接后与通用 IEC103 完全相同：链路复位、总召唤、二级数据轮询、按 ACD 请求一级数据；链路超时复位后重新总召唤。每类应答只更新本帧实际携带的点，其他点保留到 TTL 超时。

点位使用 `FUN/INF` 匹配。AM5SE 模板要求点位 `address=0`，遥信配置 `typeId=44`（同时接收变位 ASDU 1/2），遥测配置 `typeId=10`。同一 INF 可分别出现在遥信和遥测中，不能只按 INF 去重。

变位帧 DPI 的实际含义仍需厂家确认，或对照原始报文与现场分合状态验证。当前 1→分、2→合、0/3→坏质量 是代码采用的映射，不能视为该固件已验证结论。DPI 八位组第 3..8 位为 IEC 60870-5-103 备用位，不为 0 时同样按坏质量处理并保留旧值。

遥信点值保留诊断：`rawHex` 为整个 ASDU，`qualityMsg` 为坏质量原因，`text` 在解释结果后附 `[iec103 asdu=… cot=… ca=… fun=… inf=… dpiOctet=…|block=… bitIndex=… status=… change=… qds=… value=… quality=… mapping=… verified=false]`，可区分 ASDU 1/2 变位帧、COT 9 总召应答和 ASDU44 快照。共享内存只保存值、质量和时间，这些文字只在采集结果和调试日志中。

现场对照方法：
- 设置环境变量 `GATEWAY_IEC103_DEBUG=1`（例如 `systemctl edit iec-driver@<配置文件名>.service` 加 `Environment=GATEWAY_IEC103_DEBUG=1`，默认关闭；需重启驱动，只在获准的维护窗口进行）后，驱动对每个 ASDU 1/2 变位帧向标准错误（journal）输出一行：COT、FUN、INF、DPI 与 DPI 原始八位组、CP32Time2a 字段（时:分:秒.毫秒、IV、SU）、换算后的时间和整帧原始字节；并对匹配到点位的每个 ASDU 1/2 值及状态/质量变化的 ASDU44 值输出一行 `IEC103 point …` 诊断。对照装置实际分合位置记录才能确认 DPI 含义。
- 原始收发字节也可用通道报文监测抓取（见 `doc/配置与消息/通道报文监测接口.txt`），不需重启驱动。
- 证据现状、只读验证步骤和“映射已确认”所需记录见 [安科瑞AM5-IEC103主动TCP现场验证.md](安科瑞AM5-IEC103主动TCP现场验证.md#变位-dpi-证据与只读验证)。

录波：

- ASDU24 请求、ASDU23 返回录波目录；ASDU68 请求 CFG（`0x51`）或 DAT（`0x52`）；ASDU80 分包，校验包号连续、重复包、结束标志和文件大小，以临时文件写完后改名落盘。
- 录波传输占用链路期间，一级应答里的其他 ASDU（跳闸、告警等事件）缓存下来，按正常事件经 `drainBufferedValues()` 发布；传输中每秒插一次二级数据请求，遥测继续更新；采集周期的 `poll()` 不等待传输，直接返回。
- 录波命令通过常驻驱动的本地 Unix Socket 执行（见 [IEC103录波文件上送平台设计.md](IEC103录波文件上送平台设计.md)），主动、被动两种模式都支持平台录波任务。

独立诊断命令（会与常驻驱动争用同一装置会话，执行前先停止对应的 `iec-driver@*.service`）：

```bash
IecDriver --config config/runtime/devices/device_am5se_t.json --list-recordings
IecDriver --config config/runtime/devices/device_am5se_t.json \
  --pull-recording 15 --recording-output /opt/modbus-gateway/data/iec103-recordings
```

AM5/AM5SE 专用范围只包括网口遥信、遥测和 CFG/DAT 录波，不包含串口、遥控、参数/定值读写。每个配置实例只管理一个装置连接。

## 仍需现场确认的边界

- AM5SE 变位帧 DPI 的实际含义仍需厂家确认，或对照原始报文与现场分合状态验证；当前 1→分、2→合、0/3→坏质量 是代码采用的映射，不能视为该固件已验证结论。
- AM5 装置对空的一级/二级数据请求的应答功能码（FC9、E5 还是 FC0）；确认后删除 FT1.2 主站的 FC0 兼容分支（见“链路规则”）。
- 不同厂家对控制确认、激活终止、限定词扩展可能不同，需要按现场规约表配置点位。
- 电度召唤默认开启；不支持 `C_CI_NA_1` 的子站应回 COT 44，驱动只记录告警。个别子站若对未知类型断链，需关闭 `counterInterrogation`。
- 文件传输提供片段级 API（`IecFileSegment`）；落盘、续传和文件名策略由上层决定。
- 参数/定值读写提供通用 IEC104 API；定值区号、参数限定词和激活流程按规约表配置。
- 子站时标所在时区（本地或 UTC）需与现场约定，并相应设置 `timestampZone`。

## 部署

`gateway-services.sh` 扫描运行时设备配置中的 `protocol.type=iec104/iec101/iec103/iec103_tcp/iec103_serial`。只有被 `mqtt-service.json` 或 `monitor-service.json` 的 `deviceConfigFiles[]` 引用且 `enabled=true` 的 IEC 配置会启动 `iec-driver@<配置文件名>.service`。
