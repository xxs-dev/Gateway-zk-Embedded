# COMM202600103 PCS V126 协议替换映射报告

本文记录 `COMM202600103` 的 PCS 从旧协议迁移到盛弘 `PWS1-125K-One V126` 的配置、EMS 兼容关系和现场验证结果。项目配置样例见 `config/examples/device_comm202600103_pcs_pws1_125k_one_v126.json`。

协议来源：`125M-储能平台监控与后台通讯MODBUS协议V126(1)(1).xlsx`。生成时只选取 `PWS1-125K-One / Bus:Battery / Dc:Battery` 对应列，其他机型列不得混入该项目点表。

## 结论

- 型号筛选：PWS1-125K-One / Bus:Battery / Dc:Battery。
- 串口保持：/dev/ttySP4，19200 8N1，从站地址 1。
- 新协议读区和读写区均使用 0x03；单寄存器写入使用 0x06。
- 新协议数值/位域点：331 个；兼容点：10 个；总点数（含在线点）：342 个。
- 新增点 index 从 20000 到 20265，已避开当前工程其他设备 index。
- 旧 1279 的厂家专用 BMS/CMS 状态字在新协议中不存在。循环策略已改为直接检查 BMS 最大充/放电电流（1556/1557）是否大于 0。

- 安全检查：PCS 通讯状态 `1399=0`，PCS 关键读点质量为坏，写队列 `pending_count=0`；离线时未产生启停或功率写入。

## 当前现场阻塞

`/dev/ttySP4` 当前映射到 `/dev/ttyAS7`，由且仅由 PCS Modbus 进程占用。已验证 `19200 8N1`、`9600 8N1`、地址 `1-16` 以及地址 `32`，所有请求均为 `modbus response timeout`，未收到 Modbus 异常帧或有效响应。旧协议在替换前也全量超时，因此当前问题不属于 V126 JSON 加载或寄存器解析失败。

现场应按以下顺序确认：

1. PCS 的 RS485 后台通讯口是否已启用，且实际接在 SP4。
2. A/B 线序、屏蔽和共地是否正确。
3. PCS 实际从站地址与波特率是否和配置一致。
4. 现场是否改用 PCS 网口 Modbus TCP；若是，应新建 TCP 通道，不能继续轮询 SP4。

在收到稳定真实读数前，禁止主动执行启动、停机、故障复位和功率写入。链路恢复后至少验证 `1211-1216`、`1220-1245`、`1318-1323` 的数值、符号、缩放和写后反馈。

## EMS 兼容约束

- 新协议有功功率正值表示充电，负值表示放电，和当前循环策略一致。
- `1214` 取自寄存器 `1211` 的控制模式；厂家值 `2=远程` 经缩放后输出业务值 `1`，继续满足旧 EMS 远程许可判断。
- 旧 `1279` 无等价协议字段，不得用相似状态字硬代替。充电许可改为 `1556 > 0`，放电许可改为 `1557 > 0`。
- `1399` 是驱动通讯状态，不是 PCS 原始寄存器；离线时必须作为控制安全门的一部分。
