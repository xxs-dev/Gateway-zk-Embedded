# 边端数据模拟与硬件在环测试

## 1. 目标与边界

测试实验室用于在没有真实从站、需要稳定复现故障或准备批量回归时，验证以下真实链路：

```text
协议模拟设备
  -> 真实采集驱动
  -> 独立共享内存
  -> ComputeEngine / EventEngine
  -> MqttDriver / SystemMonitor
  -> Windows 客户端实时监控与写入
```

测试必须从协议端产生数据。直接向共享内存注入值只能测试后半段，不能替代串口、CAN、TCP、帧解析、超时、重试、退避和写后校验测试。

当前覆盖：

| 协议/模块 | 纯软件模式 | 硬件在环模式 | 故障注入 |
| --- | --- | --- | --- |
| Modbus TCP | 支持 | 物理网口 | 超时、断连、异常、写超时、写后校验失败 |
| Modbus RTU | Linux PTY | USB-RS485 | 同上 |
| DL/T 645-2007 | Linux PTY | USB-RS485 | 同上 |
| CAN | UDP 双向虚拟总线 | USB-CAN，需适配器厂商工具 | 停帧、断连语义、写帧 |
| 本机 DIDO | 伪 sysfs GPIO | 真实 DI/DO 工装 | 文件失效、输入切换 |
| IEC104 | TCP 常驻模拟站 | 物理网口 | 超时、断连 |
| Compute/Event/MQTT | 默认随实验室启动 | 同左 | 源点故障会向后传播 |

IEC103 串口、AM5SE IEC103 网口录波和 IEC104 文件传输尚未纳入常驻实验室，继续使用现有协议集成测试验证。

## 2. 运行模式

### 2.1 纯软件模式 `virtual`

模拟器和真实驱动运行在同一台 Linux 主机：

- Modbus TCP、IEC104 使用回环 TCP。
- Modbus RTU、DL/T 645 自动创建 PTY，驱动打开 PTY 从端。
- CAN 使用测试专用 UDP 双向虚拟总线，不依赖内核 `vcan`。
- DIDO 使用测试目录中的伪 sysfs 文件。

适用于自动回归、退避验证、写回验证和 Win 客户端联调。

### 2.2 硬件在环模式 `hil`

模拟器运行在 Windows 测试机或协议测试仪，边端运行真实驱动并使用真实接口。

| 协议 | Windows 侧 | 边端侧 | 必查参数 |
| --- | --- | --- | --- |
| Modbus TCP、IEC104 | 物理网口 | `ens0` 至 `ens3` | IP、端口、防火墙 |
| Modbus RTU | USB-RS485 | `/dev/ttySPx` | 波特率、8N1、A/B 线、终端电阻 |
| DL/T 645 | USB-RS485 | `/dev/ttySPx` | 2400、8E1、表地址、A/B 线 |
| CAN | USB-CAN | `can0` 或 `can1` | 500 kbit/s、H/L 线、两端 120 欧姆 |
| DIDO | GPIO/继电器工装 | 真实 DI/DO | 干/湿接点、电平、公共端、取反 |

Windows USB-CAN 没有统一系统 API，`gateway-test-lab-sim.exe` 不直接支持厂商私有驱动。应使用适配器自带工具发送本文定义的测试帧，或使用支持 SocketCAN 的 Linux 测试机。

## 3. 强制隔离

| 项目 | 测试值 |
| --- | --- |
| machineCode | `SIM_COMM202600999` |
| 根目录 | `/opt/modbus-gateway/test-lab` |
| SystemMonitor | `19443` |
| Modbus TCP | `15020` |
| IEC104 | 启动参数指定，示例 `12404` |
| 共享内存 | `gateway_test_lab_*` |
| MQTT | 默认禁网，仅输出日志；可显式指定测试 broker |

测试实验室不加入 systemd、不自动启动、不进入出厂初始化包、不使用正式 machineCode。

停止操作只处理 PID 文件指向且命令行包含测试根目录的进程。CAN 接口仅在脚本自己创建时删除，已有实体接口不会被删除。

## 4. 组成

### 4.1 模拟器

`gateway-test-lab-sim` 支持：

- `serve`：Modbus TCP。
- `serve-serial --protocol modbus-rtu`：Modbus RTU。
- `serve-serial --protocol dlt645`：DL/T 645-2007。
- `serve-can`：SocketCAN 周期发帧和写帧接收。
- `serve-can --transport udp_test`：跨 Windows/Linux 的 UDP 虚拟 CAN，保留 CAN ID、扩展帧、RTR、FD 和原始 payload。
- `serve-iec104`：启动链路、总召、遥信、遥测、遥控和时钟同步。
- `normal/ramp/random/boundary` 四种数据场景。
- 25ms 状态文件热加载。

Modbus 支持功能码 `01、02、03、04、05、06、0F、10`。DL/T 645 支持常用电能、电压、电流、功率 DI 读取和写入回读。

### 4.2 默认服务栈

`gateway-test-lab start` 启动：

1. 所选协议模拟器，DIDO 不需要常驻模拟进程。
2. 对应真实采集驱动。
3. `ComputeEngine`，生成 `SIM_COMPUTE_DOUBLE` 派生点。
4. `EventEngine`，扫描变位和告警。
5. `MqttDriver`，默认使用 stdout 发布器，每秒生成全量报文。
6. 独立 `SystemMonitor`，供 Win 客户端直连。

计算点有独立的 `device_compute.json` 元数据配置，确保 ComputeEngine、MqttDriver、SystemMonitor 三个进程对派生 `index` 的解释一致。

## 5. 构建与安装

### 5.1 Linux 本机

```bash
cmake -S . -B build-wsl-native -DCMAKE_BUILD_TYPE=Debug -DBUILD_TESTING=ON
cmake --build build-wsl-native -j4
ctest --test-dir build-wsl-native -R gateway_test_lab --output-on-failure
```

### 5.2 Allwinner AArch64

在 `192.168.22.11` 的独立源码目录中构建，不能覆盖正式构建目录：

```bash
tools/build_edge_aarch64.sh \
  GatewayTestLabSim ModbusRtu Dlt645Driver CanDriver DioDriver IecDriver \
  ComputeEngine EventEngine MqttDriver SystemMonitor
```

安装不会启动服务：

```bash
test-lab/scripts/install-gateway-test-lab.sh \
  --sim-bin build-aarch64-cross/gateway-test-lab-sim \
  --gateway-bin-dir build-aarch64-cross \
  --link-command
```

`--gateway-bin-dir` 会把本次构建的采集驱动、ComputeEngine、EventEngine、
MqttDriver 和 SystemMonitor 一并复制到 `test-lab/bin`。安装态启动脚本优先使用该
目录，不能借用或替换正式 `/opt/modbus-gateway/bin` 中的程序。

### 5.3 Windows 包

```powershell
./test-lab/scripts/package-windows-simulator.ps1
./test-lab/tests/run-windows-simulator-smoke.ps1
```

输出目录包含 exe、PowerShell 控制脚本、MinGW 运行库和 SHA256 清单。
冒烟脚本会校验清单，并验证 Modbus TCP 读取、数值覆盖、异常恢复，以及虚拟 CAN 双向帧传输。

## 6. 纯软件操作

一次只运行一种采集协议，便于观察该链路的退避和恢复。

```bash
# Modbus TCP
gateway-test-lab start normal --protocol modbus-tcp

# Modbus RTU，自动创建 PTY
gateway-test-lab start normal --protocol modbus-rtu

# DL/T 645，自动创建 PTY
gateway-test-lab start normal --protocol dlt645

# DIDO 伪 sysfs
gateway-test-lab start normal --protocol dio

# IEC104
gateway-test-lab start normal --protocol iec104 --port 12404

# CAN，默认使用 19011/19012 两个本机 UDP 端口，不依赖 vcan
gateway-test-lab start ramp --protocol can
```

通用操作：

```bash
gateway-test-lab status
gateway-test-lab scenario ramp
gateway-test-lab stop
```

故障与恢复：

```bash
gateway-test-lab fault modbus.slave2 timeout
gateway-test-lab recover modbus.slave2

gateway-test-lab fault dlt645.meter2 exception
gateway-test-lab recover dlt645.meter2

gateway-test-lab fault can.device1 timeout
gateway-test-lab recover can.device1

gateway-test-lab fault iec104.station1 disconnect
gateway-test-lab recover iec104.station1

gateway-test-lab fault dio.gpio101 timeout
gateway-test-lab recover dio.gpio101
```

固定值：

```bash
gateway-test-lab set-value modbus.slave1 holding 10 4321
gateway-test-lab set-value dio.gpio101 1
```

连接独立测试 MQTT broker：

```bash
gateway-test-lab start normal --protocol modbus-tcp \
  --mqtt-broker tcp://192.168.22.30:1883
```

即使启用 broker，topic 仍使用测试 machineCode `SIM_COMM202600999`。

## 7. Windows 硬件在环

### 7.1 网络协议

```powershell
./Gateway-TestLabSimulator.ps1 -Action Start -Protocol ModbusTcp `
  -ListenAddress 0.0.0.0 -Port 15020
```

边端：

```bash
gateway-test-lab start normal --protocol modbus-tcp --mode hil \
  --host 192.168.22.23 --port 15020
```

### 7.2 Modbus RTU

Windows 两个 USB-RS485 适配器交叉连接，或 Windows 适配器与边端 RS485 端口连接：

```powershell
./Gateway-TestLabSimulator.ps1 -Action Start -Protocol ModbusRtu `
  -SerialDevice COM6 -BaudRate 9600 -Parity N
```

边端：

```bash
gateway-test-lab start normal --protocol modbus-rtu --mode hil \
  --serial-device /dev/ttySP1
```

### 7.3 DL/T 645

```powershell
./Gateway-TestLabSimulator.ps1 -Action Start -Protocol Dlt645 `
  -SerialDevice COM6 -BaudRate 2400 -Parity E
```

边端：

```bash
gateway-test-lab start normal --protocol dlt645 --mode hil \
  --serial-device /dev/ttySP1
```

RS485 接线必须共地并确认 A/B 定义；不同厂商对 A/B 命名可能相反。只有总线两端加 120 欧姆终端电阻，不要在每台设备重复并联。

### 7.4 CAN

纯软件模式默认在边端内部运行 UDP 虚拟 CAN，不使用任何实体 CAN 口：

```bash
gateway-test-lab start ramp --protocol can
```

也可让 Windows 运行模拟器、边端运行真实 CanDriver。假设 Windows 为 `192.168.22.23`：

```powershell
./Gateway-TestLabSimulator.ps1 -Action Start -Protocol CanUdp `
  -ListenAddress 0.0.0.0 -Port 19012 `
  -CanPeerAddress 192.168.22.16 -CanPeerPort 19011
```

边端测试配置需要把 `udpBindAddress` 设为边端地址、`udpPeerAddress` 设为 Windows 地址。
这种方式验证跨主机帧传输，但不验证实体 CAN 控制器和收发器。实体接口验收仍需 USB-CAN，
并检查波特率、CANH/CANL、共地和两端 120 欧姆终端电阻。

## 8. Windows 客户端观察

新版 Windows 客户端选择直连：

```text
直连地址：http://192.168.22.16:19443
machineCode：SIM_COMM202600999
维护密码：客户端内置 Kydl2026，无需再次输入
```

操作顺序：

1. 选择“直连”并连接测试地址。
2. 从主页面选择“拉取工程”，保存为独立模拟工程。
3. 打开“实时监控”，选择 `SIM_CAN_01` 或当前协议的 `SIM_*` 设备。
4. 正常状态查看值、质量和时间；注入故障后刷新页面，质量应变为 `0`。
5. 可写点使用右键写入，返回结果应包含阶段、排队、设备写入和总耗时。

不打开 Windows 客户端也可直接查看 JSON：

```powershell
Invoke-RestMethod http://192.168.22.16:19443/api/v1/health
Invoke-RestMethod http://192.168.22.16:19443/api/v1/realtime/points |
  ConvertTo-Json -Depth 8
```

持续刷新表格：

```powershell
./test-lab/scripts/Show-GatewayTestLabResults.ps1 -Watch
```

筛选设备或点位：

```powershell
./test-lab/scripts/Show-GatewayTestLabResults.ps1 -Watch -MeterCode SIM_CAN_01
./test-lab/scripts/Show-GatewayTestLabResults.ps1 -PointCode TEMPERATURE
```

边端命令行查看模拟器收发帧数和故障状态：

```bash
gateway-test-lab status
```

## 9. 自动验收

```bash
ctest --test-dir build-wsl-native -R gateway_test_lab --output-on-failure
```

测试覆盖：

- Modbus TCP、RTU 读写、异常和恢复。
- DL/T 645 读取、写入回读、异常和恢复。
- DIDO 输入切换。
- UDP 虚拟 CAN 遥测、停帧故障、恢复和写帧回传。
- IEC104 周期数据和 select/execute 遥控。
- Compute 派生点跨进程可见。
- MqttDriver 全量报文生成。
- SystemMonitor 健康、实时点和工程拉取。
- 停止后的进程、共享内存和测试接口清理。

自动 CAN e2e 不依赖 `CAP_NET_ADMIN` 或 `vcan`，普通 Linux 用户即可运行。UDP 虚拟 CAN
只用于软件测试，不能替代实体 CAN 控制器、电气接线和抗干扰验收。

## 10. 验收判定

1. 正常场景全部采集点为 `quality=1`。
2. 单设备故障不能阻塞同链路其他设备。
3. 恢复后在配置的探测轮次内恢复好质量。
4. 可写点只在写权限开启时执行，写后校验结果明确。
5. `SIM_COMPUTE_DOUBLE` 等于所选源点的两倍且质量随源点传播。
6. MqttDriver 日志每秒出现测试 machineCode 的全量快照。
7. Win 实时监控可看到配置点、实时值、质量和中文名称。
8. `stop` 后没有测试进程、UDP 监听端口和 `gateway_test_lab_*` 共享内存残留。
