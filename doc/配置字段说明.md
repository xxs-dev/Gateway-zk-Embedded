
# Config 说明

本文档专门说明 `config/` 目录下各类配置文件的用途，以及主要字段的含义。

## 文件分类

当前 `config/` 目录建议按两类区分：

- 运行时依赖配置
  - `config/runtime/devices/*.json`
  - `config/runtime/apps/*.json`
- 报文与日志样例
  - `config/samples/messages/*.json`
  - `config/samples/logs/*.log`

当前已整理为：

- 设备采集配置
  - `config/runtime/devices/device_slave_ttySP1.json`
  - `config/runtime/devices/device_slave_ttySP2.json`
  - `config/runtime/devices/device_alarm_multi_slave_tcp_1_2.json`
  - `config/runtime/devices/device_dlt645_multi_meter_1_2.json`
- MQTT 驱动 / 应用配置
  - `config/runtime/apps/mqtt-service.json`
  - `config/runtime/apps/monitor-service.json`
  - `config/runtime/apps/camera-service.json`
- MQTT 消息样例
  - `config/samples/messages/mqtt_command_request_example.json`
  - `config/samples/messages/mqtt_telemetry_chunk_example.json`
  - `config/samples/messages/mqtt_ota_request_example.json`

## 1. 设备采集配置

设备配置文件负责定义：

- 协议类型
- 通信参数
- 采集周期
- 共享内存参数
- SQLite 参数
- 从站列表
- 点位读写能力
- 点位告警规则

### 顶层字段

#### `schemaVersion`

配置版本号，用于后续配置演进兼容。

#### `machineCode`

网关编码。  
同一边端实例建议唯一。

#### `protocol`

协议定义。

字段：

- `type`
  - `modbus_rtu`、`modbus_tcp`、`dlt645_2007` 或 `local_dio`
- `slave`
  - 默认从站地址
  - 多从站模式下可被 `devices[].slave` 覆盖
- `transport`
  - RTU 串口参数，见下文 `protocol.transport`
- `tcp`
  - TCP 连接参数，见下文 `protocol.tcp`
- `backend`
  - `local_dio` 使用的硬件访问后端，当前为 `sysfs_gpio`
- `gpioBasePath`
  - `local_dio` 的 GPIO sysfs 根路径，默认 `/sys/class/gpio`

##### `protocol.transport`（Modbus RTU）

- `serialPort`、`baudRate`（1200–115200）、`dataBits`、`stopBits`、`parity`（`N`/`E`/`O`）
  - 有校验位时驱动开启接收奇偶校验，出错字节被丢弃，帧随后因长度/CRC 不符被拒收
- `timeoutMs`
  - 等待应答的时长。超时后驱动再静听最多一个 `timeoutMs`：迟到的完整应答仍算本次请求的应答，其余字节丢弃，然后才发下一帧。RTU 没有事务号，否则迟到应答会被当成下一帧（同从站、同功能码、同寄存器数）的应答
  - 因此无应答从站每次尝试最多占用总线 2×`timeoutMs`
- `frameIntervalMs`
  - 同一从站两次请求开始之间的最小间隔，只约束该从站；等待期间驱动先服务同一串口上的其他从站，不阻塞总线
  - 总线上任意两帧之间另有 3.5 字符静默；波特率高于 19200 时按规范固定为 1.75 ms
- `readRetryCount`
  - 读请求失败后的重试次数；写请求从不自动重试
- `localEcho`
  - RS-485 适配器会把发送字节回显到接收端时设为 `true`
- 串口独占：驱动打开串口后加 `flock` 独占锁并设置 `TIOCEXCL`。两份配置或其他工具占用同一串口时，后打开者报 `serial device busy ... /dev/ttySPx`，不会互相覆盖串口参数
- `rs485`
  - 内核 RS-485 收发方向控制，默认关闭。示例：`{"enabled":false,"rtsOnSend":true,"rtsAfterSend":false,"delayRtsBeforeSendMs":0,"delayRtsAfterSendMs":0}`
  - 是否需要取决于现场硬件：收发器带自动方向切换时保持关闭；只有收发器方向由 UART 的 RTS 脚控制时才打开。出厂配置均为关闭，即沿用此前依赖硬件自动收发的行为
  - `enabled=false`：打开串口时不做任何 RS-485 ioctl，内核里该口原有的 RS-485 设置保持不变（之前打开过的口从 `true` 改成 `false` 不会把内核设置关掉，需要重启或由板级默认配置恢复）
  - `enabled=true`：打开串口后执行 `TIOCSRS485`，再用 `TIOCGRS485` 读回核对使能位、两个 RTS 电平和两个延时。驱动不支持（如 `Inappropriate ioctl for device`）或读回不一致时，打开失败，报错带设备路径和 errno，不降级为不控制方向
  - `rtsOnSend`/`rtsAfterSend`：发送中/发送后 RTS 电平（`true` 为高），两者必须不同
  - `delayRtsBeforeSendMs`/`delayRtsAfterSendMs`：发送前/后 RTS 保持时间，0–100 ms（内核上限）
  - 不认识的字段、越界值、两个 RTS 电平相同在加载配置时直接报错。Modbus RTU、DL/T 645、IEC 串口共用这一项

##### `protocol.tcp`（Modbus TCP）

- `host`、`port`、`connectTimeoutMs`、`timeoutMs`
- 某个请求超时后连接保留；之后收到的该请求的迟到应答按事务号识别并丢弃。只有连续 3 次请求都无应答、或数据流不完整/协议错误时才断开重连，所以经串口服务器挂多个单元号时，一个掉线单元不会拖垮其他单元

`local_dio` 是本机 DI/DO 独立协议，不使用串口或 TCP。只有设备文件被 `mqtt-service.json` 或 `monitor-service.json` 的 `deviceConfigFiles[]` 引用时，`gateway-services.sh` 才会启动 `dio-driver@<设备文件名>.service`。

#### `collect`

采集线程参数。

字段：

- `defaultIntervalMs`
  - 默认采集周期
- `batchOptimize`
  - 是否按连续地址合并读任务
- `maxBatchRegisters`
  - 单批最大寄存器数
- `offlineProbeOnly`
  - 设备或读任务确认失败后，只保留少量探测任务，健康任务继续正常采集
- `offlineProbeTaskCount`
  - 设备级离线探测时每轮最多执行的探测任务数
- `offlineProbeIntervalMs`
  - 已达到离线阈值的设备或读任务再次探测前的墙钟间隔
  - `0` 表示保持原有仅按轮次退避的行为；生产现场可设为 `30000`，即 30 秒
  - 只抑制已经确认失败的任务；成功任务会立即清除其失败状态，不影响短暂抖动后的恢复
- `maxGapRegisters`（Modbus，默认 `0`）
  - 一次请求最多跨过多少个未配置的寄存器把两个点合并读取。`0` 只合并相邻或重叠的点
  - 设备对空洞寄存器回异常码时，`adaptiveSplitOnFailure` 会把该块拆回逐点读取；不支持拆分时加载告警
- `maxTasksPerMeterPerCycle` / `realtimeMaxTasksPerMeterPerCycle`（Modbus）
  - 一个电表每轮最多发出的请求数，用完即让同一串口上的下一个电表；剩余的到期请求在下一轮立即继续，不再等待采集周期。它是公平份额，不是限速
  - `realtime...` 用于平台实时监测租约期间的被监测电表
- `backgroundTaskIntervalMs`（Modbus，默认 `5000`）
  - `collectPriority > 0` 的后台点只用串口的空闲时间：本电表的实时点（优先级 0）读完、且同一串口上其他在线电表也没有到期实时点时才读
  - 实时点持续占满串口时，每个电表仍保证每隔该时长读一次后台点（排在该轮最前），后台点不会被饿死。`0` 表示每轮都插入一次
  - 串口严重过载时这份保底会占用可观的总线时间（每表每 5 s 一次），需要更快的实时刷新时调大该值
- `runtimeMeterBatchSize`
  - 采集线程每批遍历的电表数；一批之后若还有电表未轮到，立即继续下一批，整轮结束后才休眠。休眠到最早一个电表可再发请求（点到期或从站 `frameIntervalMs` 结束）的时刻，该时刻按各电表自己那一轮结束时计算，不会因同一轮里后面电表的读取耗时而推迟
- `staleAfterIntervals` / `staleAfterMinMs`
  - 点值超过 `max(staleAfterIntervals × 点周期, staleAfterMinMs)` 未成功刷新即过期（读侧为 stale），且不超过 `cachePolicy.ttlMs`

Modbus 调度规则：

- 每个点按自己的 `read.intervalMs`（未配置时 `defaultIntervalMs`）到期，到期时刻是固定节拍：下次到期 = 本次所服务的到期时刻 + 周期，与读取耗时无关，周期不会被读取时间拉长
- 落后不足一个周期时，错过的那个节拍随即补读一次，之后回到原节拍；落后超过一个周期时（总线过载、设备超时、时钟前跳），读一次后对齐到下一个未来节拍，错过的节拍不补读，不会出现集中补读
- 系统时间后跳时，所有节拍随时钟一起平移，下次读取仍在原间隔之后
- 到期点按功能码和地址合并成请求（不超过 `maxBatchRegisters`，跨空洞见 `maxGapRegisters`）。实时点与后台点分别成块，后台寄存器不会加宽每一次实时读取；同一轮里两者都要读且地址相邻时合并成一次请求
- 请求顺序：先实时（`collectPriority` 0），再按 `collectPriority` 从小到大；同一优先级内按紧迫度（上次读取完成 + 周期）早的先读，相同时点值更旧的先读。到期判断用固定节拍，争用时排序用实际完成时间，过载时不会因节拍相位相同而总偏向同一批点
- 同一串口上的电表之间同样按紧迫度：另一个电表的实时点更逾期、且其从站此刻可以发请求时，本电表让出本轮。因此配置 500 ms 的点比配置 1000 ms 的点优先，不再因为点数多而刷新更慢（平台实时监测租约中的电表不让出）
- 加载配置时按波特率估算总线负载（假定设备 20 ms 应答），所需时间超过 100%，或某从站请求数超过 `frameIntervalMs` 允许的次数时打印 `config warning`。这时实际刷新必然慢于配置，点值会按 stale 规则如实变为过期

#### `memoryStore`

共享内存和本地缓存参数。

字段：

- `enabled`
  - 是否启用内存存储
- `backend`
  - 当前主要是 `memory`
- `keepHistory`
  - 历史条数逻辑参数
- `defaultTtlMs`
  - 默认缓存有效期
- `indexBy`
  - 逻辑索引键
- `sharedMemoryName`
  - 共享内存段名称；生产默认统一为 `gateway_point_store`
- `maxLatestPoints`
  - latest 点位逻辑上限；运行时会在编译期物理容量内按配置值限制
- `maxPendingWrites`
  - 待写命令逻辑上限；队列满时会拒绝新写命令，不再静默覆盖旧命令
- `pendingWriteMaxAgeMs`
  - 待写命令最长排队时间（0–86400000，默认 10000，0 表示不过期）。超过后不再下发，回执 `stage=expired`
  - 排队时长按单调时钟计算：命令入队时由提交进程写入 `CLOCK_MONOTONIC` 时间戳，执行前用同一时钟判断，系统时间前跳或后跳（NTP 校时、手工改时间）既不会让新命令误过期，也不会让过期命令“复活”
  - 没有单调时间戳的命令（升级窗口内由旧版本进程入队）一律按过期处理，不下发
- `maxPersistentSamples`
  - 待落盘采样逻辑上限
- `sqlitePath`
  - 点位分钟存盘 SQLite 路径
- `sqliteLibraryPath`
  - SQLite 动态库路径
- `persistFlushIntervalMs`
  - 采样落盘周期
- `writebackIntervalMs`
  - 写回线程消费周期
- `writebackBatchSize`
  - 单次写回最多消费多少条命令

#### `devices`

多从站设备列表。

每个元素表示一个逻辑设备，字段：

- `meterCode`
  - 设备编码
- `deviceName`
  - 设备名称
- `slave`
  - 对应 RTU slave / TCP unit id
- `points`
  - 点位列表

补充说明：

- 设备采集配置里的逻辑设备分组字段统一为 `meters`
- MQTT 上送的 grouped telemetry / snapshot 消息体分组字段也是 `meters`
- 配置结构和消息结构字段已统一，平台侧不需要再区分 `devices` / `meters`

## 2. 点位字段

### 基础字段

- `index`
  - 共享内存主索引，必须全局唯一
- `pointCode`
  - 点位编码
- `name`
  - 点位名称
- `desc`
  - 说明
- `category`
  - 分类
- `address`
  - Modbus 寄存器地址
- `enabled`
  - 是否启用
- `isStore`
  - 是否按分钟本地存盘
- `reportOnChange`
  - 是否启用变位上传；为 `true` 时首次扫描只建立基线，后续仅在数值真正变化时发送单条 `change` 事件到 `mqtt.changeEventTopic`，不因 `ts / expireAt` 刷新重复上传
- `persistIntervalSec`
  - 本地采样存盘周期
- `initialValue`
  - 仅用于 `protocol.type=ems_virtual` 的虚拟点。共享内存和保持文件都没有有效值时，以该值建立质量为 `1`、不过期的首次运行值，避免策略使能、状态反馈和必要运行参数显示“数据不可用”
  - 物理 Modbus、CAN、DL/T 645、IEC 等采集点不会使用该字段恢复数据，不能用初值掩盖真实通讯异常
- `retain`
  - 仅用于 `protocol.type=ems_virtual`。为 `true` 时，点值原子写入 `/opt/modbus-gateway/data/ems-virtual-parameters/<index>.value`，服务或设备重启后优先恢复最后保存值
  - 策略使能、模式、操作参数和状态反馈应同时配置明确的 `initialValue` 与 `retain=true`；所有保持点都必须有首启值
  - Graph 计算遥测通常只配置 `initialValue`，由 `graphStateFile` 保存计算状态，避免同一状态被两套文件重复管理
  - 直接写入操作参数时，保持文件落盘失败会拒绝本次写入；Graph 状态反馈落盘失败时保留共享内存实时值并记录错误，不中断策略计算

```json
{
  "index": 161,
  "pointCode": "ems_bms_soc_max",
  "category": "setting",
  "initialValue": 95.0,
  "retain": true
}
```
- `tags`
  - 系统自动生成标签，不在模板和导入表中手工填写
  - 当前生成规则：设备在线点生成 `status/online`，变位上传点生成 `change`，全量上传点生成 `full_upload`，配置告警规则生成 `alarm`，可写点生成 `writable`
  - 无以上属性时不输出 `tags` 字段，避免普通测点被误分类

### `read`

定义读能力。

字段：

- `enable`
  - 是否可读
- `function`
  - 读功能码，常见 `3/4`
- `length`
  - 寄存器长度
- `dataType`
  - Modbus 寄存器类型：`bit`、`bool`、`uint16`、`int16`、`uint32`、`int32`、`float32`、`uint64`、`int64`、`float64`；`read.length` 必须等于类型占用的寄存器数
  - 64 位整数换算为浮点，超过 2^53 时有精度损失
  - 本机 DI/DO 使用 `digital_input` 或 `digital_output`
  - 设备在线状态使用 `device_online`
- `scale`
  - 缩放系数
- `offset`
  - 偏移量
- `byteOrder`
  - 规范大端序第 i 个字节取线上的第几个字节（`ABCD` 大端、`CDAB` 低字在前、`BADC` 字内交换、`DCBA` 全小端）
  - 必须是该数据类型全部字节的一个排列：16 位 2 个字母、32 位 4 个、64 位 8 个，否则加载失败
  - 不配置时按类型取自然序：16 位 `AB`、32 位 `ABCD`、64 位 `ABCDEFGH`
- `signed`
  - 有符号由 `dataType` 决定（`int16/int32/int64`）。`signed=true` 配在 `uint*`/`bit`/`bool` 上会加载失败
- `unit`
  - 单位
- `intervalMs`
  - 该点采集周期
- `gpio`
  - `local_dio` 点位绑定的 Linux GPIO 编号
- `activeHigh`
  - `true` 表示 GPIO 高电平对应逻辑值 `1`
  - `false` 表示 GPIO 低电平对应逻辑值 `1`
- `debounceMs`
  - `digital_input` 防抖毫秒数，建议干接点输入配置 `30`
- `cachePolicy`
  - 缓存策略

本机硬件默认映射：

| 通道 | GPIO | 逻辑 |
| --- | ---: | --- |
| DI1-DI5 | 224、225、226、227、230 | 湿接点，低有效 |
| DI6-DI18 | 134、135、136、137、138、143、128、139、140、341、340、339、338 | 干接点，低有效；现场验证 DI6-DI13 短接时 GPIO 为 `0` |
| DO1-DO8 | 231、238、239、129、130、131、132、133 | 继电器输出，低有效；平台逻辑 `1=闭合/动作` |

舜通旧工程导入时，`modbusTCP_Reg.xml` 中的本机干接点会生成独立 `device_dio.json`。默认映射规则为旧 `DI0-DI7` 对应硬件 `DI6-DI13`，即旧通道号加 `5` 后再映射 GPIO。

### `write`

定义写能力。

字段：

- `enable`
  - 是否可写
- `function`
  - 写功能码，常见 `6/16`
- `length`
  - 写入寄存器长度
- `dataType`
  - 写入数据类型
  - 本机 DO 使用 `digital_output`
- `scale`
  - 写缩放，不继承 `read.scale`。同一个保持寄存器（读功能码 3、地址相同、类型相同）读写缩放或偏移不一致时加载失败
- `offset`
  - 写偏移
- `byteOrder`
  - 写字节序，规则与读侧相同；不配置时按 `write.dataType` 取自然序（不再默认 `AB`，旧默认值会把 32 位值截成高字）
- `min`
  - 最小值
- `max`
  - 最大值
- `step`
  - 步长
- `function`
  - `5` 写线圈（`bit`/`bool`）；`6` 写单寄存器（16 位类型，或按 `read.bit` 读改写一个位，位号按 `read.byteOrder` 解释）；`16` 写多寄存器（32/64 位必须用 16）
- `verifyAfterWrite`
  - 是否写后回读校验。回读值与实际写入的编码值比较（例如 float32 写 230.7，设备里是 230.699997），不再用绝对误差 1e-6
- `verifyDelayMs`
  - 写后延时
- `verifyByRead`
  - 是否通过读回校验

注意：

- 只把 `write.enable=true` 打开还不够
- `function / dataType` 至少要配完整；加载时校验功能码与类型、字节序、缩放
- 写结果三态：成功 / 失败 / 结果未知。请求已经发到设备但没有得到确定应答（超时、应答损坏、连接中断、写成功但校验回读失败）时，`CommandResult.outcomeUnknown=true`，写回阶段为 `writeback-timeout`。设备可能已经执行，不要换新 cmdId 重发；设备回异常码、请求未发出、回读值不一致属于确定失败

### `alarms`

告警规则数组。

每个元素字段：

- `type`
  - `high` 或 `low`
- `threshold`
  - 阈值
- `reportRecovery`
  - 是否上报恢复
- `persistValue`
  - 非空则告警写 SQLite
  - 空字符串则只上报不存盘

### `mqtt`

MQTT 连接与 topic 参数。

字段：

- `enabled`
  - 是否启用真实 MQTT
- `protocolVersion`
  - `mqtt3` 或 `mqtt5`
- `broker`
  - broker 地址
- `clientId`
  - 配置值保持为当前网关 `machineCode`；边端子服务和平台端消费者会在运行时追加职责后缀，保证 MQTT 连接唯一
- `username`
  - 用户名
- `password`
  - 密码
- `telemetryTopic`
  - 遥测 topic
- `legacyTelemetryEnabled`
  - 是否启用旧项目兼容上送。启用后新版驱动按 `legacyTelemetryIntervalMs` 额外发布旧版 `data/meterid/metrics` 格式
- `legacyTelemetryTopic`
  - 旧项目完整发布 topic。该字段按完整 topic 使用，不会再追加新版 machineCode
- `legacyTopicMachineCode`
  - 旧 topic 所属的旧设备标识，用于兼容 topic 路由校验
- `legacyTelemetryIntervalMs`
  - 旧格式上送周期，最小 1000ms；新版 topic 仍由 `mqttDriver.fullUploadIntervalMs` 控制
- `changeEventTopic`
  - 变位事件 topic；配置了 `reportOnChange=true` 的点位在数值变化时按单条事件消息发送到这里
- `alarmTopic`
  - 告警 topic
- `statusTopic`
  - 驱动状态与运行事件 topic
- `commandRequestTopic`
  - 命令请求 topic
- `commandReplyTopic`
  - 命令回执 topic，当前回执的是“已入共享写队列/被拒绝”，不是设备最终执行结果
- `otaRequestTopic`
  - OTA 请求 topic
- `otaReplyTopic`
  - OTA 受理结果 topic
- `otaStatusTopic`
  - OTA 过程状态 topic，当前支持 `accepted/downloading/verifying/applying/completed/failed`
- `qos`
  - QoS
- `maxPayloadBytes`
  - 实时数据 `telemetry / snapshot` 单条 MQTT payload 目标上限，默认 `49152` 字节；超过后自动按 `machineCode + chunkId + chunkIndex + chunkCount` 分片发送到同一个 `telemetryTopic`
- `cleanSession`
  - 是否清会话
- `keepAliveSec`
  - 心跳秒数
- `sessionExpirySec`
  - MQTT5 会话过期秒数
- `tls.enabled`
  - 是否启用内置 MQTT TLS。也可以通过 `ssl://` / `tls://` / `mqtts://` broker scheme 自动启用
- `tls.caFile`
  - TLS CA 文件路径。为空时使用系统默认 CA 路径；嵌入式生产环境建议显式配置
- `tls.certFile`
  - TLS 客户端证书路径，用于 broker 要求客户端证书的双向 TLS
- `tls.keyFile`
  - TLS 客户端私钥路径，必须和 `tls.certFile` 成对配置
- `tls.insecureSkipVerify`
  - 是否跳过证书和主机名校验。仅允许临时联调，生产禁止开启
- `offlineBuffer`
  - MQTT 断链本地缓冲配置。实时数据写入预分配 ring 文件；告警、变位、OTA 状态写入 SQLite outbox；连接恢复后先补发 outbox，再补发实时 ring。
- `offlineBuffer.enabled`
  - 是否启用断链缓冲
- `offlineBuffer.mode`
  - 当前使用 `ring`
- `offlineBuffer.realtimeFile`
  - 实时数据 ring 文件路径
- `offlineBuffer.realtimeFileSizeBytes`
  - 实时数据 ring 文件大小，默认 1GB
- `offlineBuffer.maxRealtimeMessageBytes`
  - 单条实时消息最大大小，默认 4MB
- `offlineBuffer.flushBatchSize`
  - ring 批量写入/补发控制参数
- `offlineBuffer.flushIntervalMs`
  - 刷盘间隔
- `offlineBuffer.replayBatchSize`
  - 实时 ring 恢复连接后单轮补传条数
- `offlineBuffer.eventOutbox.sqlitePath`
  - 关键事件 outbox SQLite 路径
- `offlineBuffer.eventOutbox.retentionMonths`
  - 已发送事件按自然月保留数量，默认 12；例如 2026-01 数据在 2027-02 清理
- `offlineBuffer.eventOutbox.cleanupIntervalHours`
  - outbox 清理检查间隔
- `offlineBuffer.eventOutbox.replayBatchSize`
  - outbox 恢复连接后单轮补传条数

### `mqttDriver`

### `systemMonitor`

边端系统监测、远程诊断、配置拉取和共享内存点位快照配置。该服务用于平台侧查看网关本机运行情况，不用于第三方实时数据转发。

字段：

- `enabled`
  - 是否启用 `system-monitor@monitor-service.service`
- `defaultIntervalMs`
  - 没有页面订阅或订阅未指定周期时的默认上报周期
- `minIntervalMs`
  - 平台订阅允许的最小上报周期
- `subscriptionTtlSec`
  - 平台监测订阅租约有效期；页面不续约后边端停止高频上报
- `cpuAlertThreshold` / `memAlertThreshold` / `diskAlertThreshold`
  - CPU、内存、磁盘主动告警阈值
- `cpuAlertRecoveryThreshold`
  - CPU 告警恢复阈值，必须低于触发阈值；默认 `80`
- `cpuAlertConsecutiveSamples` / `cpuRecoveryConsecutiveSamples`
  - CPU 告警触发和恢复所需的连续采样次数；默认均为 `3`，按 5 秒采样时约需持续 15 秒
- `alertRepeatIntervalSec`
  - 同一告警持续存在时的重复上报间隔
- `diagEnabled`
  - 是否允许远程诊断命令
- `allowedCommands`
  - 允许执行的诊断命令白名单，当前包括 `uptime`、`free_m`、`df_root`、`top_once`、`ps_gateway`、`journal_tail`、`systemctl_status`、`cellular_status`
- `cellular.enabled`
  - 是否采集 4G 模块状态
- `cellular.probeIntervalMs`
  - 4G 状态实际探测间隔；即使页面订阅周期更短，也不会每次都访问串口
- `cellular.commandTimeoutMs`
  - 单条 AT 指令等待响应超时时间
- `cellular.atBaudRate`
  - 4G AT 口波特率，当前硬件默认 `115200`
- `cellular.signalAlertThresholdPercent`
  - 4G 信号强度低于该百分比时主动告警
- `cellular.maskSensitiveFields`
  - 是否脱敏 IMEI、ICCID、IMSI。当前项目要求平台侧直接查看完整 4G 模块标识，默认 `false`
- `cellular.interfacePatterns`
  - 4G 数据网卡匹配规则，例如 `wwan*`、`ppp*`、`usb*`、`rmnet*`
- `cellular.modemDevicePatterns`
  - 4G Modem 设备匹配规则。当前硬件优先按 `/dev/ttyUSB2`、`/dev/ttyUSB1`、`/dev/ttyUSB0`、`/dev/ttyUSB3` 顺序探测，之后兜底匹配 `/dev/ttyUSB*` 和 `/dev/cdc-wdm*`
- `cellular.routeFailover.enabled`
  - 是否启用 4G 与有线网络自动切换；三种运行模式使用同一配置。
- `cellular.routeFailover.preferCellular`
  - `true` 表示 4G 健康时优先使用 4G；`false` 表示有线优先。
- `cellular.routeFailover.cellularInterface` / `cellular.routeFailover.wiredInterface`
  - 4G 网卡和兼容旧项目的单个有线网卡字段。
- `cellular.routeFailover.wiredInterfaces`
  - 有线候选网口列表；`auto` 表示自动发现全部实体以太网口。默认 `ens1, auto`，优先使用 `ens1`，之后轮询其余实体口。
- `cellular.routeFailover.wiredRouteMetric` / `cellular.routeFailover.wiredStandbyRouteMetric`
  - 当前选中有线口和上一个有线口的路由优先级，用于确保换口后新端口立即成为出口。
- `cellular.routeFailover.probeHost` / `cellular.routeFailover.probePort`
  - 强制通过 4G 网卡访问的公网健康检查目标。
- `cellular.routeFailover.failureThreshold` / `cellular.routeFailover.recoveryThreshold`
  - 连续失败多少次后切到有线，以及连续成功多少次后恢复 4G。
- `cellular.routeFailover.cellularRouteMetric` / `cellular.routeFailover.fallbackRouteMetric`
  - 4G 正常和故障时的路由优先级；数值越小优先级越高。

### `localDisplay`

- `kiosk.fullscreen`
  - 是否全屏
- `kiosk.setDisplayMode`
  - 是否尝试用 `xrandr` 切换显示模式
- `kiosk.zoom`
  - WebKit 缩放比例
- `screens`
  - WebKit 本地画面定义列表
- `screens[].screenCode`
  - 画面编码，例如 `overview`
- `screens[].title`
  - 画面标题
- `screens[].layout`
  - 画面栅格布局配置
- `screens[].layout.columns`
  - 栅格列数，默认 `12`
- `screens[].layout.rowHeight`
  - 栅格行高，单位像素
- `screens[].layout.gap`
  - 组件间距，单位像素
- `screens[].widgets`

- `screens[].widgets[].type`
  - 组件类型，支持 `groupTitle`、`statusCard`、`valueCard`、`pointTable`、`alarmSummary`
- `screens[].widgets[].bind.index`

### `cameraService`

边端摄像头接入和推流配置。该服务独立运行，不依赖 Modbus/DLT645 采集驱动。视频流不写入共享内存，也不通过 MQTT 传输；摄像头在线状态、帧率、码率、错误码等轻量状态会写入共享内存，并通过 MQTT 状态 topic 上报。
