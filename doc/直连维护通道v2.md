# 直连维护通道 v2（SystemMonitor）

分支 `feat/maint-v2`，基于 `realese1.0 @ aac6e5e`。接口与授权票格式按客户端交接文档
`GatewayClient/docs/handoff/edge-maintenance-v2.md`（以下简称“交接文档”）实现；与交接文档不同的地方见第 7 节。

## 1. 做了什么

| 能力 | 说明 |
| --- | --- |
| HTTPS | 运行时加载设备上的 OpenSSL（dlopen `libssl` / `libcrypto` 3 或 1.1，与 MQTT TLS、OTA 验签相同做法），**不新增链接依赖**；TLS 1.2+；设备自签证书（ECDSA P-256，CN = 机器码，10 年），客户端按 SHA-256(证书 DER) 指纹固定 |
| 会话 | `POST /api/v2/auth/login {"passwordSha256"}`（与 v1 同一凭据、同一失败锁定）→ 令牌 15 分钟滑动、最长 8 小时；设备只存 SHA-256(令牌)，SystemMonitor 重启后令牌仍有效（直推事务会重启它） |
| 授权票 | Ed25519 验签，验证顺序与拒绝码按交接文档第 4 节；一次性票记到过期为止；12 条测试向量全部通过 |
| 调试模式 | `GET/POST /api/v2/debug-mode`，进入要 `debug.enter` L2 票；30 分钟无请求自动退出；状态文件 `debug-mode.json`（0644，供本地屏幕横幅读取） |
| 配置直推 | `POST /api/v2/config/apply`：`dryRun` 默认 true；预演给 `checks[]` 和 `affectedServices`；正式应用要 `config.apply` L3 票，回 202 + 事务号，**按 requestId 幂等**；事务在独立助手进程里执行：校验 → 备份 → 写入 → 重启 gateway-services → 健康检查（期望单元全部 active 且稳定）→ 提交；不健康自动回退并再重启 |
| 回退 | `POST /api/v2/config/restore {transactionId}`（`config.restore` L3）：进行中的事务先停下再回退（回 202 + 当前状态，客户端接着查询），已提交的事务直接回到应用前的备份；文件在事务之后又被改过时拒绝（409 `restore_conflict`） |
| 写点 | `POST /api/v2/control/batch`：`dryRun` 默认 true，设备预判可写性、量程、步长、允许值、优先控制租约、功率控制归属；正式写要 `control.batch` 票（安全类参数 161/162/151/535/504/453/454/457/458 要 L3）；回执逐点 `accepted / adoptedValue / arbitrationLevel / rejectReason / stage / writebackTs / readback`；请求里出现 `highPriority / priority / priorityControl` 一律 400 `high_priority_not_allowed`，`source` 由设备固定 |
| 按点读 | `POST /api/v2/points/query {indexes, meters}`、`GET /api/v2/telemetry/full`：带 `total` / `truncated`，非数值输出 `null` 且 `quality=0`，**不碰上位机心跳租约** |
| 设备审计 | `audit.jsonl` 只追加、哈希链：`hash = SHA-256(prevHash + JCS(本条去掉 hash))`，首条 `prevHash` 为 64 个 0；`GET /api/v2/audit?sinceSeq=&limit=` |
| v1 只读 | v2 启用时（默认 `v1ReadOnly=true`）v1 端口的写接口（control/batch、config/apply 正式应用、config/delete、config/restore、ota/jobs）一律 403 `use_maintenance_v2`：**知道口令不能写** |
| 系统状态 | `GET /api/v2/system/status` 按 `gateway-services.sh list` 的期望单元报状态（修交接文档第 1 节 #7），带 `expected:true` |

没有做（第二阶段）：离线升级上传与任务（`/ota/uploads`、`/ota/jobs`）、实时推送（SSE）、日志接口、`config/delete`、
映射阶段（`features` 里没有 `mappingStage`，收到 `logic/point-mapping.json` 预演即报 `mapping.points` 错误）。这些接口回 501 `not_implemented`。

## 2. 配置

`apps/monitor-service.json` → `systemMonitor.directMaintenance.v2`（不认识的字段旧固件会忽略，可先改配置再换程序）：

```json
"v2": {
  "enabled": true,
  "listenPort": 9444,
  "listenHosts": [],
  "v1ReadOnly": true,
  "sessionTtlSec": 900,
  "sessionMaxSec": 28800,
  "debugIdleSec": 1800,
  "healthTimeoutSec": 90,
  "healthStableSec": 10,
  "maxConnections": 8
}
```

- `listenHosts` 为空时用 v1 的 `listenHosts`；放行网段、失败锁定、口令凭据都与 v1 共用。某个地址绑定失败只跳过该地址。
- 默认端口 9444，与 v1（9443）并存；以后 v1 关闭时可改成 9443。

不在应用配置里、配置直推也改不到的安全锚点（只有 root 能改）：

| 位置 | 内容 |
| --- | --- |
| `/opt/modbus-gateway/config/maintenance-v2/server.crt`、`server.key`（0600） | 设备证书与私钥，`SystemMonitor --init-maintenance-tls` 生成 |
| `/opt/modbus-gateway/config/maintenance-v2/trusted-ticket-keys.json` | 信任的平台公钥：`{"keys":[{"keyId":"…","algorithm":"Ed25519","publicKey":"<32 字节公钥 base64>"}]}`；固件内置列表目前为空（平台正式公钥 C5 下发） |
| `/opt/modbus-gateway/data/maintenance-v2/` | 会话、一次性票、审计、调试模式、事务（`transactions/<id>/tx.json`、`staged/`、`backup/`） |

两个目录可用 `--maintenance-v2-dir`、`--maintenance-v2-state-dir` 改（测试用）。

## 3. 命令

```sh
SystemMonitor --help
SystemMonitor --app-config /opt/modbus-gateway/config/runtime/apps/monitor-service.json --init-maintenance-tls
# 输出：fingerprint=AA:BB:…（95 个字符） 和 certFile=…；已有证书时只输出指纹（幂等）；没有 openssl 命令时输出 unsupported=1
```

证书用设备上的 `openssl req` 生成（私钥文件 0600，不离开设备，不打印）。

## 4. 配置事务的执行方式

- `gateway-services.sh apply` 会停掉并重启 `system-monitor@*`，所以事务不能在 SystemMonitor 里跑：服务端写好事务日志
  （`state: accepted`、暂存内容、写入前文件的 SHA-256）后，用 `systemd-run --unit=gz-maint-v2-apply-<事务号>` 起一个
  `SystemMonitor --maintenance-v2-tx <事务号>` 助手进程（没有 systemd 时双 fork 脱离），助手持有事务锁直到结束。
- 助手：复核内容（边端加载器）与“预演之后文件没被别人改过” → 先记日志再写（备份 → 原子写）→
  `systemctl restart gateway-services.service` → 期望单元全部 active 并持续 `healthStableSec` → `committed`；
  超时或重启失败 → 恢复备份、删除新建的文件 → `rolled-back` → 再重启服务并记录回退后的健康结果。
- 进行中的事务收到回退请求：服务端写中止标记，助手在下一步（健康检查每秒、重启命令每 200 ms）看到后回退。
- 助手进程死掉（掉电等）：SystemMonitor 每 30 秒检查，没有活着的助手且超过 15 秒没有进展的事务按“中断”回退。
- 生产升级日志管理的运行目录（存在 `data/runtime-production`）**保持现有保护**：正式应用回 409
  `production_runtime_locked`，与 v1 相同；预演、快照照常。
- 可写路径：v1 快照集合里的文件，加上运行目录下 `device_identity.json`、`apps/*.json`、`devices/*.json`、`logic/*.json`
  （没有就新建，回退时删除）；不写符号链接；证书、私钥、信任公钥不在可写范围。快照同样列出运行目录里这些文件。

## 5. 编译与测试

- 新增源码 `src/maintenance_v2/*.cpp`（只编进 `SystemMonitor`，`edge_gateway` 库不变）、
  `include/edge_gateway/maintenance_v2.hpp`、`include/edge_gateway/system_monitor_direct_maintenance_bridge.hpp`

## 7. 与交接文档的差异（以边端为准）

1. **写点没有“仲裁限值”**：边端现有写入路径对越界值是拒绝，不会改小后采纳；所以 `adoptedValue` 要么等于请求值、要么为 `null`
   （带 `rejectReason`）。`arbitrationLevel` 取 `ems-parameter`（EMS 虚拟参数，本地落盘）或 `device-write`（设备驱动写）。
2. **出厂 EMS 虚拟点里只有计划曲线 400–447 可写**；161 / 455 等参数在点表里 `write.enable=false`，写点预演直接拒绝
   （`point write is disabled`）。这些参数要改，走配置直推。
3. 事务的 `services` 是 `gateway-services.sh list` 的全部期望单元（直推总是整体重启 gateway-services），不是按文件推算的子集。
4. 生产升级日志管理的设备不能现场直推（第 4 节）。
5. 回退进行中的事务回 202（不是 200）+ 当前状态。
