# 192.168.22.11 边端交叉编译教程

## 适用范围

本文档统一记录当前边端项目在 `192.168.22.11` 交叉编译机上的构建方式，包括：

- 边端 C++ 驱动和服务程序。
- KY-EMS Qt 本地界面程序。
- 出厂初始化包中的二进制同步要求。

当前目标平台是全志 aarch64，不要使用 RK3568 工具链、RK3568 sysroot 或 Windows MinGW Qt 路径。

> 当前交叉编译环境已经迁移到远端服务器。Windows 本机、WSL 和远端
> `/srv/build/Gateway-zk` 之间没有 HGFS、SMB 或其他直接目录映射。本机修改不会自动出现在
> 22.11，远端构建产物也不会自动回到本机。

## 远端编译服务器

- ESXi 宿主机：`192.168.22.100`
- 虚拟机名称：`Tronlong`（VMID `12`）
- 编译机地址：`192.168.22.11/24`
- 编译机网关：`192.168.22.1`
- ESXi 已配置该虚拟机自动启动，启动顺序为 `1`，延迟 `30` 秒。

本机 VMware 中保留的旧副本与远端服务器使用相同 IP，禁止同时启动。旧副本仅作为离线
回退介质，不再承担日常编译。日常交叉编译必须先确认 `192.168.22.11:22` 可达，再通过 SSH
进入远端工作区。

交叉编译工具链不一定在登录 shell 的 `PATH` 中，项目脚本会自动补齐所需路径。

源码位于远端服务器本地磁盘，不再依赖 VMware Workstation 的 `/mnt/hgfs`、Windows 盘符或
WSL `/mnt/d`。日常修改优先通过 Git 提交和推送后在编译机拉取；服务器工作区有未提交修改
时，先确认修改归属，不要执行 `reset`、`clean`、强制切换分支或 `rsync --delete`。

```sh
ssh root@192.168.22.11
sudo -iu tronlong
cd /srv/build/Gateway-zk
git status --short --branch
git fetch origin
# 仅在工作区干净且目标分支已推送后执行：
git pull --ff-only
```

## 编译前同步规则

每次交叉编译都要明确完成下面四步，不能省略源码同步：

1. 本机记录待编译分支、提交和未提交文件，确认要编译的真实源码范围。
2. SSH 登录 22.11，检查 `/srv/build/Gateway-zk` 的分支、提交和工作区状态。
3. 已提交内容使用 `git fetch`、`git pull --ff-only` 同步；未提交内容必须上传到独立临时工作区，
   不直接覆盖共享工作区中的未知修改。
4. 编译后使用 `scp` 明确回传选中的二进制或安装包，并在远端、本机各计算一次 SHA256。

编译前最少执行：

```sh
ssh root@192.168.22.11
sudo -iu tronlong
cd /srv/build/Gateway-zk
git status --short --branch
git rev-parse HEAD
```

禁止把本机 `D:/workspace/Embedded/Gateway-zk`、WSL `/mnt/d/workspace/Embedded/Gateway-zk` 或旧
`/mnt/hgfs/Embedded/Gateway-zk` 当作 22.11 的实时镜像。

本机 VS Code/WSL 任务以及历史 `build-*` 目录中的 CMake 缓存可能仍记录旧绝对路径；这些内容
不是当前交叉编译入口，也不能作为发布产物已经基于最新源码构建的证据。

### 方式一：已推送提交，更新持久仓库

只有同时满足“目标提交已经推送”和“远端工作区干净”时，才允许更新
`/srv/build/Gateway-zk`：

```sh
ssh root@192.168.22.11
sudo -iu tronlong git -C /srv/build/Gateway-zk status --short --branch
# 确认没有未提交文件，并确认当前分支正确后：
sudo -iu tronlong git -C /srv/build/Gateway-zk fetch origin
sudo -iu tronlong git -C /srv/build/Gateway-zk pull --ff-only
```

如果状态不干净，立即停止持久仓库更新流程。不得为了编译而清理、覆盖或暂存不属于本次任务的
远端改动。

### 方式二：未推送内容，使用独立临时工作区

需要验证本机暂存树，或者远端持久仓库不干净时，使用唯一的
`/tmp/gateway-build-<id>`。本机先将本次要构建的文件加入 Git 暂存区，再从 Git 索引导出；
不要直接压缩整个脏工作目录。未跟踪但确实参与构建的文件也必须先明确加入暂存区。

本机 PowerShell 示例：

```powershell
$BuildId = Get-Date -Format 'yyyyMMddHHmmss'
$ExportDir = "$env:TEMP/gateway-build-$BuildId"
$Archive = "$env:TEMP/gateway-build-$BuildId.tar.gz"

git status --short --branch
git diff --check
git diff --cached --check
New-Item -ItemType Directory -Force $ExportDir | Out-Null
git checkout-index --all --force --prefix="$ExportDir/"
tar -C $ExportDir -czf $Archive .

ssh root@192.168.22.11 "install -d -o tronlong -g tronlong /tmp/gateway-build-$BuildId"
scp $Archive "root@192.168.22.11:/tmp/gateway-build-$BuildId/source.tar.gz"
```

在 `22.11` 上只解压和构建该临时快照，目录属主必须是 `tronlong`：

```sh
# 将 <id> 替换为本次记录的 BuildId，不使用通配符。
chown -R tronlong:tronlong /tmp/gateway-build-<id>
sudo -iu tronlong sh -lc '
  cd /tmp/gateway-build-<id> &&
  mkdir source &&
  tar -xzf source.tar.gz -C source &&
  cd source &&
  sh tools/build_edge_aarch64.sh --clean --build-dir /tmp/gateway-build-<id>/out
'
```

构建完成后，用 `scp` 回传明确的产物，分别计算 SHA256。确认产物已回传后，只清理本次记录的
完整 `/tmp/gateway-build-<id>` 路径；不得使用 `gateway-build-*` 通配符，也不得清理
`/srv/build/Gateway-zk`。

两种方式都禁止：

- 用 `scp`、`rsync` 或共享目录直接覆盖 `/srv/build/Gateway-zk`。
- 在持久仓库执行 `git reset`、`git clean`、强制切分支或 `rsync --delete`。
- 从包含未确认修改和测试产物的本机工作目录直接打包构建。

## 边端驱动编译

在 `192.168.22.11` 上执行：

```sh
cd /srv/build/Gateway-zk
sh tools/build_edge_aarch64.sh --clean
```

该命令默认构建到 `build-aarch64-cross`，不会覆盖现有 `build-aarch64` 产物。

如果需要将已验证产物发布回 `build-aarch64`，用于出厂包打包：

```sh
cd /srv/build/Gateway-zk
sh tools/build_edge_aarch64.sh --clean --publish
```

如果需要同时生成出厂初始化包：

```sh
cd /srv/build/Gateway-zk
sh tools/build_edge_aarch64.sh --clean --publish --package --profile full
```

如果只打项目实际需要的驱动包：

```sh
cd /srv/build/Gateway-zk
sh tools/build_edge_aarch64.sh --clean --publish --package --profile project --manifest edge-package-manifest.json
```

## Qt SCADA 界面编译

先构建 `edge_gateway` 公共库，再使用全志 Qt sysroot 编译统一运行时。建议始终使用独立 `/tmp` 目录，避免污染共享源码目录。

在 `192.168.22.11` 上执行：

```sh
cd /srv/build/Gateway-zk
sh tools/build_edge_aarch64.sh --clean \
  --build-dir /tmp/gateway-ems-scada-build/edge edge_gateway
sh tools/build_scada_qt_aarch64.sh --clean \
  --build-dir /tmp/gateway-ems-scada-build/qt \
  --edge-build-dir /tmp/gateway-ems-scada-build/edge
```

预期产物：

- 产物路径：`/tmp/gateway-ems-scada-build/qt/KY-SCADA`
- 文件类型：`ELF 64-bit LSB executable, ARM aarch64`
- 主要依赖：`libQt5Widgets`, `libQt5Gui`, `libQt5Core`, `libGLESv2`, `libpthread`, `libstdc++`, `libc`

## 桌面初始化包同步

Qt SCADA 验证通过后，需要同步到当前活跃桌面端初始化资源。Windows 开发环境路径：

```text
D:/workspace/CloudPlatform/idea/GatewayDesktop-Modern/src/GatewayDesktop.UI/Assets/DeviceInit/ky-ems/KY-EMS
```

同时替换初始化包内的同名文件：

```text
D:/workspace/CloudPlatform/idea/GatewayDesktop-Modern/src/GatewayDesktop.UI/Assets/DeviceInit/gateway-factory-defaults.tar.gz
```

初始化包内的 `KY-EMS`、外层 `ky-ems/KY-EMS` 和 KY-EMS 编译产物应保持相同 SHA256。

由于没有映射目录，必须显式回传。例如：

```sh
scp tronlong@192.168.22.11:/srv/build/Gateway-zk/gateway-factory-defaults.tar.gz .
scp tronlong@192.168.22.11:/srv/build/Gateway-zk/build-scada-qt-aarch64/KY-SCADA .
sha256sum gateway-factory-defaults.tar.gz KY-SCADA
```

## 注意事项

- 不要使用 Windows Qt/MinGW 的 qmake 产物编译目标端程序。
- 不要复用 RK3568 的 Qt/sysroot。
- 出厂包 `gateway-factory-defaults.tar.gz` 是边端、桌面初始化工具、平台部署的共同交付物，发布前需要校验三处 SHA256 是否一致。
