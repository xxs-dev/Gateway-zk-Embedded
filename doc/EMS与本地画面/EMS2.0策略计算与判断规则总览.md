# EMS 2.0 策略计算与判断规则总览

## 1. 文档目的

本文整理当前边端 EMS 2.0 的真实计算和判断逻辑，回答以下问题：

- 每个策略从哪些共享内存点取数。
- 策略如何计算有功、无功和运行状态。
- 什么条件下启动、保持、降额、停止或禁止输出。
- 多个策略同时运行时如何仲裁。
- 台区、PCS、BMS、SOC 和通讯条件如何限制最终输出。
- 哪些节点会真实写设备，哪些当前只计算不下发。

本文以以下文件为准，不以旧 Qt `script.cpp` 或界面显示结果反推算法：

- 运行图：`config/factory/runtime/logic/shuntong_ems_graph.json`
- 解释器：`src/graph_ems_engine.cpp`
- 工厂运行入口：`config/factory/runtime/apps/mqtt-service.json`
- 基线提交：`8ebf515 feat(edge): complete EMS cluster dispatch integration`
- 整理日期：2026-08-07

## 2. 当前运行基线

### 2.1 实际执行入口

当前工厂配置由 MQTT 服务中的 `computeEngine` 执行 Graph EMS V2：

```text
采集驱动共享内存
  -> ComputeEngine 统一快照
  -> shuntong_ems_graph.json
  -> 策略候选输出
  -> phaseArbiter 多策略仲裁
  -> 强制满充覆盖
  -> powerConstraint 最终限制
  -> 627..632（PCS A/B/C 相最终有功、无功目标）
  -> controlWrite / PendingWriteCommand
  -> PCS 驱动真实写入
```

- `computeEngine.scanIntervalMs = 200 ms`
- Graph EMS 规则触发周期为 `1000 ms`
- 当前运行图包含 `487` 个节点、`489` 条连接
- 当前运行图虚拟点范围为 `700000..799999`
- 单次扫描最多提交 `100` 个设备写命令

节点构成：

| 节点类型 | 数量 | 当前用途 |
| --- | ---: | --- |
| `formula` | 287 | 算术、限幅、绝对值、三角函数 |
| `switch` | 110 | 单条件二选一 |
| `windowAggregate` | 30 | 电表滑动平均 |
| `controlGate` | 29 | 多条件许可判断 |
| `controlWrite` | 21 | 设备命令提交 |
| `scheduleSelect` | 3 | 24 小时计划和台区分时限制 |
| `sequence` | 3 | 循环测试、强制满充、启动保持 |
| `timeSource` | 2 | 本地小时、月内日期 |
| `phaseArbiter` | 1 | 多策略 P/Q 仲裁 |
| `powerConstraint` | 1 | 最终功率和 SOC 限制 |

工厂 `mqtt-service.json` 当前配置：

### 2.3 功率符号

当前舜通 Graph EMS 使用：

```text
P > 0：PCS 充电，储能从交流侧吸收功率
P < 0：PCS 放电，储能向交流侧送出功率
Q 正负：沿用现场 PCS 分相无功符号
```

固定充电、光伏消纳、高压治理和强制满充产生正有功；固定放电、低压治理和动态增容产生负有功。

> 风险：新并机 KECP 协议当前约定 `P > 0` 为放电、`P < 0` 为充电，与本图相反。并机输出接入本图前必须增加符号转换或统一协议约定。

## 3. 数据有效性和通用判断

### 3.1 单周期一致快照

每次 Graph EMS 运行前，解释器一次性读取本图依赖的共享内存点。一次策略计算中的所有节点使用同一份快照，避免同一周期前后节点读到不同采集时刻的数据。

### 3.2 有效点条件

普通 `latestValue()` 只有同时满足以下条件才返回数值：

```text
点存在
AND quality == 1
AND stale == false
```

`stale` 由点路由和采集点 TTL 判断。Graph EMS 普通节点本身没有再增加统一的固定超时时间。

### 3.3 缺点和坏质量行为

| 节点/环节 | 输入缺失、坏质量或过期时的行为 |
| --- | --- |
| `formula` | 不更新本节点输出；带 `defaultValue` 的输入可使用默认值 |
| `switch` | 条件或被选值不可用时不更新输出 |
| `controlGate` | 许可输出强制为 `0` |
| `windowAggregate` | 本周期不加入窗口，也不更新平均值 |
| `scheduleSelect` | 当前小时引用的点不完整时保留原输出，不写合成零值 |
| `phaseArbiter` | 候选缺失时跳过该候选；基础值缺失时按 `0` 使用 |
| `powerConstraint` | 任一输入 P/Q 缺失时整节点不更新最终输出 |
| `controlWrite` | 输入或许可点无效时不提交设备命令 |
| `sequence` | 转移条件有任一点无效时不发生状态转移 |
| `clusterDispatch` | 输入无效或超时后输出无效原因，配置允许时将候选 P/Q 清零 |

### 3.4 Profile 判定

节点是否执行由 `shouldRunNode()` 判断：

- `enabled=false`：节点不运行。
- `profileKey...`：Profile 未配置时按启用处理；显式为 `0` 时跳过。
- `optionalProfileKey...`：Profile 未配置时按关闭处理；必须显式为 `1` 才运行。
- `profileDisabledKey...`：对应 Profile 为 `1` 时反向停用节点。
- `profileIntKey`：只有整数 Profile 等于声明的允许值时运行。

## 4. 数据预处理

### 4.1 电表滑动平均

台区电表、储能电表和可选备用电表使用 `windowAggregate`：

```text
N = clamp(floor(156（电表平均窗口样本数）), 1, 4096)
平均值 = 最近 N 个有效样本之和 / 有效样本数
```

- 台区电表原始电参 `1030..1043` 生成台区滑动平均电参 `201..216`。
- 储能电表原始电参 `1130..1143` 生成储能滑动平均电参 `251..266`。
- 可选备用/并网电表原始 P/Q `4536..4543` 生成内部平均点 `700034..700041`。
- 坏质量样本不进入窗口。
- 窗口尚未填满时，使用当前已有样本计算，不等待满窗口。

### 4.2 负荷派生

当前默认 `Meter_TQ=1`、`Meter_CN=1`、`Meter_BW=0`，负荷按台区表减储能表计算：

```text
Pload_i = Pgrid_i - Pess_i
Qload_i = Qgrid_i - Qess_i
```

其中：

- `309/310/311`：负荷 A/B/C 相平均有功 `Pload_A/B/C`
- `312`：负荷平均总有功 `Pload_total`
- Q、S、功率因数使用对应派生点继续计算

启用 `Meter_BW` 且不启用独立负荷表路径时，改为：

```text
Pload_i = Pgrid_i - Pbackup_i
Qload_i = Qgrid_i - Qbackup_i
```

### 4.3 视在功率和功率因数

每相及总量均按以下公式计算：

```text
S = sqrt(P^2 + Q^2)
cos = P / S
```

除数接近 `0` 时 `safeDivide` 输出 `0`，不抛出除零异常。

### 4.4 BMS 允许功率和当日电量

```text
1552（BMS 最大允许充电功率）
  = 1566（BMS 堆电压） * 1556（BMS 最大允许充电电流） * 0.001

1553（BMS 最大允许放电功率）
  = 1566（BMS 堆电压） * 1557（BMS 最大允许放电电流） * 0.001
```

当 `BMS_MODEL=1` 或 `3` 时：

```text
1615（BMS 今日充电量）
  = 1586（BMS 累计充电量） - 398（BMS 充电电量日初值）

1616（BMS 今日放电量）
  = 1587（BMS 累计放电量） - 399（BMS 放电电量日初值）
```

当前默认 `BMS_MODEL=2`，当日电量两条节点不运行，但允许充放电功率仍正常计算。

## 5. 台区正向和反向功率限制

该部分负责生成后续所有策略共同使用的：

- `453`：当前正向功率限制值
- `454`：当前正向功率限制使能
- `457`：当前反向/返送功率限制值
- `458`：当前反向/返送功率限制使能

### 5.1 模式选择

- `27（台区功率限制总使能）=1`：允许台区限制生效。
- `28（台区功率限制模式）=0`：固定限制模式。
- `28（台区功率限制模式）=1`：24 小时分时限制模式。

固定模式：

- `471`：台区固定正向限制使能
- `472`：台区固定正向限制功率
- `473`：台区固定反向限制使能
- `474`：台区固定反向限制功率

分时模式：

- `700..723`：0 至 23 时台区正向限制功率
- `724..747`：0 至 23 时台区反向限制功率
- `475/476`：正向小时使能掩码，分别覆盖 0 至 15 时、16 至 23 时
- `477/478`：反向小时使能掩码，分别覆盖 0 至 15 时、16 至 23 时
- 0 至 15 时使用低 16 位掩码，16 至 23 时使用高掩码，对应小时 bit 为 `1` 才启用。

最终输出：

```text
453（当前正向限制值）
454（当前正向限制使能）
457（当前反向限制值）
458（当前反向限制使能）
```

### 5.2 当前默认状态

生成上述值的节点带 `optionalProfileKey=STATION_LIMIT_V2`，工厂默认 Profile 为 `0`。因此工厂默认图不会主动刷新这些点，其他策略读取的是工程已有值或外部配置写入值。

## 6. COS 无功补偿

### 6.1 输入

- `514`：目标功率因数
- `209..211`：台区 A/B/C 相平均有功
- `213..215`：台区 A/B/C 相平均无功

### 6.2 计算

每相执行：

```text
tanTarget = tan(acos(targetCos))
Qtarget_i = abs(tanTarget * Pgrid_i)

Qout_i =
  Qgrid_i - Qtarget_i,  Qgrid_i >  Qtarget_i
  Qgrid_i + Qtarget_i,  Qgrid_i < -Qtarget_i
  0,                    其他
```

输出：

- `505..507`：A/B/C 相目标无功绝对值
- `508`：三相目标无功绝对值之和
- `601..603`：A/B/C 相 COS 无功补偿候选
- `604`：三相 COS 补偿输出绝对值之和
- `604（COS 补偿总量）!= 0` 时 `8（COS 运行反馈）=1`，否则 `8=0`

`targetCos` 超出 `[-1, 1]` 时 `acos` 节点跳过本周期计算。

### 6.3 启停判断

当前图没有独立的 COS 使能点。只要 `Meter_TQ` Profile 启用、输入有效且计算结果非零，就会产生无功候选；将目标功率因数配置成不会产生补偿的值，才能自然停止输出。

## 7. 低电压治理

### 7.1 输入

- `251..253`：储能电表 A/B/C 相滑动平均电压
- `1130..1132`：储能电表 A/B/C 相瞬时电压
- `1136..1138`：储能电表 A/B/C 相实时有功
- `544`：低压治理下限
- `545`：低压治理上限
- `533`：功率调节步长 `GradP`
- `535`：PCS 单相有功绝对值上限 `PphaseMax`

### 7.2 每相计算

```text
if Uavg < Ulow:
    Pnext = PessRealtime - GradP
else if Uavg > Uhigh:
    Pnext = PessRealtime + GradP
else:
    Pnext = 0

P = clamp(Pnext, -PphaseMax, 0)

if Uinstant < Ulow - 8:
    P = clamp(P * 1.2, -PphaseMax, 0)
```

输出：

- `605..607`：低压治理 A/B/C 相有功候选
- `608`：低压治理三相有功绝对值之和
- `608（低压治理总量）!= 0` 时 `10（低压治理运行反馈）=1`

负值表示放电，低压治理通过 PCS 放电抬升电压。

### 7.3 启停判断

当前图没有独立低压策略使能点。`Meter_CN` Profile 启用后，是否动作完全由电压区间、实时储能功率和阈值决定。

## 8. 高电压治理

### 8.1 每相计算

输入与低压治理相同，高压阈值改用：

- `546`：高压治理下限
- `547`：高压治理上限

```text
if Uavg > Uhigh:
    Pnext = PessRealtime + GradP
else if Uavg < Ulow:
    Pnext = PessRealtime - GradP
else:
    Pnext = 0

P = clamp(Pnext, 0, PphaseMax)

if Uinstant > Uhigh + 8:
    P = clamp(P * 1.2, 0, PphaseMax)
```

输出：

- `609..611`：高压治理 A/B/C 相有功候选
- `612`：高压治理三相有功绝对值之和
- `612（高压治理总量）!= 0` 时 `12（高压治理运行反馈）=1`

正值表示充电，高压治理通过 PCS 充电吸收功率。

### 8.2 启停判断

当前图没有独立高压策略使能点。`Meter_CN` Profile 启用后由电压阈值自动判断。

## 9. 手动固定功率充电

### 9.1 启动和停止

```text
启动条件：1570（BMS 堆 SOC） < 452（手动充电目标 SOC）
         AND 451（手动充电目标功率） != 0

停止条件：1570（BMS 堆 SOC） >= 452（手动充电目标 SOC）
         OR 451（手动充电目标功率） == 0
         OR 输入无效
```

运行反馈输出到 `14（手动充电运行反馈）`。

### 9.2 功率计算

正向台区限制启用时：

```text
Pavailable = 453（当前正向功率限制值） - 312（负荷平均总有功）
Pcharge = min(max(Pavailable, 0), 451（手动充电目标功率）)
```

正向台区限制未启用时：

```text
Pcharge = 451（手动充电目标功率）
```

总充电候选输出到 `613（手动充电总有功候选）`，在仲裁器中按三相均分。

当前图没有额外的手动充电使能点，目标功率置 `0` 即停止。

## 10. 手动固定功率放电

### 10.1 启动和停止

```text
启动条件：1570（BMS 堆 SOC） > 456（手动放电目标 SOC）
         AND 455（手动放电目标功率） != 0

停止条件：1570（BMS 堆 SOC） <= 456（手动放电目标 SOC）
         OR 455（手动放电目标功率） == 0
         OR 输入无效
```

运行反馈输出到 `16（手动放电运行反馈）`。

### 10.2 功率计算

反向台区限制启用时：

```text
Pavailable = 457（当前反向功率限制值） - 312（负荷平均总有功）
Pdischarge = -min(max(Pavailable, 0), 455（手动放电目标功率）)
```

反向台区限制未启用时：

```text
Pdischarge = -455（手动放电目标功率）
```

总放电候选输出到 `614（手动放电总有功候选）`，在仲裁器中按三相均分。

## 11. 24 小时计划充放电

### 11.1 当前小时参数

`scheduleSelect` 按本地整点小时选择：

- `400..423`：0 至 23 时计划功率
- `424..447`：0 至 23 时计划目标 SOC
- `760..783`：0 至 23 时计划模式
- `461`：当前小时计划功率
- `462`：当前小时计划目标 SOC
- `700148`：当前小时计划模式内部虚拟点

不做小时之间的线性插值。当前小时引用点缺失时，保留上一周期输出。

### 11.2 方向判断

当前图实际只使用功率正负和 SOC 判断：

```text
461（当前计划功率） > 0
AND 1570（BMS 堆 SOC） < 462（当前计划目标 SOC）：进入计划充电

461（当前计划功率） < 0
AND 1570（BMS 堆 SOC） > 462（当前计划目标 SOC）：进入计划放电

其他：当前分相输出按 2 * GradP 向 0 衰减
```

> 当前计划模式点 `760..783` 会被读取到 `700148（当前计划模式内部虚拟点）`，但没有后续节点消费。也就是说，当前计划方向由 `461（当前计划功率）` 的正负决定，模式字段暂不参与执行判断。

### 11.3 分相渐变

设：

```text
Ptarget = abs(461（当前计划功率）)
Pprev_i = 上一周期 615/616/617（A/B/C 相计划有功输出）
PprevTotal = 上一周期 618（计划三相有功绝对值之和）
GradP = 533（功率调节步长）
```

计划充电：

```text
当 PprevTotal < Ptarget - 1
且 Uavg_i > 464（计划充电电压下限）：
    Pprovisional_i = Pprev_i + GradP
否则：
    Pprovisional_i = Pprev_i
```

计划放电：

```text
当 PprevTotal < Ptarget - 1
且 Uavg_i < 463（计划放电电压上限）：
    Pprovisional_i = Pprev_i - GradP
否则：
    Pprovisional_i = Pprev_i
```

不满足充放电方向时：

```text
Pprev_i > 0：Pdecay_i = max(Pprev_i - 2 * GradP, 0)
Pprev_i < 0：Pdecay_i = min(Pprev_i + 2 * GradP, 0)
```

### 11.4 总功率和平均电压限制

如果三个临时分相功率绝对值之和超过 `Ptarget`，每相先限制到：

```text
PphaseTarget = Ptarget * 0.3333
```

随后按平均电压再退一步：

```text
充电且 Uavg_i < 464（计划充电电压下限） - 1：
    P_i = max(P_i - GradP, 0)

放电且 Uavg_i > 463（计划放电电压上限） + 1：
    P_i = min(P_i + GradP, 0)
```

### 11.5 瞬时电压降额和最终限幅

```text
充电且 Uinstant_i < 464（计划充电电压下限）：P_i = P_i * 0.8
放电且 Uinstant_i > 463（计划放电电压上限）：P_i = P_i * 0.8

P_i = clamp(P_i, -535（PCS 单相有功上限）, 535（PCS 单相有功上限）)
```

最终输出：

- `615..617`：A/B/C 相计划有功输出
- `618`：计划三相有功绝对值之和，等于 `abs(615)+abs(616)+abs(617)`
- `618（计划输出总量）!= 0` 时 `18（计划曲线运行反馈）=1`

## 12. 循环充放电测试

`powerConstraint` 按固定顺序处理 `700308..700313（强制满充覆盖后的 A/B/C 相 P/Q）`，输出 `627..632（PCS A/B/C 相最终 P/Q 目标）`。

                  453（当前正向功率限制值）

### 22.2 台区反向限制

### 22.3 动态增容

按第 16 节公式执行，可能进一步把有功拉向负方向。

### 22.4 单相 P/Q 绝对值限制

```text
abs(P_i) <= 535（PCS 单相有功上限）
abs(Q_i) <= 504（PCS 单相无功上限）
```

限制值小于等于 `0` 时，该项绝对值限制不生效。

### 22.5 视在功率限制

```text
SphaseMax = 151（PCS 总视在功率上限） / 3
```

如果 `sqrt(P_i^2 + Q_i^2) > SphaseMax`，优先保留 Q，收缩 P：

```text
P_i = sign(P_i) * sqrt(max(0, SphaseMax^2 - Q_i^2))
```

### 22.6 BMS 总允许充放功率

```text
sum(P_i) > 0 且超过 1552（BMS 最大允许充电功率）：
  按比例缩小所有正有功分量

sum(P_i) < 0 且绝对值超过 1553（BMS 最大允许放电功率）：
  按比例缩小所有负有功分量
```

正负分量同时存在时，比例计算会保留反方向分量的影响，使最终总功率不越界。

### 22.7 SOC 限制

普通 SOC 上限读取 `161（BMS SOC 上限）`；强制满充运行时临时改为 `100%`。SOC 下限读取 `162（BMS SOC 下限）`。

```text
1570（BMS 堆 SOC） < 162（BMS SOC 下限）：
           禁止所有负有功，即禁止放电
           清零所有无功
           清 8（COS 运行反馈）和 10（低压治理运行反馈）

1570（BMS 堆 SOC） > 当前 SOC 上限：
           禁止所有正有功，即禁止充电
           清 12（高压治理运行反馈）和 22（光伏运行反馈）
```

判断使用严格 `<` 和 `>`，等于边界时不会触发禁止。

## 24. 引擎通用计算和判断节点

以下为解释器支持的通用规则，当前或后续策略图可复用。

### 24.1 `formula`

| 运算 | 规则 |
| --- | --- |
| `add/sum` | 全部输入求和 |
| `subtract` | 第一个输入依次减后续输入 |
| `multiply` | 全部输入相乘 |
| `divide` | 普通除法，除零报错 |
| `safeDivide` | 除数接近零时输出 `zeroDivisorValue`，默认 `0` |
| `min/max/average` | 最小、最大、平均 |
| `abs/negate/square/sqrt` | 绝对值、取负、平方、开方 |
| `acos/tan/sin/cos` | 三角函数，输入输出使用弧度 |
| `clamp` | 限制在动态或固定上下限之间 |

`sqrt` 负输入和 `acos` 越界可按 `invalidPolicy=skip` 跳过，否则记录节点错误。

### 24.2 `switch`

支持两种形式：

- `conditionIndex != 0`：非零选 true，零选 false。
- 左值和右值比较后选择 true/false。

比较符：`gt/gte/lt/lte/eq/ne`。`eq/ne` 支持容差，默认 `1e-9`。

### 24.3 `controlGate`

- `combine=all`：全部条件通过才输出 `1`。
- `combine=any`：任一条件通过即输出 `1`。
- 任一必要输入缺失时保守输出 `0`。
- 每条条件可配置 `invert=true` 取反。

### 24.4 `windowAggregate`

支持 `average/sum/min/max`，窗口范围 `1..4096`。窗口按有效执行样本数计数，不按绝对时间长度计数。

### 24.5 `scheduleSelect`

- 按边端本地小时选择计划项。
- 不插值。
- 可从常量或共享内存 index 读取功率、SOC、模式。
- 引用点缺失时保留旧输出。
- 可用两个 16 位掩码控制 24 个小时的使能。

### 24.6 `sequence`

- 状态值写入共享内存虚拟点。
- 转移支持 `all/any` 条件和最短驻留时间。
- 状态和进入时间持久化到 Graph 状态文件。
- 转移输入无效时保持当前状态。

### 24.7 `rateLimit`

```text
上升：每秒最多增加 risePerSecond
下降：每秒最多减少 fallPerSecond
```

输出还受 `minValue/maxValue` 限制，运行状态可持久化。当前工厂图未使用。

### 24.8 `hysteresis`

```text
input >= highThreshold：置位
input <= lowThreshold：复位
中间区域：保持原状态
```

输入无效时保守复位。当前工厂图未使用。

### 24.9 `debounce`

- `onDelayMs`：输入持续为真后才置位。
- `offDelayMs`：输入持续为假后才复位。
- 输入无效时立即进入保守关闭状态。
- 当前工厂图未使用。

### 24.10 `feedbackVerify`

输出状态：

| 值 | 含义 |
| ---: | --- |
| `1` | 反馈与目标在容差内一致 |
| `0` | 等待反馈 |
| `-1` | 等待超时 |
| `-2` | 目标无效 |

当前工厂图未使用，因此普通 PCS 六路输出当前没有 Graph 内部写后反馈闭环。

## 25. 并机调度和 AGC/AVC 边界

### 25.1 `clusterDispatch`

解释器已经支持并机调度节点，可检查：

- 并机使能、Leader/Follower 角色。
- 法定多数派是否成立。
- 调度结果是否有效。
- 调度原因码是否合法。
- 调度 P/Q 是否在 `maxTargetAgeMs` 内。
- 站级策略是否由当前 Leader 执行。

输入无效时可清零并机候选并输出原因码。但当前 `shuntong_ems_graph.json` 中没有 `clusterDispatch` 节点，因此并机调度尚未进入当前 487 节点生产图，也没有参与 `phaseArbiter`。

### 25.2 AGC/AVC

AGC/AVC 当前是独立 `runtimeMode=agc_avc` 模块，使用 `agc-avc-service.json` 和独立控制器，不属于本 Graph EMS 2.0 工厂运行图。它的容量分配、频率/电压/功率因数控制和 PCS 水位分配规则见 `doc/需求说明/边端AGC_AVC独立模块设计.md`。

## 26. 当前实现需要明确的风险和约束

1. 普通 PCS 六路功率写节点默认 `submitWrites=false`，当前默认只能计算，不能据此宣称 PCS 已由 Graph EMS 自动控制。
2. COS、低压、高压、计划、光伏、三相平衡没有独立使能点；运行依赖 Profile、目标值、SOC、时间窗和阈值。
3. `760..783（0 至 23 时计划模式）` 已读取但未参与当前策略判断，功率正负才决定充放电方向。
4. 循环测试仍要求 `1279（旧厂家 BMS/CMS 工作状态字）` 命中特定厂家状态码，与新盛弘协议“1279 无明确等价点”的结论冲突。
5. 受控覆盖没有读取 `25（受控模式使能）`；只要 `590（受控总有功目标）/591（受控总无功目标）` 任一非零，就会令 `26（受控模式运行反馈）=1` 并覆盖其他策略。
6. 强制满充启动门不检查手动充放电、动态增容和受控覆盖运行反馈。
7. PCS 自动复位写 `1` 后没有独立的脉冲清零状态机，需要确认驱动或设备反馈行为。
8. `STATION_LIMIT_V2` 默认关闭，`453（正向限制值）/454（正向限制使能）/457（反向限制值）/458（反向限制使能）` 是否有效取决于工程已有点值或外部配置。
9. 并机协议与当前 Graph EMS 的有功符号相反，未转换前禁止直接接入生产 PCS 仲裁。
10. AGC/AVC 是独立运行模式，不应与当前 Graph EMS 同时争夺同一 PCS 控制所有权。

## 28. 结论

当前 EMS 2.0 已经把旧固化策略拆成可执行图，完成了平均值、负荷派生、BMS 功率、COS、低压、高压、手动充放电、计划曲线、循环测试、光伏、三相平衡、受控覆盖、动态增容、强制满充、节能启停、统一仲裁和最终功率限制。

但“计算完整”和“真实闭环控制”需要区分：工厂默认普通 PCS 功率写入关闭，可选真实写策略也全部由 Profile 默认关闭。上线前必须按项目确认写入所有权、设备协议点位、`1279（旧厂家 BMS/CMS 工作状态字）` 兼容性、计划模式语义、并机功率符号和写后反馈链路。
