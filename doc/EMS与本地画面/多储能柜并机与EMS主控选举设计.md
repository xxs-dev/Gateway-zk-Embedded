# 多储能柜并机与 EMS 主控选举设计

## 1. 目标与边界

本设计用于多个独立储能柜组成一个并机组。每个柜均保留自己的 EMS、PCS、BMS、采集驱动和本地安全链路，系统自动完成：

1. 有线或无线局域网发现。
2. EMS 主控选举和故障切换。
3. 基于 `machineCode` 的稳定自动编号。
4. 站级有功、无功和分相目标在多个柜之间分配。
5. 网络、主控或单柜故障时安全退出，避免多个 EMS 同时按站级目标独立调节。

本设计中的“负载低”已经确认指 EMS 所在主机的计算和控制处理负载，不是储能柜电气负荷。电气负荷、SOC 和可用功率用于目标分配，不应直接决定谁成为主控，否则策略动作会反过来触发主控切换。

首期支持最多 `5` 个储能柜，主要使用场景为 `2-3` 个柜。成员协议仍保留扩展字段，但第一版测试和容量边界均按 `5` 个节点验收。

并机策略在执行端只保留 `0=停用`、`1=启用`。发布前禁止写回测试由独立测试工具完成，不增加“影子运行”状态。

## 2. 总体架构

新增独立进程 `EmsClusterCoordinator`，只负责组网、选举、编号、状态同步和目标分配。它不解析设备协议，也不直接写 PCS。

```mermaid
flowchart LR
    A["柜 1 采集与本地共享内存"] --> C1["EmsClusterCoordinator"]
    B["柜 2..N 采集与本地共享内存"] --> C2["各柜 Cluster Coordinator"]
    C1 <-->|"KECP/1 有线或无线局域网"| C2
    C1 --> D["主控站级策略与容量分配"]
    D --> E["各柜分配目标"]
    E --> F["各柜 Cluster 虚拟点"]
    F --> G["phaseArbiter"]
    G --> H["powerConstraint"]
    H --> I["现有 PCS 写回与反馈校验"]
```

职责划分：

| 模块 | 职责 | 禁止行为 |
| --- | --- | --- |
| `EmsClusterCoordinator` | 发现、心跳、选举、编号、成员状态、目标分配 | 不直接写驱动，不绕过本地安全限制 |
| 主控 `ComputeEngine` | 计算站级计划、AGC/AVC、防逆流、调压和三相治理目标 | 不直接操作远端 PCS |
| 从控 `ComputeEngine` | 接收本柜目标，参与本地仲裁和安全限制 | 不重复执行站级策略 |
| 本地驱动 | 消费 `PendingWriteCommand` 并反馈结果 | 不接受无当前任期和超时的集群命令 |
| 平台 | 配置、监测、审计 | 不参与实时选举，不作为并机运行依赖 |

## 3. 通讯方式

### 3.1 网络选择

首期只使用专用有线以太网。当前现场没有独立无线网络，不能把 Wi-Fi 作为第一版依赖。

- `ens0` 继续作为固定维护口，默认不承载并机控制。
- `ens2` 作为默认并机口；也允许在本地 EMS 屏幕选择其他实体网口。进入并机模式时必须移除该口的出厂固定 IPv4。
- 并机网使用独立子网，不配置默认网关和 DNS，不影响 4G、MQTT、EasyTier 或维护路由。
- 默认使用 RFC 3927 IPv4 Link-Local 自动地址 `169.254.0.0/16`，不需要 DHCP 服务器。静态地址模式建议使用 `172.22.240.0/24`，首批设备可使用 `.11-.15`。
- IP 与柜号相互独立，主控切换和自动编号时不更改 IP。
- 两柜可使用一根网线直接连接；三到五柜优先接入独立工业交换机。
- 无交换机时可以把每柜两个实体口组成 `br-cluster` 做链式连接，但任一中间柜断电都会切断后续节点，只作为临时方案。
- 所有柜的 `ens2` 出厂静态地址相同，禁止直接接入同一个并机网络。集群服务发现并机口仍为出厂地址时必须拒绝启动并明确告警。

自动地址流程：

1. 操作员在本地屏幕把 `ens2` 用途切换为“并机口”。
2. 系统备份原出厂地址并移除 `192.168.3.250/24`。
3. 根据 `machineCode + MAC` 生成稳定的 `169.254.x.x` 候选地址。
4. 发送至少 3 次 ARP Probe 做 Duplicate Address Detection。
5. 冲突时更换 salt 重新生成，成功后持久化本机地址。
6. 地址就绪后才启动 KECP/1 发现、选举和自动柜号。

集群身份始终使用 `machineCode` 和证书，不把 Link-Local IP 当成永久身份。地址文件损坏或网卡更换后允许重新选址，但不会造成柜号重排。

- 发现：UDP 组播，建议端口 `37680`。
- 选举、成员同步、调度和反馈：持久 TCP 连接，建议端口 `37681`。
- 组播不可用时：使用配置的 `seedPeers` 做单播发现。
- 第一版节点数量限制为 `2-5`，节点之间建立去重后的全连接，规模可控。
- 默认只绑定明确选中的 `ens*` 或 `eth*`，不允许集群控制流量走 `usb0`、4G 或公网 EasyTier。

### 3.2 后续蓝牙和 LoRa 扩展

通讯层定义统一的 `IClusterTransport`，第一版实现 `EthernetTransport`，后续可以增加：

- `BluetoothProvisionTransport`：用于发现、配网、IP 设置和现场维护。
- `BluetoothClusterTransport`：只有在实测延迟、重连和多节点稳定性满足要求后，才允许承载完整调度。
- `LoRaSafetyTransport`：只传输任期、主控身份、失联停机和少量应急状态，不承载 1 秒级 P/Q 调度和全量能力数据。

LoRa 带宽、占空比和时延不适合当前 `1000 ms` 调度周期。蓝牙若使用 PAN/BNEP 形成 IP 网络，可以继续复用 KECP/1；BLE GATT 或 LoRa 则使用同样的消息语义，但需要独立分帧和重传适配。后续要完全替代网线，优先评估 Wi-Fi Direct、`802.11s` 或工业无线网桥，它们比 LoRa 更适合持续并机控制。

任何无线基础设施都不能绑定到当前策略主控身份。通信节点和策略主控必须分离，避免主控切换同时导致全网掉线。

### 3.3 安全模式

目标协议支持：

- `mtls`：默认推荐，复用设备初始化得到的证书。
- `psk`：离线项目使用项目级组密钥。
- `none`：仅允许物理隔离的调试网络，Win 端必须明确提示风险。

无线链路默认不允许 `none`。

当前实现开放 `psk/none`，其中 `psk` 使用 KECP/1 帧级 HMAC-SHA256，`none` 仅用于回环或物理隔离实验网。只要 `controlEnabled=true`，配置校验就强制要求 `securityMode=psk`；不能在无认证模式下开启调度。`mtls` 仍是后续证书化增强项，当前程序会明确拒绝未实现的 `mtls`，不能静默降级。

## 4. KECP/1 协议

协议名称：`KY Energy Cluster Protocol v1`，简称 `KECP/1`。

### 4.1 帧头

| 字段 | 说明 |
| --- | --- |
| `magic/version/type/flags` | 协议识别、版本和消息类型 |
| `payloadLength` | 负载长度，拒绝超限帧 |
| `clusterIdHash` | 防止不同项目互相加入 |
| `term` | 当前选举任期，作为第一层 fencing token |
| `membershipEpoch` | 已提交成员表版本 |
| `sequence` | 同任期内严格递增序号 |
| `senderNodeId` | `machineCode` 的稳定标识 |
| `crc32` | 非 TLS 调试下的传输错误检测 |

负载使用固定字段、网络字节序的紧凑二进制编码，不使用 JSON 或 CBOR；当前帧版本为 `2`，状态文件提供等价 JSON 便于排障。每帧上限为 `64 KiB`。租约统一以接收端单调时钟记录到达时间，不依赖发送端墙上时间。

### 4.2 消息类型

| 类型 | 用途 |
| --- | --- |
| `DISCOVER/HELLO` | 广播节点身份、协议版本和集群摘要 |
| `HEARTBEAT/HEARTBEAT_ACK` | 主控租约、节点负载和链路质量 |
| `VOTE_REQUEST/VOTE_REPLY` | 任期内选举 |
| `LEADER_COMMIT/STEP_DOWN` | 提交主控或主动让位 |
| `MEMBERSHIP_PROPOSE/COMMIT` | 柜号和成员表变更 |
| `CAPABILITY_REPORT` | 从柜上报 SOC、额定能力、可充放功率、闭锁和反馈 |
| `DISPATCH_TARGET/DISPATCH_ACK` | 主控下发本柜 P/Q 目标，从柜返回接受值和拒绝码 |
| `FEEDBACK` | 从柜周期返回实际三相 P/Q 和当前能力 |

解码器只接受上表中的已知类型、已知调度码和正确认证帧，未知值直接拒绝。调度消息只有在 `controlEnabled=true`、PSK 校验通过、任期和成员版本一致时才生效；`controlEnabled=false` 时仍可独立运行发现、选举和编号。

所有调度帧必须包含 `term + leaderNodeId + membershipEpoch + dispatchSequence + deadlineMs`。从控拒绝旧任期、旧序号、错误主控、成员版本不一致和已超时命令，并返回中文可映射的拒绝码。

## 5. 主控选举

### 5.1 候选资格

节点同时满足以下条件才可成为主控：

1. `machineCode` 唯一，集群配置和协议版本一致。
2. EMS、共享内存和 ComputeEngine 正常；第一阶段以 ComputeEngine 新鲜健康文件作为候选门槛。
3. 本机 PCS/BMS 关键通讯、急停、消防闭锁、人工接管只决定本柜是否接受调度，不参与主控选举。
4. 系统时间是否准确不影响租约；单调时钟正常。
5. CPU、内存、策略周期超时和控制队列未超过硬阈值。
6. 至少有一条允许的集群网络链路。

### 5.2 低负载评分

目标版本使用 30 秒 EWMA，分数越低越优：

```text
loadScore = 35% × CPU 使用率
          + 15% × 内存使用率
          + 25% × EMS 周期超时率
          + 15% × 控制队列 P95 延迟归一值
          + 10% × 集群链路丢包率
```

当前已经读取 CPU、内存、ComputeEngine 周期超时率和控制队列 P95；健康文件超过 `5 s` 未更新即按 ComputeEngine 不健康处理。链路丢包率和 30 秒 EWMA 仍是后续优化项，当前丢包项按 `0` 计入，选举只在没有有效主控时发生，因此不会因瞬时评分主动抢占。

低负载只在需要选举时决定候选顺序。已有健康主控不会因为另一节点瞬时低 `5%` 就被抢占。仅在以下情况重新选举：

- 主控租约失效。
- 主控关键服务或安全输入异常。
- CPU 超过 `85%` 或策略周期超时率超过 `20%` 持续 `30 s`，主控主动移交。
- 操作员执行“重新选举”。

主动移交要求新候选分数至少优于当前主控 `10` 分，并设置默认 `5 min` 的主控保持时间，防止来回切换。相同分数按 `electionPriority`、再按 `machineCode` 排序。

### 5.3 任期、租约和多数派

1. 心跳周期默认 `250 ms`，连续 `5` 次未收到有效心跳后进入选举。
2. 候选按负载排名设置不同启动延迟，并发送新 `term` 的投票请求。
3. 每个节点每个任期只投一票。
4. 获得 `floor(N/2)+1` 票后才能发送 `LEADER_COMMIT`。
5. 主控只有持续获得多数派 ACK 才能续租；失去多数派后必须停止生成新调度。
6. 租约和命令超时全部使用单调时钟，墙上时间只用于日志。

两个柜时多数派为 `2`。网络分区后任何单柜都不能继续作为并机主控，只能进入配置的本地安全回退。这牺牲部分可用性，但避免双主控。需要单节点继续并机控制时，必须增加第三个独立见证节点，不能仅靠 `machineCode` 大小判断。

## 6. 自动标号

`machineCode` 是永久身份，`cabinetNo` 只用于现场显示和策略分配，不作为通讯地址或共享内存 Index。

1. 首次形成多数派后，主控按 `electionPriority + machineCode` 建立初始编号。
2. 编号映射以 `membershipEpoch` 版本提交给多数派，并原子落盘为 `cluster-membership.json`。
3. 节点重启、主控切换或链路切换不重新编号。
4. 新节点取得最小空闲编号；离线节点编号默认保留 `24 h`。
5. 删除节点或立即复用编号必须由 Win/平台明确确认。
6. 支持 `lockedCabinetNo`，但重复锁定编号时两个冲突节点都不得进入控制成员集。
7. 重复 `machineCode` 的节点进入 `Quarantined`，不能投票、不能接收调度。

新主控只有拿到多数派已提交的编号表才可继续调度，不能根据当前在线列表临时重排。

## 7. 并机策略

### 7.1 站级和柜级逻辑

站级策略只在主控计算一次：计划曲线、AGC/AVC、光伏防逆流、台变正反向过载、高低电压和站级三相平衡。各从控不得再次独立执行同一站级目标。

每个柜始终保留本地逻辑：BMS/PCS 通讯、SOC、温度、电流、急停、消防、额定功率、P/Q 包络、爬坡和写回反馈。

主控自己也必须通过“分配目标 -> 本柜虚拟点 -> 本地仲裁 -> 本地安全限制”的相同路径执行，不能使用特殊直写路径。

### 7.2 容量分配

复用现有 `AgcAvcController` 的容量分配算法，将每个储能柜视为一个逻辑 PCS：

- 充电优先 SOC 较低且可充功率大的柜。
- 放电优先 SOC 较高且可放功率大的柜。
- 受额定 P/S、BMS 允许功率、温度、电流、最小稳定功率和爬坡限制。
- 某柜限幅后的剩余目标使用迭代水位法重新分配。
- Q 目标在分配 P 后按 `sqrt(S²-P²)` 计算剩余无功能力。
- 三相目标按 A/B/C 分别分配，合相目标先由主控按能力拆分到各柜，再由各柜按 PCS 能力执行。

从控 ACK 必须返回“请求目标、接受目标、本地限幅原因”。主控按实际接受量重新分配，不把发送成功当成设备执行成功。

### 7.3 控制所有权

协调器不直接取得 PCS 写权限，也不创建 `PendingWriteCommand`。它只把通过任期、成员版本、序号、TTL 和本地能力校验的目标写入独立 `ems_cluster_store`。`clusterDispatch` 节点再把有效目标送入现有 `phaseArbiter -> powerConstraint -> PCS 写回` 链，因此最终写入继续受 ComputeEngine 的 `PowerControlOwnership`、可写性、队列容量和高优先级人工控制约束。人工接管期间本柜上报 `manualOverride=1` 并拒绝调度，释放后必须接收新序号目标，不能恢复旧命令。

## 8. 虚拟点建议

预留 `724000-724999`。每个柜使用相同 Index 表示本柜状态，完整成员表通过集群状态接口和 MQTT 上报，不把动态 N 个柜全部展开成固定本地点表。

| Index | 名称 |
| ---: | --- |
| `724000` | 并机策略启用，`0/1` |
| `724001` | 本机集群状态：离线/发现/从控/候选/主控/隔离/故障 |
| `724002` | 本柜自动编号 |
| `724003` | 当前任期 |
| `724004` | 在线成员数 |
| `724005` | 多数派有效 |
| `724006` | 主控柜号 |
| `724007` | 本机负载评分 |
| `724008` | 当前链路：有线/无线 |
| `724009` | 主控 RTT |
| `724010` | 配置与语义版本一致 |
| `724020-724028` | 本柜 SOC、额定 P/S、可用充放电/无功能力、控制就绪、闭锁和人工接管 |
| `724030-724035` | 分配到本柜的三相 P/Q 目标 |
| `724040-724045` | 本柜实际三相 P/Q 反馈 |
| `724050` | 最近调度结果 |
| `724051` | 最近拒绝/闭锁原因 |
| `724052` | 本机是否为可运行站级策略的有效主控 |
| `724053` | 最近调度序号 |
| `724060-724065` | 主控 Graph EMS 生成的站级三相 P/Q 总目标，六点必须同周期刷新 |

## 9. 故障行为

| 场景 | 行为 |
| --- | --- |
| 主控进程退出 | 租约到期后多数派重新选举，目标序号和任期重新开始 |
| 从控离线 | 主控剔除其可用能力并把剩余目标重分配给健康柜 |
| 从控失去网络 | 当前命令 TTL 到期后按配置爬坡到 0 或切回批准的本地安全策略 |
| 网络分区 | 只有多数派分区可以继续；少数派停止并机调度 |
| 两柜互相失联 | 两边都停止并机调度，不允许各自成为单节点主控 |
| 主控过载 | 完成本周期后主动移交，旧主控释放所有权再降为从控 |
| 配置或语义版本不同 | 节点只观察、不投票、不接收控制 |
| 柜号或 machineCode 冲突 | 节点隔离并告警，不自动覆盖 |
| 高优先级人工控制 | 集群释放本柜控制并暂停重分配，待控制结束后重新读取反馈 |

默认调度周期为 `1000 ms`，命令 TTL、能力 TTL 和站级目标 TTL 均为 `3000 ms`。`clusterDispatch` 默认在输入无效或过期时立即把本柜候选目标清零；消防、急停和硬件保护仍可在更下层立即归零。


### 10.1 EMS 屏幕网卡设置

KY-EMS 新增独立“网络与并机”页面，不能把网卡参数混在普通设备点表中。页面至少包括：

| 区域 | 内容 |
| --- | --- |
| 网卡列表 | `ens0-ens3`、MAC、物理连接、协商速率、当前 IP、收发流量 |
| 用途 | 维护口、并机口、业务上行口；同一网卡冲突时禁止保存 |
| 地址模式 | 自动 Link-Local、静态、DHCP；并机口默认自动 Link-Local |
| 静态参数 | IPv4、前缀长度；并机口默认不填写网关和 DNS |
| 并机检测 | 本机端口监听、组播、已发现节点、RTT、丢包、重复 IP |
| 操作 | 校验、应用、恢复上次配置、恢复出厂网络 |

应用链路：

```text
KY-EMS 本地页面
  -> SystemMonitor 本地 Unix Socket
  -> NetworkConfigService 权限校验
  -> 备份现有配置
  -> 移除并机口出厂固定 IP
  -> ARP DAD / 子网 / 网关冲突检查
  -> 原子写入 interfaces.json
  -> 应用系统网络配置
  -> 60 秒倒计时确认
  -> 未确认或并机探测失败则自动回滚
```

KY-EMS 不以 root 身份直接执行 shell。`NetworkConfigService` 只接受本机 Unix Socket，请求中必须指定接口名、旧配置摘要和新配置，拒绝 `usb0`、`lo`、EasyTier 虚拟口及不存在的接口。

首期安装流程：每个柜暂不接入并机网，操作员在本柜屏幕把 `ens2` 切换为“并机口/自动 Link-Local”，确认出厂固定 IP 已移除后再接线。需要固定地址的项目可改用 `172.22.240.11-15/24`；系统只给出地址建议，不让 IP 跟随自动柜号改变。

Win 端操作链：

1. 新建并机组，填写组名、预期柜数、并机网卡和安全模式。
2. 搜索或录入各柜 `machineCode/IP`，检查版本和语义模板一致性。
3. 下发仅包含通讯配置的集群工程，保持 `724000=0`。
4. 查看实时拓扑、负载评分、选举结果和自动编号，允许锁定柜号。
5. 执行独立“禁止设备写回”联调测试并导出报告。
6. 校验站级测量源、功率方向、每柜额定 P/S、SOC 和 BMS 限制。
7. 二次确认后设置 `724000=1`，从小功率开始真实并机。

平台维护模板、组配置、拓扑和审计，但边端在平台断线时仍能完成选举和并机运行。

## 11. 现有储能柜设计审计

本节是开始并机实现前，对当前边端 EMS、控制、共享内存、网络和部署链路的审计结果。结论不是要求重写现有采集驱动，而是给并机功能划出不能越过的安全边界。

### 11.1 已具备的基础

1. 各采集驱动按独立共享内存运行，`PointStoreRouter` 可以按全局 Index 汇总读写路由；并机协调器不需要修改协议解析。
2. `phaseArbiter -> powerConstraint -> PendingWriteCommand -> 写后反馈` 已形成柜内控制链，主控自己的目标也应继续走这条链。
3. `PowerControlOwnership` 能阻止同一柜内多个进程同时写同一批 PCS 目标，`PriorityControlLease` 能让人工高优先级控制暂停普通写入。
4. AGC/AVC 已具备多 PCS 容量、SOC、P/Q 包络和水位分配能力，第二阶段可把“每个柜”视为一个逻辑 PCS 复用算法。
5. `SystemMonitor` 已能采集 CPU、内存、负载和实体网卡状态，现有 4G/有线故障切换也有独立服务。

### 11.2 阻断并机控制的问题

| 级别 | 问题 | 风险 | 处理要求 |
| --- | --- | --- | --- |
| 已修复 | `PowerControlOwnership` 只是本机文件租约，不包含集群任期和多数派信息 | 网络分区或主控切换时，两个柜可能各自在本机成功取得所有权 | 集群入口已校验 `term + leaderNodeId + membershipEpoch + dispatchSequence + TTL`，柜内文件锁继续作为第二层互斥 |
| 阻断 | 站级策略和柜级策略当前没有显式作用域 | 从控可能继续计算防逆流、调压、三相平衡，与主控下发目标叠加 | 第二阶段给策略增加 `scope=station/cabinet`，从控屏蔽站级输出，柜级保护始终保留 |
| 阻断 | 主控切换缺少“旧目标失效 -> 爬坡归零 -> 新任期接管”的完整状态机 | 旧目标可能在 TTL 内继续生效，新主控同时下发造成短时双写 | 调度目标必须带单调时钟 TTL；新任期接管前读取实际反馈，旧任期目标只能归零、不能续期 |
| 阻断 | 公共并网表、台变表只有单柜采集时是单点数据源 | 数据源柜离线后，主控仍可能依据过期数据执行站级控制 | 配置中必须声明 `stationMeasurementOwner`、质量、最大时效和备用源；没有健康公共测量时停止相关站级策略 |
| 已修复 | ComputeEngine 周期耗时、超时率和写队列 P95 原先不可见 | 只凭 CPU/内存无法选出真正低控制负载的主控 | 已输出原子健康文件；缺失或超过 `5 s` 未更新时视为不健康，不允许成为或继续担任主控 |
| 阻断 | 两柜没有第三方见证时无法同时满足可用性和防双主 | 断线后若允许单柜继续，会出现两个主控 | 第一版固定多数派语义，两柜失联双方退出并机控制；需要持续运行时增设见证节点 |

### 11.3 第一阶段必须同时修复的问题

1. **并机口和上行口冲突**：现有网络故障切换配置包含 `wiredInterfaces: ["ens1", "auto"]`，`auto` 会枚举 `ens2`。启用并机后必须把 `clusterInterface` 从有线出口候选、默认路由和 DNS 配置中强制排除。
2. **服务生命周期遗漏**：`gateway-services.sh`、安装脚本、OTA 停启列表必须认识 `EmsClusterCoordinator`，但仅在 `runtimeMode=ems && emsCluster.enabled=true` 时启动。它不是新的互斥 `runtimeMode`。
3. **地址冲突**：检测到并机口仍有 `192.168.3.250/24` 时拒绝启动。自动 Link-Local 只能由明确的网络应用操作执行，协调器不能在普通重启时静默改 IP。
4. **身份冲突**：同一个 `machineCode` 配合不同系统 `bootId` 同时出现时，相关节点进入隔离；进程重启不能被误判为重复设备。
5. **成员状态持久化**：任期、投票和已提交柜号表必须原子落盘。IP、柜号和共享内存 Index 彼此独立，任何重新选址或主控切换都不得重排 Index。
6. **配置重载边界**：修改集群 ID、预期成员、安全模式或并机网卡属于集群重启操作；普通点表重载不应重启或自动启用并机服务。
7. **协议安全边界**：UDP 发现结果只能作为候选地址，不能直接授予成员资格。`none` 只允许物理隔离测试网，真实调度强制 PSK；协议只携带柜级 P/Q 候选目标，不携带设备协议写帧或设备写密码。

### 11.4 可延后但必须在真实控制前完成

1. 高优先级人工控制已经可通过 `724028` 让本柜拒绝新调度；仍需在 Win/KY-EMS 中补齐“暂停分配、确认本柜输出、释放后重新读取反馈”的完整操作和审计界面。
2. 本地时间可跳变，而现有部分文件租约使用墙上时间。集群租约和调度 TTL 必须只用单调时钟；墙上时间仅用于日志。
3. KY-EMS 尚无受限的网卡配置服务。最终应通过本地 Unix Socket 和白名单化特权 helper 应用配置，并提供 60 秒确认回滚，界面进程不能直接执行任意 shell。
4. mTLS 身份校验、证书轮换、项目级 PSK 更新和审计需要在控制阶段启用前完成。
5. 消防、急停、BMS 禁充禁放必须保持纯本地硬闭锁。集群网络恢复、主控恢复或人工操作都不能覆盖这些状态。

### 11.5 审计后的第一阶段验收边界

第一阶段允许：地址预检、节点发现、TCP 会话、心跳、负载评分、任期投票、多数派租约、稳定柜号、状态文件和故障模拟。

第一阶段禁止：创建 `PendingWriteCommand`、取得 PCS `PowerControlOwnership`、修改 `724000` 启用点、运行站级功率分配、改变现有策略启停状态。即使协议收到未知或伪造的调度类型，也必须拒绝且不能转入共享内存。

### 11.6 第一阶段当前实现

截至 2026-08-06，已实现：

1. `EmsClusterCoordinator` 独立进程、`ems-cluster@.service` 和按配置启停的服务生命周期。
2. UDP 组播/种子节点发现、TCP 长连接、64 KiB 帧上限、CRC32、PSK HMAC-SHA256 和错误帧拒绝。
3. 单调时钟心跳、任期、单任期单票、多数派 leader lease、少数派退位和健康主控不抢占。
4. ComputeEngine 周期超时率、周期 P95、控制写队列 P95 健康文件；指标缺失会提高负载分，不会按零负载参与。
5. 柜号提案、成员 ACK、多数派提交、任期/投票/柜号表原子持久化。
6. 重复 `machineCode + 不同 bootId` 隔离、配置哈希不一致只观察、出厂重复 IP 拒绝启动。
7. Link-Local 稳定候选计算、显式 `arping -D` 三次 DAD 和 `ip address replace` 入口；不写默认路由或 DNS。
8. 4G/有线故障切换自动排除已启用的 `emsCluster.clusterInterface`。
9. 2/3/5 节点、两柜断链、三柜分区、重启、身份冲突、错误 PSK 和真实回环 UDP/TCP 测试。
10. 远端 `lockedCabinetNo` 协议传播、重复锁号拒绝、过期未提交成员不占号、成员版本落后节点拒绝当选。
11. quorum 随已提交成员数动态取真实多数派；新发现柜先作为观察者，成员提案获得新旧多数派要求后才取得投票权。
12. 主控心跳携带已提交成员快照，落后从柜可自动补齐；普通服务启动忽略 `autoConfigureAddress`，只有显式 `--prepare-network` 才允许改并机口。

第二阶段已完成 `724xxx` 独立共享内存、能力上报、SOC 加权水位分配、三相 P/Q 包络、调度 ACK/反馈、过期清零和 Graph `clusterDispatch` 接入。真实 PCS 写入仍默认关闭，只有完成字段映射和安全验收后才允许同时设置 `controlEnabled=true` 与 `724000=1`。

仍未完成的产品化能力包括：mTLS、公共并网表主备源、Win/KY-EMS 完整并机配置页面、人工接管的跨进程可视化和多柜实机低功率验收。成员提案已经多数派 ACK 并通过心跳补齐，但仍建议持久化“已接受但未提交”的提案，进一步收窄主控在提交广播前掉电的恢复窗口。

## 13. 已确认项与剩余决策

已确认：

1. 主控按 EMS 计算和控制处理负载选择，不按柜体电气负荷选择。
2. 首期最多 `5` 柜，主要为 `2-3` 柜。
3. 首期使用专用网线，不依赖现场无线网络。
4. KY-EMS 本地屏幕需要直接配置实体网卡 IP。
5. 蓝牙和 LoRa 只保留后续传输适配边界，不进入第一版依赖。

实施前仍需确定：

1. 两柜互相失联时是否接受双方退出并机控制；本设计推荐接受。
2. 三到五柜现场是否可以增加独立工业交换机；不建议正式项目依赖链式软件桥。
3. 站级并网表、台变表等公共测量接在哪个柜，是否需要双表冗余。
4. 失联后的本地回退是爬坡到 `0`，还是切换到某个已经批准的单柜策略。
