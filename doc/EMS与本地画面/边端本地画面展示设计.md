# 边端本地画面展示设计

## 目标

边端本地画面用于在网关设备接显示器时直接展示共享内存中的实时数据。它不依赖 Java 平台在线，也不依赖 MQTT Broker 在线。

2026-06-30 起，生产本地屏幕统一走 Qt 组态运行时：

```text
KY-EMS(Qt Widgets) + KY-EMS-Config.xml + KY-EMS-PointMap + VarList.xml
```

`LocalDisplay + local-kiosk.py(WebKit2)` 保留为远程预览、调试和轻量点表浏览方案，不再作为 EMS 设备本地屏幕的生产主入口。现场测试已验证 WebKit 在全志平台上 CPU 占用过高，且布局无法一比一复刻现有 Qt 画面。

## 生产数据链路

```text
ModbusRtu / Dlt645Driver / DioDriver / CanDriver / ComputeEngine
        |
        | 写入最新值
        v
共享内存 PointStore
        ^
        | EmsPointProvider / QRamRT 读取
        |
KY-EMS Qt 组态运行时
        |
        | Qt Widgets 直接渲染
        v
本机显示屏
```

平台和 Windows 工具负责生成、编辑和下发配置；边端本地屏幕只读取本机配置和共享内存，不依赖平台在线。

## 服务职责

- `ky-ems.service`：启动 `/opt/modbus-gateway/ky-ems/KY-EMS`，作为生产 EMS 本地屏幕。
- `KY-EMS-Config.xml`：描述 Qt 页面控件和数据绑定关系。
- `KY-EMS-PointMap.example.json`：把 `meterCode + pointCode` 映射到当前项目实际共享内存 index。
- `VarList.xml`：兼容旧工程 `appDataIndex` 和历史 QRamRT 绑定。
- `LocalDisplay`：保留 HTTP/SSE 点位浏览、平台同步预览和调试接口。
- `local-kiosk.py`：仅在 `localDisplay.renderer=webkit` 时启动 WebKit 全屏展示。

## 配置结构

生产 EMS 本地屏幕在 app 配置中使用：

```json
{
  "localDisplay": {
    "enabled": true,
    "renderer": "nativeQt",
    "refreshIntervalMs": 1000,
    "sharedMemoryNames": ["gateway_point_store"],
    "qtRuntime": {
      "serviceName": "ky-ems.service",
      "home": "/opt/modbus-gateway/ky-ems",
      "binary": "/opt/modbus-gateway/ky-ems/KY-EMS",
      "layoutFile": "/opt/modbus-gateway/ky-ems/KY-EMS-Config.xml",
      "pointMapFile": "/opt/modbus-gateway/ky-ems/KY-EMS-PointMap.example.json",
      "varListFile": "/opt/modbus-gateway/ky-ems/VarList.xml"
    }
  }
}
```

服务编排规则：

- `localDisplay.enabled=false`：不启动本地画面。
- `localDisplay.enabled=true` 且 `renderer=nativeQt|qt|ky-ems|kyems`：启动 `ky-ems.service`。
- `localDisplay.enabled=true` 且 `renderer=webkit` 或未配置：启动 `local-display@monitor-service.service`，并按 `kiosk` 配置决定是否启动 `local-kiosk@monitor-service.service`。

## Qt 组态绑定规则

Qt 画面绑定优先级：

1. `KY-EMS-Config.xml` 控件声明 `meterCode + pointCode`。
2. `KY-EMS-PointMap.example.json` 解析到当前项目共享内存 index。
3. 找不到时使用 `indexFallback`。
4. 再找不到时兼容旧 `appDataIndex` / `VarList.xml`。
5. 仍找不到时，嵌入式生产构建显示 `--`，不显示 `.ui` 中的演示值。

`.ui` 默认值仅供 PC 模拟构建和布局验收使用。嵌入式二进制未完成真实绑定时不得显示伪造运行数据。

## Qt 页面路由约束

- 顶部主导航为唯一全局路由入口：首页、运行监测、故障预警、数据报表、参数设置。
- 运行监测二级导航只在监测上下文切换系统、PCS、BMS、动环消防、UPS 和 IO 页。
- 页面切换一律先隐藏当前页，再显示目标页，并同步顶部和二级导航高亮，不允许两个 `1920x1080` 页面叠加。
- 首页功率曲线是快捷路由，其返回按钮必须恢复首页完整图层和按钮命中层级。
- 页面路由和设备控制必须分离。设备控制按钮不得用跳转、假值或只改界面状态来代替真实写回。

这样可以避免旧项目 `appDataIndex` 固定绑定导致新项目点位重排后错位。

## 初始化与 OTA

出厂包可以携带 `ky-ems/` 目录：

```text
ky-ems/
  KY-EMS
  KY-EMS-Config.xml
  KY-EMS-PointMap.example.json
  VarList.xml
  dataStoreBases/
```

初始化时，如果项目驱动清单包含 `KY-EMS`，`install-factory-config.sh` 会安装整个目录到：

```text
/opt/modbus-gateway/ky-ems
```

并安装：

```text
/etc/systemd/system/ky-ems.service
```

OTA 白名单已允许下发 `/opt/modbus-gateway/ky-ems` 子目录文件和 `ky-ems.service`。后续可用 OTA 更新 Qt 可执行文件、XML 组态、PointMap、VarList 和图片资源。

## WebKit 保留用途

`LocalDisplay` 仍保留这些能力：

- `/api/health`：服务状态。
- `/api/pages`：画面列表。
- `/api/points`：可路由点位元数据。
- `/api/frame?pageCode=overview`：单帧数据。
- `/api/stream?pageCode=overview`：SSE 实时推送。

平台“本地画面”页面可以继续用同一份 `localDisplay.screens/widgets` 做预览和配置辅助，但生产 EMS 屏幕不再要求运行 WebKit。

## 生产约束

- 生产 EMS 屏幕优先使用 Qt，避免 WebKit 长时间高 CPU 占用。
- `KY-EMS-Config.xml` 中新增绑定应优先写 `meterCode + pointCode`，不要只写旧 `appDataIndex`。
- `PointMap` 必须跟随当前工程点表生成和下发。
- 本地屏幕按钮写入设备时必须走共享内存写队列和驱动写回机制，并校验点位可写属性。
