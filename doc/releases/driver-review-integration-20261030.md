# realese1.0 驱动审查回复与合并验证

日期：2026-10-30。

## 结论与范围

附件对旧基线的数据正确性、调度、控制结果语义风险的判断有依据，但不能把旧问题清单直接当作当前版本状态，也不能把模拟测试通过当作现场验收。

本轮开始时 GitHub、GitLab 的 `realese1.0` 均为 `d09d91f`。附件对应的修复实际在 GitLab `fix/driver-review`，末端为 `c829398`。本轮将该分支合入 `realese1.0`，同时保留主线原有 AM5 SOE/录波关联功能，并整理以下本地改动：

- `b9236d3`：HGM6110NC 发电机无效值、十进制累计量、点表准备和控制绑定工具。
- `7e304af`：EMS2 画面布局修正、PCS 远方/就地反馈与控制入口联锁。
- 合并适配：新 FT1.2 主站上的 SOE 持久化重试、录波目录关联及 HGM 扩展读类型校验。

`feat/maint-v2` 和独立的 `feature/soe-reporting-workflow` 未纳入本轮；不能据此声称已完成该独立分支的平台 SOE 上报工作。工程客户端独立仓库的 `fix/do-output-state` 也不在此次边端合并范围。

本轮不部署 103/104/108/163，不连接真实电气设备，不执行启停、分合闸、复位、功率或校时操作。

## 对六项决策的回复

1. **升级窗口**：采用关联生产者和消费者同窗升级，不是整机服务全部重启。按《共享待写队列升级规程》暂停命令入口、核清在途回执、确认 pending=0，再切换；EasyTier、4G、网络不动。不能让平台把所有失败或未知命令一律重发。只有确认未执行且业务仍需要时，才另行决定提交。
2. **后台 14.3 秒**：只接受为过载模拟结果，不接受为生产控制性能指标。先分别明确关键点、全点表和防逆流闭环要求，再测量、分组或拆线。不能把 PCS 的 20 ms 调度档位等同实际采样周期。
3. **广播校时**：保留时钟可信门槛，不为“能发出去”绕过检查。确认生产板 NTP/PTP/其他对时链路及可信标志，结合 `Dlt645Driver --time-sync-status` 判断未发送原因。
4. **CAN 状态文件**：称为“已请求状态”，不是设备真实反馈。缺少可信状态时只有明确声明 `write.can.templateSafe` 的模板才可作为起点；发送前后各一次持久化须纳入闪存写入预算。不能因为文件写盘成功就把设备动作判成功。
5. **去重回执**：同意保留 `writeback-mismatch` 与 `writeback-timeout/unconfirmed` 的区别，三者 outcome 都为 unknown；明确拒绝才是 failed。消费者需同时看 stage 与 outcome，不能仅凭 success=false 重发。
6. **DO 文案和告警**：边端新增持续反馈不一致告警，不补发动作。附件“KY-EMS 是二进制所以不能改”不适用于本仓库：这里有 Qt 画面源码和项目生成脚本，但这不等于所有部署中的画面都已升级，也不代表本轮已完成全站 DO 文案/反馈绑定验收。

## 需要纠正的口径

- 附件末尾“没有 TIOCSRS485/TIOCGRS485”是旧状态。新 `src/posix_serial_port.cpp` 已有可选设置及读回核验，默认关闭。是否启用必须依串口硬件、设备树和实际 RTS 方向确定。
- 当前通用陈旧判据默认是 `max(20 * 点位周期, 120000ms)`，并受原 TTL 上限约束，不是最初建议的 2–3 个周期。该默认值不能直接作为防逆流安全新鲜度阈值。
- 新旧共享队列布局版本号相同，不等于支持长期混跑。旧驱动回滚后仍使用旧的墙钟/结果语义，不能宣称跨任意版本混跑均安全。
- 采集调度改为单调时钟解决回拨冻结，不保证设备时标、事件排序、墙钟 TTL 和历史时间轴在校时后全部无影响。
- 同一 cmdId 可能先收到未知回执、再收到晚到结果；平台需要按 cmdId 更新状态，不应统计成两次执行。
- 模拟总线中的 30 ms 应答只是测试条件，不是现场测量值。2.2 秒等表格数值不可直接写进生产验收报告。

## 合并时额外处理

### HGM6110NC

保留 `read.invalidRawWords` 在缩放前拒绝不可用原始字，以及 `uint32_base10000` 的高字乘 10000 加低字语义。新配置校验接受该只读类型、默认完整四字节顺序，拒绝长度不符、无符号类型配 signed=true，以及把该扩展类型用于写入。普通 uint32 仍按二进制组合。

### AM5 原生 SOE 与录波

新共用主站仅在接受合法应答后调用 SOE 回调，并在下一次交换前重试尚未提交的事件。落库失败期间不发送下一请求、不额外翻转 FCB，重试保留原 eventId。

录波目录核查保留 commonAddress、COT、对象长度检查及总时限；完整目录与不完整目录不能混用。下载前后必须有相同 FAN、原始时间、状态且可解的时间，才确认文件关联；FAN 被循环复用时不把新文件挂到旧事件。下载文件使用唯一名。

这不是“突发事件本身必定携带录波文件标识”的承诺：原始故障号、目录证据、文件下载状态是不同层次。进程内待提交批次可重试，也不能据此宣称机器掉电时尚未落库的数据具有零丢失保证。

首次回归曾有 6 项失败，未把失败直接忽略：

- 本地新增 Modbus sentinel 测试夹具未声明 `read.dataType`，被合并后的严格配置校验拒绝。补为 `uint16`，不放宽生产校验。
- Windows 源码快照未保留 Git 的脚本执行位，已按 Git index 恢复远端文件模式。
- 整套测试放在没有子进程回收的 Python PID1 下，端到端进程退出检查会等待僵尸进程；普通测试改为不隔离 PID，仅迁移测试隔离 PID。
- 初轮 512 MiB 共享内存环境中末尾三项出现 Bus error；新建 2 GiB 隔离环境后全部通过，未改产品代码或放宽测试超时。未进一步断言这三项错误只有单一原因。

原生完整构建使用 Debug，以避开旧 GCC 对迁移布局大对象初始化的长时间 Release 优化；不能把这次结果说成 x86 Release 全量验证。PowerShell 5.1 不作为上述中文脚本的验证环境。

构建与运行日志、源码校验及产物哈希保存在本地工作目录 `D:/workspace/new/driver-merge-20261030/`，远端仅使用 22.11 的独立目录 `/tmp/driver-merge-20261030/`，未改共享构建目录。
